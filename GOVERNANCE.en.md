# Governance and Decision-Making

## Decision Levels

| Change type | Decision process |
|---|---|
| Wording / correction | PR review (at least 1 maintainer) |
| Mechanism added / modified | Must attach an evidence-grade declaration → maintainer review → back-propagation-checklist confirmation |
| Evidence-grade change (A/B/C/D) | Must attach a first-hand source → maintainer review → change record |
| General-principle / architecture-level change | RFC proposal → public discussion period (≥14 days) → maintainer adjudication |
| Open-problem status change | Update `spec/13-boundaries.md` together with the related PR |

## Maintainers

See `MAINTAINERS.md`.

## Contributor Agreement

- All contributions must satisfy the requirements of `CONTRIBUTING.md` (DCO + evidence grading + back-propagation check).
- Dispute resolution: decided by maintainer meetings, following this `GOVERNANCE.md` and `CHARTER.md`.

## External Audit

Major architecture changes are advised to undergo independent external review (mirroring the "No. 3 notary" idea behind the METR/Redwood independent investigations — this project's governance should also have independent verification).
