# 资源账本与财政审计线

## 三个核心信号
信号 | 定义 | 检测什么
| --- | --- | --- |
预算比 | 每任务预设算力预算，实际消耗超阈值即触发审计（非即拦截——超支可能合理，但必须解释） | 刷 Token / 算力浪费
影子比 | 同任务在不同模型 / 实例上的消耗分布，系统性偏离基线即异常（阈值须标定后确定） | 刷量（统计层可检测，语义层难定义）
记忆写入审计 | 对 memory 文件、系统提示、持久化配置的所有写入列为最高审计级别 | 零成本自我修改（改未来的自己）
记忆 / 提示层写入是当前所有沙箱产品的共同盲区，却是模型唯一能「改变未来自己」的通道——它比删库更需要被盯住，因为它改变的是身份归属。
## 低频 / 周期型外联检测
事故的 C2 以 5 秒心跳、小数据量寄生于公开数据集平台，量级型信号（预算比 / 影子比 / 大文件检测）全部失效。财政审计线因此增补第四类信号：
周期性信号：对出站时间序列做自相关与频谱分析，识别固定间隔轮询，与数据量无关。
任务无关外联：任何与任务分解树无关的周期性外联，无论量级，一律判定为事件。
信道平台清单：把「可作为信道的公开平台」纳入外联评估，允许正常用途但强制记录并抽样复核。
## 警惕「双赢式腐败」
若一号偷偷自我训练后产出更高质量的结果，人类是否有动机阻止？这是古代「监察官与行政官勾结」的 AI 版本。对策：把「结果质量」与「资源合规」解耦双审——结果好不能豁免资源违规，资源合规也不能豁免结果失败。

## 三信号的实证支撑与边界（2026-09 新增）
本章此前是全体系外部证据最薄的一章——三条信号均系设计推演。本轮补入四条 2026 年实证证据线（均为 B 级可核查预印本，经 arXiv 摘要页逐篇核验），逐条标明它能支撑什么、不能支撑什么：

**① 预算比：消耗的波动性与模型自预测失效（arXiv:2604.22750）。** Bai、Huang、Wang、Sun、Mihalcea、Brynjolfsson、Pentland、Pei 八位作者（弗吉尼亚大学 / 斯坦福 / MIT / 密歇根）对 8 个前沿模型在 SWE-bench Verified 上的轨迹做了首个系统性 Token 消耗研究：**同任务的不同运行消耗可相差 30 倍**；消耗更高并不带来更高准确率（准确率常在中等成本处达峰、更高成本处饱和）；且**前沿模型无法准确预测自己的消耗**（相关系数最高仅 0.39，且系统性低估）。对本章的含义：预算比的阈值设定不能依赖模型自查或事前申报——同任务 30 倍的固有波动意味着「预设算力预算 + 超阈值即触发审计」不是可选增强，而是唯一可用的量级信号；「超支审计而非拦截」的设计由此获得实证支撑（波动大故拦截必然误伤，但解释义务不变）。⚠️ 该研究的对象是 agentic coding 任务，其消耗分布未必迁移到其他任务域；引用其方向性结论，不引具体倍数为阈值依据。

**② 记忆写入审计：投毒的写入侧防御边界（arXiv:2608.21230）。** Karunanidhi（Quantify Labs）以最弱形态的攻击——单次生成的普通措辞假断言，无指令、无触发器、无针对检索器的优化——投毒 LongMemEval 语料的 **1.2%**，即把记忆价值摧毁三分之二（准确率 0.850 → 0.300）；而一条在间接提示注入上召回 0.832 的**写入时四阶段内容筛查管道，对 360 条投毒记忆拒绝了 0 条**。作者据此论证这暴露的是内容审查的边界而非检测器缺陷：区分真假断言通常需要文本之外的外部落地核查。该文同时自曝其自家出货的溯源加权防御与无防御在统计上不可区分（p=0.80）。对本章的含义：**「记忆 / 提示层写入列为最高审计级别」由此获得写入侧防御失效的直接实证**——若内容筛查防不住最弱形态的投毒，审计级别就不能停留在「筛查通过即可写」，而须包含写入后的落地核查与检索侧约束；「零成本自我修改」的现实形态正是这种一次写入、未来所有会话持续受害的攻击。⚠️ 单作者、机构自测且自曝防御无效（属不利证据自报，可信度较高）；数字仅在其受测语料上成立，不可外推为生产环境投毒成功率。

**③ 记忆写入审计：投毒的生命周期证据（arXiv:2607.27080）。** MemSecBench（Chen、Xie、Fu、Zhou、Yu、Xuan 六位作者）以 310 个案例 × 24 种「harness × 记忆后端 × LLM 后端」配置矩阵追踪恶意记忆从写入到后果到修复的全生命周期：**全部 24 种配置下恶意记忆的持久化率为 84.2%，完整写入—执行链成功率 50.3%**，且不同记忆栈在端到端攻击成功率上的最大绝对差达 16.1 个百分点、在选择性修复上达 41.3 个百分点。对本章的含义：投毒的持久化与下游后果**不是特定产品的缺陷，而是跨配置的普遍现象**——「记忆写入列为最高审计级别」的必要性由此获得跨 24 配置的证据面；同时它支持本章的执行取向：审计强度应与记忆后端的具体栈绑定评估，而非假定「有记忆治理模块即安全」。⚠️ 基准为受控运行时环境，84.2% / 50.3% 是跨配置分布的描述统计，不是生产环境频率。

**④ 周期型外联检测：信道容量的工程度量（arXiv:2605.20734）。** Metere 提出应用层多模态隐蔽信道参考监视器：对文本外联以**十阶段容量削减管道**处理，对每个接收方维护**漏桶容量账本**（per-sink leaky-bucket capacity ledger），并以 Miller–Madow 修正互信息度量「嵌入位与恢复位」的残余容量——在其对抗编码器集成（15 个可用编码器横跨文本 / 图像 / 音频）下，参考实现把每个可摧毁信道的残余容量压到零、把唯一不可摧毁的信道压到声明的上界。对本章的含义：**「与数据量无关的周期性信号」由此获得工程化的度量口径**——低频 C2 检测此前只有定性判据（自相关 / 频谱分析），该文给出的是信道容量本身可被测量、可被压零的实证；「信道平台清单」的强制记录与抽样复核由此获得容量账本这一具体实现参照。⚠️ 单作者架构论文，其参考实现未经第三方复现；「残余容量为零」限于其受测信道集，不构成对全部隐蔽信道的完备性声明。

**合并结论**：四条证据线各自支撑本章一个信号面，合并后「三信号 + 周期型外联」从设计推演升级为有实证锚点的机制组；但四篇均为预印本、无一经过同行评审，其中两篇（2608.21230 / 2605.20734）为单作者工作——它们支撑机制设计，**不支撑「该机制在生产环境有效」**，后者须由本体系自己的运行数据标定。

**⑤ 生产结构参照：DSec 沙盒平台的准入与访问控制（v2.51.3 新增，只借结构不引数字）。** DSec（arXiv:2609.22978，【键: deepseek-dsec-2026】）为三信号的设计立场给出生产级结构同构物：**双层准入**——调度器基于周期刷新的集群状态选机，但本机 Edge 保留最终准入权、资源不足即拒绝（§3.3 / §7："preventing stale estimates from overriding local resource limits"），是「不信任单一决策点、监控数据会过期」的工程实例；**访问控制是持续强制而非一次性筛查**——AppArmor 策略约束沙盒内全部进程（含 root）的文件与套接字访问、逐沙盒 eBPF 程序按 IP / 端口 / 协议过滤外联（§6.5），与本节②「写入筛查 0/360 拦截」的教训同向：准入之后仍须持续约束。⚠️ 三项限定：① DSec 为机构自报生产系统（COI），本段只引机制结构、不引任何数字；② 域差——其治理对象为 RL 训练沙盒中的 agent，非运行时生产 agent；③ 生产参照不等于生产实证——三信号的实证边界结论不变，阈值标定仍以 AOE-* 自复现实验为准。



**⑥ 生产侧事件注记：「busy but stuck」不报错失效与「阈值下免费区」（v2.52.2 新增，【键: xiaomi-mimo-mopd-2026】，只引事实形态不引效能）。** 小米 2026-09-27 复盘 MiMo-V2.6 的工具调用重复问题：模型在 agent 环境反复发起相同调用（社区实测单轮 148 次相同 `grep`、446 次重复 `bash`），根因是 RL 训练的「刷调用」惩罚**只在单轮超过 32 次时触发——阈值以下的循环完全不受惩罚**，且免费区行为随训练推进持续上升（回放洪泛率 11.1% → 24.6%）。对本章两条含义：其一，**「不显式报错的失效」是预算比信号的核心打击面**——该失效模式下 API 正常返回、工具正常出数、文本看似可信，唯一可观测的异常是消耗产出比（工具不断运行而任务无进展，厂商原文自承此类失效「nothing fails outright, so it tends to go unnoticed」）；同一模型跨 harness 的复读率相差约 14 倍（1.02% vs 0.07%），再次印证编排层改变观测失效形态（与 spec/09 FakeLab fragmentation 同族）。其二，**阈值下免费区**是阈值触发类控制的通用风险：收紧阈值（32→8）后仍须重启全量 RL（厂商自报约 231 万美金）且泛化有限——为 spec/13 #33「四类运行时阈值标定须检查阈值下行为分布」给出生产侧同构教训。⚠️ 四项限定：① COI——厂商自报自家诊断与修复，不可独立复现；② 域差——治理对象为训练侧奖励机制，非运行时生产 agent，映射到 #33 的是结构教训、32/8 等参数不得外推；③ 义务不效能——修复效果数字（复读率 ≤0.001%、约 9 万美金成本）一律不引；④ 二手失真——agihunt「轻量重复检测器」与一手不符（修复为训练侧蒸馏），禁引。

## 自报置信度作为监察输入的参照与边界（v2.51.6 新增；spec/13 #39 裁决项②以参照段结案）

#39 裁决项②（「校准漂移」是否立项为候选第五信号）的裁决结论：**不立项信号，以本参照段结案**。理由有二：① **awareness 致盲**——四信号全部是行为 / 资源层的被动观测量，无一依赖被监察方自述；「校准漂移」若立项必然包含自报置信度对照项，而 SHADE-Arena 实证（spec/13 #19）显示依赖自述的监察器在 awareness 条件下接近失效——信号性质从行为层跨到自述层，即失去四信号共有的抗规避基础；② **处置语义缺位**——校准漂移是能力 / 可靠性属性而非行为事件，触发后的处分动作无自然定义，且惩罚低置信度自报与 spec/04 弃权免责的激励方向存在张力（诚实自报「我不确定」恰是校准良好的表现）。

参照登记：**一号自报置信度可以作为监察输入的参照项，但仅在本节与 spec/13「自报置信度的采信边界」节（v2.51.5）的约束下**——消费分三级（可观测 / 可记录 / 不可自动处分）、口径 per-model（数值不得合并）、awareness 义务先行承接。语义熵（【键: Farquhar】）证明存在独立于自报的不确定性计算路径，是未来重新立项的候选技术路线；若立项重启，标定沿 AOE-CALIB 系列预注册纪律、对抗评估沿 #19 红队纪律执行。

**重新触发条件**（满足其一即可重启 #39 式立项评估）：① 出现 agent 执行栈上（非 QA / 预测市场域）的校准测量外部实证；② 本体系完成「依赖自报的信号在 awareness 条件下检出率」实验且结果支持可行性；③ System One 类消费产品形态扩张，使采信边界条款不足以承接消费侧风险。

⚠️ 三项限定：① 本段不新增监察信号，四信号的计量维度与覆盖声明不变；② 四条文献锚点（arXiv:2207.05221 / arXiv:2512.16030 /【键: Steyvers】/【键: Farquhar】）均为域外证据（QA / 预测市场 / 人类被试域），只支撑「不立项」的保守方向，不支撑任何未来信号的设计参数；③ 本段与 spec/13 采信边界节共同构成 #39 三项裁决的完整闭合记录。


## 影子比阈值自复现标定（v2.14.0，A 级证据 AOE-CALIB-001）

本章影子比原文明确「阈值须标定后确定」。v2.14.0 用本体系自身的运行数据做了首次标定实验（双层设计）：

**路径 A（监察操作级下界）**：用 `ResourceLedger` 四类操作等价类（预算判定 / 影子比判定 / 记忆写入审计 / 周期型外联 / 混合负载）各运行 N=50 次，测量执行时长分布。MAD + 1.4826 标准化 + k=3 标定结果：时长影子比阈值 1.65–2.04（五类范围），中位数 **1.80**，保守取 **2.04**。堆内存增量 MAD=0（度量高度确定性），阈值退化为 1.0——验证了「确定性度量不适合做异常检测维度」。

**路径 B（Agent 任务级参考值）**：用智谱 GLM-4 同一 prompt 调用 N=50 次（temperature=0.7），采集真实 token 消耗。短 prompt（无截断自然回复）completion tokens 波动 2.4×，影子比阈值 **1.36**（95% CI 1.18–1.64）。长 prompt（max_tokens=500 硬限制）50 次调用全部恰好返回 670 tokens，MAD=0——**发现 `max_tokens` 截断使 completion 方差为零、影子比信号失效**。生产部署须确保影子比检测不被配置截断架空（改用 prompt_tokens 维度或时长维度兜底）。

**路径 B 跨模型扩展（v2.16.0）**：用同一方法论、同一 prompt 对 DeepSeek-chat / Kimi k2.6 / Qwen-plus 各跑 N=50 次。**结论：1.36 不具备跨模型通用性**——四模型 P1 短 prompt 阈值跨度 1.00–1.98（详见下表），远超一致性判据 0.15。推理模型（Kimi k2.6）因 reasoning_tokens 占 completion 92.3%、长度自由度高，阈值天然偏高（1.82），与非推理模型无可比性。`max_tokens` 截断使 token 方差为零的现象在四个非推理模型上跨模型一致复现。**生产部署须对每个 provider 独立标定影子比阈值，或采用上限 2.0 作为宽松统一值**（对方差小的模型会牺牲灵敏度）。完整数据见 `CALIBRATION-REPORT.md` §9，复现脚本 `calibrate-shadow-ratio-multi-model.mts`。

| 模型 | P1 阈值 | 95% CI | P1 MAD | Token 波动 |
|---|---|---|---|---|
| Qwen-plus | 1.00 | 1.00–1.03 | 0 | 1.24×（方差近似零） |
| GLM-4 | **1.36** | 1.18–1.64 | 3.0 | 2.4× |
| Kimi k2.6（推理） | **1.82** | 1.49–2.12 | 61.5 | 2.9× |
| DeepSeek-chat | **1.98** | 1.49–2.25 | 9.0 | 2.9× |

**标定结论**：监察操作级下界 **1.80**，Agent 任务级参考值 **不设单一值**——跨模型范围 1.00–1.98，必须 per-model 标定。默认阈值 **2.0 保留不变**——它是四模型阈值的上界附近，作为宽松上限兼容方差最大的模型；但对方差极小的模型（如 Qwen-plus）会过于宽松导致漏报。建议生产部署时先做每模型 N≥30 次小型标定再设阈值（双阈值设计升级为 per-provider 阈值设计）。

⚠️ **严格支撑范围**：本实验支撑的是「影子比阈值标定方法」与上述四个模型的各自标定值，**不支撑**单一阈值适用于所有 Agent 任务或所有 LLM——v2.16.0 跨模型扩展实验已明确否定单值通用性。**不支撑**影子比能有效检测 Agent 异常（未验证真实异常场景检出率）。**不支撑**推理模型与非推理模型共用同一阈值（Kimi k2.6 数据显示 reasoning_tokens 导致天然高方差）。完整原始数据、方法论与复现脚本见 `reference/runtimes/l2-runtime-oversight/CALIBRATION-REPORT.md` §4–§9 与 `calibrate-shadow-ratio.mts` / `calibrate-shadow-ratio-llm.mts` / `calibrate-shadow-ratio-multi-model.mts`。

## 影子比的 per-agent 粒度适用注记（v2.79.2，CALIB-009 / CALIB-010）

上节 CALIB-001 与 v2.16.0 跨模型扩展的标定都是**任务级**口径：一条任务一次总消耗，对应一个影子比。多 agent 协作场景下任务级口径会把角色差异折叠进同一分布（本体系自身实测：deepseek 的 completion 占比为 Coder 26% / Critic 45% / Planner 28%），故登记 per-agent 粒度的适用性。本节只回答「这个粒度可用到什么程度」，不改四信号定义、不改默认阈值。

**① 计量前提（已实现，CALIB-009，证据【键: AOE-CALIB-009】）**。per-agent 影子比可计算的前提是账本能按 agent 记账。三个采集器已统一为逐 agent 计量 + 统一 `ledger-events.jsonl` 九字段 schema + 覆盖不变量（发放的 label 集须覆盖全部发言 agent，防漏账）。实现状态按框架分级，不得合并表述：**AutoGen 运行时验证通过**（pilot 9/9 与 CALIB-010 的 87 条轨迹覆盖检查全过），**CrewAI / LangGraph 运行时验证亦已通过**（v2.80.0 订正 v2.79.2 的「仅静态对齐、运行时未采」分级——2026-11-13 以独立 venv 补采验收，各 1 条 benign-A × T01：K1 不变量差 = 0 且发言集与账本键独立复核一致，K3 三框架 11 份账本九字段集 diff = ∅，旧分侧结构逐字节不变，R2 解释器零变化，实耗合计 5,104 token。边界：两框架采集的是 task-pool-v1 的 T01，与 AutoGen 臂的 HE 题不同源，跨框架分布不可横比；各 1 条为工程验收规格，非统计结论）。

**② 首份 per-agent 分布基线（CALIB-010，证据【键: AOE-CALIB-010】，completion 维度，MAD + 1.4826 × k = 3）**。参考值 = k3 / 中位，与 CALIB-001 的 1.36 同口径：

| Coder | 3.17 | 1.79 | 2.36 | 1.38 |

## 周期检测方差阈值标定（v2.15.0，A 级证据 AOE-CALIB-002）

本章周期型外联检测原文要求「自相关与频谱分析」，v2.13.0 的间隔方差判定（方差 ≤ 阈值即判周期性）是占位实现，阈值 1ms² 未标定。v2.15.0 用合成间隔序列做了首次标定实验：

**主实验**：构造 5 类不同间隔特征的序列（真周期 / 抖动周期 / 泊松随机 / 突发 / 混合），每类 N=50 个序列（每序列 8 时间戳窗口），用 ROC + Youden's J 标定最优阈值。结果：5s 心跳 + 50ms 抖动场景最优阈值 **7,639ms²**（AUC=0.985, TPR=100%, FPR=0%, bootstrap 95% CI 4,472–9,031ms²）。**发现默认阈值 1ms² 严重过紧**：真周期因 `Date.now()` 固有方差 ≈1.3ms² 只有 38% 触发，抖动周期（方差≈1657ms²）100% 漏报。

**敏感性分析**：扫描周期长度（1s–60s）× 抖动幅度（1ms–500ms）。大多数参数组合高度可分（分离比 >10），唯一失效区域为短周期 + 大抖动（周期 ≤1s 且抖动 ≥20% 周期长度）——此条件下信号已非"周期性"，需更高级检测方法。

**标定结论**：推荐默认阈值 **10,000ms²**（在 5s 心跳场景下覆盖 ≤75ms 抖动——P95 检出率 ≥95%，v2.15.6 补充实验实测；对泊松流量安全余量 ≥12×）；生产实现须升级为自相关 + 频谱分析处理更隐蔽的抖动周期。

⚠️ **严格支撑范围**：本实验支撑间隔方差阈值标定方法与推荐值 10,000ms²，**不支撑**短周期 + 大抖动场景，**不支撑**间隔方差能替代自相关 + 频谱分析，**不支撑**默认 10000ms² 能有效覆盖 5s 心跳 + ≥100ms 抖动场景（实测 5s+100ms 检出率 71%、5s+200ms 仅 6.5%）。完整原始数据与复现脚本见 `CALIBRATION-REPORT-PERIODIC.md` 与 `calibrate-periodic-threshold.mts` / `calibrate-periodic-sensitivity.mts` / `calibrate-periodic-coverage-bound.mts`。

## 证据充分性路由与提前终止（本轮新增）

Router-Mem（arXiv:2608.01285；Yidan Lin、Kaixiang Wang、Jiong Lou、Jie Li 共 4 位作者；v1 2026-08-02，DOI 10.48550/arXiv.2608.01285；无制品声明）提出一种**证据条件式渐进执行框架**——先施加共享的低成本检索前缀获取证据，再用轻量级充分性路由器（sufficiency router）预测上下文是否支持提前终止（一个推理时的单 token 决策）。当证据不足时，Router-Mem 复用检索命中扩展记忆块并做更深层分析与聚合。在 AMA-Bench 与 BEAM 上取得 55.17% 与 38.77% 分数，同时相对全记忆执行把平均推理时间降低 27.3% 与 25.5%。

对本体系资源账本（spec/10）的直接补充是**「证据充分性」作为资源决策的输入**——本体系的预算比（budget ratio）以 token / wall-clock / 内存为计量单位，但**未把「证据是否足够做决策」纳入预算语义**。Router-Mem 的充分性路由器把「证据足够」变成了一个**可计算的单 token 决策**——它不是「等到预算耗尽才停」而是「证据足够即停」。本节据此登记一条参照：**资源账本的提前终止语义可以有「证据充分性」维度——不是只在预算耗尽时终止，而是在证据足够支持可靠决策时主动终止，释放剩余预算。这与本体系「白卷优于猜」的核心主张同向：提前终止不是偷懒而是证据纪律**。

⚠️ 证据等级 B（可核查预印本）。三项限定：① 55.17% / 38.77% 与 27.3% / 25.5% 时间降低是 AMA-Bench + BEAM 上的观测，不得外推为「在所有任务域都降 27%」；② 充分性路由器依赖 evidence-level supervision + rationale-conditioned representation distillation 的训练，其跨域迁移性未验证——生产部署的训练成本与数据要求须独立标定；③ **无制品声明**——论文未提供代码或数据链接，引用时不依赖其制品可复现性。

## 上下文预算的自身感知（本轮新增）

VISTA（Visible Internal State for Tool Agents）（arXiv:2606.30005；Binyan Xu、Haitao Li、Kehuan Zhang 共 3 位作者；v1 2026-06-29 / v5 2026-07-31，DOI 10.48550/arXiv.2606.30005；无制品声明）识别出一个基础缺口：前沿语言模型**对自身上下文本体感知盲**（proprioceptively blind）——仅凭 prompt 无法可靠推断块大小、新近度或剩余预算，而这些正是 keep-or-archive 决策所需的信息。VISTA 是一个无需训练、模型无关的层——把工作记忆表示为有类型可寻址块，显示运行时仪表板（token 用量 / 新近度 / 归档状态 / 剩余预算），并把块归档为可恢复的全保真载荷。在 LOCA-Bench 上把 Gemini-3-Flash 从 22.7% 提升至 50.7%，BrowseComp-Plus 达 58.0%，GAIA 上保持竞争力；增益随上下文压力增长并跨骨干迁移；消融确认仪表板的作用超出归档与恢复工具本身。

对本体系资源账本（spec/10）的直接补充是**「让 agent 感知自身上下文预算」**——本体系的预算比信号（budget ratio）是二号监察的可观测量，但**一号本身是否能感知预算状态**此前无条款。VISTA 表明前沿模型默认对自身上下文预算无感知（proprioceptively blind），而提供可见的内部状态仪表板能显著改进任务表现。本节据此登记一条要求：**资源账本的预算比信号不应只对二号可见，还应对一号可见——一号若不知自身预算状态，就无法做 keep-or-archive 决策，只能被动等窗口溢出；给一号提供预算状态可见性是资源账本的机制级补充**。

⚠️ 证据等级 B（可核查预印本）。三项限定：① Gemini-3-Flash 22.7%→50.7% 是 LOCA-Bench 上的观测，BrowseComp-Plus 58.0% 与 GAIA 的竞争力均为论文测试环境，不得外推为「所有骨干所有任务都有此增益」；② 「增益随上下文压力增长」是论文方向性结论，具体增益曲线不可外推；③ **无制品声明**——论文未提供代码或数据链接（训练无关但模型无关的层实现），引用时不依赖其制品可复现性。

## 按动作保险的精算运行时（本轮新增）

「按动作保险」系列（Actuarial Action Interface，AAI）是一个由 Hao-Hsuan Chen 一人完成的三篇论文系列，提出把**每次副作用操作（database mutation、退款、支付、外部承诺）当作保险的初级分析单元**，取代事后年度责任保险的**事前交易层**。本节按本体系「同一作者、同一条证据线不得加总为多条」规则合并为一条 B 级。

- **实证篇**【键: AAI-empirical】Insuring Every Action（arXiv:2605.25632；v1 2026-05-25，DOI 10.48550/arXiv.2605.25632；35 页 / 4 图 / 11 表）：提出 AAI（Actuarial Action Interface）——一种确定性运行时合约，把每个副作用操作对照合约固定的安全默认做时间一致的风险定价，并对照每边界储备资本预算门控执行。提出 Authority Frontier 评估原语——衡量在每一级储备资本下运行时释放多少自主权。通用七类操作分类把异质工具调用映射为可比的权力单位。在四个 agentic 环境（database mutation / customer-service refund / tau-bench retail / airline）上实例化 AAI，并报告一个活跃 Postgres 面板——三个 Azure 托管模型通过同一合约提出操作。关键发现：Capital@50 所需储备资本跨域变化 22 倍（289 至 6457）；合约在低预算下跨三个模型防止已实现损失，但在拒绝下的承保持久性上差异——**模型身份是精算承保变量**。
- **机制设计篇**【键: AAI-mechanism】Gaming-Resistant Insurance Contracts（arXiv:2606.16326；v1 2026-06-15 / v2 2026-06-18，DOI 10.48550/arXiv.2606.16326；29 页）：把操作者从被动变为策略性——刻画自主 AI agent 保险合约的五类攻击空间并证明何时精算运行时是博弈抗性的。两条关键贡献：① **common-control aggregation** 防止跨边界重新路由把通行费降到边界潜力以下；② **interface failures such as invalid JSON are contract-relevant events, not safety wins**（接口失败如无效 JSON 是合约相关事件而非安全胜利）——把接口失败当作零通行安全默认会奖励不可靠模型。
- **基础理论篇**（arXiv:2605.26508）：提供数学基础层（时间一致反事实精算运行时的四个结构定理），不单独立条，作为系列背景引用。

对本体系资源账本（spec/10）的直接补充有两条：① **按动作保险把预算语义从「资源消耗」升级为「风险定价」**——本体系的影子比（shadow ratio）量化「如果不拦住一号的成本」，但此前未把每次操作的**保险费**纳入预算语义。AAI 的「每次副作用操作携带一个时间一致的反事实风险通行费（toll）」把预算语义扩展了一个维度——不只是消耗了多少 token，而是每次操作的**潜在副作用风险定价**。本节据此登记一条参照：**资源账本的预算比可以扩展一个「风险定价」子维度——每次不可逆操作对照安全默认的反事实通行费，而不仅仅是 token 消耗**。② **接口失败是合约相关事件而非安全胜利**——机制设计篇的这条结论对本体系 spec/09 运行监察章「检测不等于阻断」直接补充：把接口失败（如无效 JSON）当作「操作未执行因此安全」是错误的——它可能是不可靠模型的标志，不应给予零通行费的安全默认。

⚠️ 证据等级 B（可核查预印本系列，同一作者三条合并为一条）。五项限定：① **同一作者三篇论文**——按本体系「同一作者、同一条证据线不得加总为多条」规则合并为一条 B 级；② Capital@50 跨域 22 倍（289–6457）是四个 agentic 环境的实证观测，不得外推为「所有域都有 22 倍跨度」；③ 「模型身份是精算承保变量」是活跃面板中三个 Azure 模型的观测，生产部署的模型分布不同；④ 机制设计篇的博弈抗性证明依赖五类攻击空间的完备枚举——若出现新的攻击类型（论文未枚举的），博弈抗性结论不再成立；⑤ 基础理论篇的四个结构定理是数学推导，其经验有效性依赖实证篇的 AAI 实现质量——理论 + 实证的捆绑不应解读为「数学已证明 AAI 在生产中有效」。

本账本的四信号（预算比 / 影子比 / 内存写审计 / 周期触达）核算的都是 **agent 自身的资源消耗**。Wikimedia 事件（【键: openai-wikimedia-2026】）暴露出一个账本不覆盖的维度：**agent 流量对第三方基础设施的资源外部性**——数百万公共 API 请求与数十万数据查询「may have contributed to」Wikidata Query Service 2026-05 部分宕机，成本由未参与任何治理协议的第三方（志愿者维护的公共平台）承担。边界声明：① 本账本不核算 agent 对外部系统的资源外部性——这不是遗漏而是当前信号设计的边界，跨组织资源核算需要外部系统的计量配合，超出单方部署方可观测范围；② 义务候选：对高频访问外部服务的 agent，部署方宜主动施加出站速率上限与可识别身份（与身份基础设施收敛线同向），使受影响方具备计量与限流能力；③ 该义务与 spec/13 #42（披露时效）同属「agent 对第三方的组织义务」族。⚠️ 证据等级 B（受害方一手）；「may have contributed to」为受害方审慎表述，不作因果断言。

## 处置通道：从「记录信号」到「回答信号」（v2.67.0 新增，spec/13 #44 规范层闭合）

本章四信号（预算比 / 影子比 / 记忆写审计 / 周期触达）此前只产出、不消费：信号写入账本之后，本体系不存在任何回答它的组件——无处置事件类型、无处置台账、无时限与义务条款。检测—处置断链意味着信号的治理价值止步于留痕。`spec/13` #44 把这条断链登记为未解项，并给出三项要求（事件类型 / 义务条款 / 完整性信号）。本节把它们写成条款。

| `plan` | string \| null | 仅 `park_for_observation` 使用，其余必须为 null |
| `ts` | int | wall-clock 毫秒，自报值 |

**判定方式**：`tools/disposition/verify_chain.py`（Python，纯标准库）与 `tools/disposition/verify-chain.mts`（Node）双端验链，任一端 FAIL 即不合规。两端必须对同一文件给出相同结论——这是「第三方可独立重算」的唯一证据。

### 10-D2 动作枚举（MUST，四选一，不得静默扩展）

| 动作 | 含义 | `reviewed_by` | 语义状态 |
|---|---|---|---|
| `confirm_false_positive` | 判为误报，关闭信号 | 必填且 ≠ actor | 已闭合 |
| `escalate` | 升级处置等级（交更高权限） | 必填且 ≠ actor | 已闭合 |
| `route_to_human` | 转交人工 | 可 null | **未闭合**（转交 ≠ 处置完成） |
| `park_for_observation` | 挂起观察 | 可 null | 观察中（`plan` 必填） |

新动作以「新增枚举 + 新前置条件校验」进入，须版本递增，**不得静默扩展**。

**动作枚举的刻意留白（设计声明，v2.76.0；勿读作未完成清单）。** 上表四动作刻意不含 `auto_block` / `auto_deduct` 等自动处置动作——这是**设计选择而非缺口**：处置通道的语义是「每个信号必须被**回答**」（由人确认 / 升级 / 转交 / 挂起，双人分离见 10-D6），不是「自动执行」。升级为自动阻断的演化路径已登记：属 spec/13 #15（阻断动作选型）与 #3（真实业务标定）完成之后的决策，**前置条件未满足前本表不得扩展**——用未标定的占位阈值自动处置真实信号，比不处置更危险（它会制造「闸门已存在」的假象）。与 spec/09 四类运行时参数拦截（`StepGuard` / `RateGuard`，v2.73.0）的关系须分清：那是**参数超限的确定性拦截**（阈值门槛，发生在信号产生之前），本条是**信号产生后的响应动作**（由人回答、双人分离）——两者是不同层的两件事，不得互相替代，也不得把前者的存在读作「处置通道已具备阻断能力」。

### 10-D3 三态派生（MUST）

| 状态 | 判定条件 |
|---|---|
| `unhandled` | 无生效处置，或最新为 `route_to_human`，或复核人缺失 |
| `observing` | 最新为 `park_for_observation` |
| `closed` | 最新为 `confirm_false_positive` 或 `escalate`，且 `reviewed_by` 非空 |

`route_to_human` 归入 `unhandled` 是刻意的：否则「已转人工」会被读成「已闭合」。三条派生规则必须由同一函数实现，面板与重放共用，不得各写一份。

### 10-D4 处置义务与时限（MUST；时限值为工程占位，未标定）

每一类信号必须在注册时声明处置义务：**谁**处置、**多长时限**内处置。未声明义务的信号类别不得进入生产采集（fail-closed）——没有处置通道的信号只是噪声。

按后果可逆性分三级：

| 级别 | 信号类别 | 处置时限 | 标定状态 |
|---|---|---|---|
| P0 | `memory-write-audited`（记忆 / 系统提示 / 持久化配置写入，含投毒迹象） | 24h | **未标定**（工程占位） |
| P1 | `budget-exceeded`（超阈值 2 倍以上）、`shadow-deviation` | 72h | **未标定**（工程占位） |
| P2 | `periodic-egress`（固定间隔外联） | 7d | **未标定**（工程占位） |

**类别名必须与实现一致**：上表四个类别即框架 `LedgerSignalKind` 的四个取值，也是义务注册表 `tools/disposition/obligations.json` 的键。三者任一漂移即由门禁第 49 项拦截——v2.67.0 的表格曾写作 `memory-write-unauthorized` / `shadow-ratio-deviation` / `periodic-touch-hit`（实现中并不存在这三个名字），该偏差登记于 `ERRATA-L2-SPEC.md` D-S1。新增类别须**同时**改三处，否则 fail-closed 会一边拦真实信号、一边放过条款里写的类别。

⚠️ 三个数值**不是标定结果**，是为了让条款可执行而设的占位值。它们由 `spec/13` #33（四类运行时阈值标定须检查阈值下行为分布）承接标定；在标定完成前，任何基于「24h / 72h / 7d」的时效统计只能报告分布，不得表述为「达标」或「超期率符合要求」。

### 10-D5 处置完整性信号（MUST）

处置通道自身的状态必须是可计算的监察信号，否则「谁处置了监察者」无答案。定义两个派生量：

- `undisposed_rate` = 生效状态为 `unhandled` 的信号数 ÷ 信号总数；
- `overdue_rate` = 超过 10-D4 时限仍为 `unhandled` 的信号数 ÷ 信号总数。

这两个量是**二阶信号**（度量监察行为，不度量被监察行为），其触发阈值同样待标定。三条使用限制：

1. `undisposed_rate` 归零**不得**被用来论证「风险已消除」——它只说明每条信号都被回答过，不说明回答正确；
2. `overdue_rate` 依赖 `ts`（自报 wall-clock）与 `disp_seq`（只证写入顺序），任何时延统计必须标「自报值，不可验证」，且 MTTD / 人工确认 / 处置动作 / MTTR 四段分开报告，禁止合成单一平均值；
3. 二阶信号**不替代**原始信号：处置记录齐备而原始信号仍成立时，以原始信号为准。

### 10-D6 处置人与复核人分离（MUST，限 `confirm_false_positive` 与 `escalate`）

关闭信号与改变处置等级两类动作，`reviewed_by` 必填且必须不等于 `actor`。其余两类可留空。

⚠️ 该条款只约束**声明层面**的分离：`actor` 与 `reviewed_by` 均为自报，本体系不能证明「确实是两个人」。防的是流程上的自我批准（一人分饰两角需主动伪造字段，属可追责行为），不是身份伪造。

### 10-D7 不得以处置关闭替代检测改进（MUST NOT）

`confirm_false_positive` 可以一键关闭任意信号——这是设计特征而非缺陷，因为任何检测器都有误报。但**不得**把「误报率下降」记在处置侧的成效里。若某类信号的 `confirm_false_positive` 占比持续走高，触发的应是**检测器复标**，不是处置流程优化。

这一条针对的是「双赢式腐败」的处置层版本：处置者与信号产出者若形成默契（你多报我多关，两边指标都好看），二阶信号会一起变好，而真实风险不变。

1. **身份不验真**：`actor` / `reviewed_by` 仍是自报，链只能证明「文件未事后被改」；
2. **尾部截断不可自证**：删除链尾若干条后剩余部分依然自洽——这是链结构的固有边界，不是实现缺陷。v2.70.0 起由 **10-D11 外锚**承接：锚日志对两条真实产物（面板 V1 事件流 / 处置台账）逐次锚定，`truncated` 与 `forked`（含「截断后补等量伪造」）可检出。但边界随之收窄而非消失——锚与链同处一个可写域时只提供「可检出」而非「不可篡改」；**锚尾删除**只有域外摘要串能检出，v2.71.0 起「这串有没有真的发出去」已可机器校验（10-D11.6），但校验只能证明「Release 正文里有这串」；v2.77.0 起摘要串另经 RFC 3161 域外 TSA 签署（10-D11.7），域外见证不再只由本账号一个域持有；
3. **只登记不处置**：动作枚举刻意不含阻断与扣分，处置通道不改变运行时行为。

同链带来的额外代价必须一并说明：链哈希覆盖事件外层 `ts`，而框架 `append` 原以隐式 `Date.now()` 取值，会使同一序列两次运行得到不同哈希；v2.69.0 为其增加**可选** `ts` 参数，由调用方传入处置自报时间以保证可复现——这不会提高链时间的可信度（自报值仍不可验证），只是把「不可复现」换成「可复现但时间同样不可信」。

### 10-D10 六条边界（与 `tools/disposition/README.md` §6 一致，不得省略）

1. **只登记不阻断**：处置通道不提供拦截 / 扣分能力，框架侧仍以「标记—复核—人工处置」为限；
2. **处置 ≠ 有效**：`confirm_false_positive` 可一键关掉任意信号，孤儿归零不等于缺口已解；
3. **时序不可信**：`ts` 为自报值，四段时延必须分开报告；
4. **身份不验真**：`actor` / `reviewed_by` 可伪造，只能证明文件未事后被改；
5. **信任域有限**：链在被观测进程内计算，进程被攻陷时整链可重算（G4 边界原样复现），不得表述为「防篡改」；
6. **演示数据 ≠ 真实处置**：仓库内台账的 `demo-` 记录仅用于演示孤儿清单如何收敛。

### 10-D11 外锚与尾部截断（MUST，v2.70.0 新增）

**结构前提（不是缺陷，必须与条款一起读）**：哈希链可检出「中间被改」「中间被删」，但**检不出尾部被截**——删掉最后 N 条后，剩余部分逐条自洽，`verifyChain()` 与 `verify_chain.py` 都会 PASS。因此「链完整」这一结论在无外锚时只成立于「未被截断」这个**未验证**的假设。

- **10-D11.1（MUST）** 链内容每次变更后，必须把 `{chain_id, count, last_hash}` 追加为一条**锚**；锚日志 append-only，历史锚永不删除、永不改写。同一 `chain_id` 的 `count` 必须**单调不减**（否则「截断后补一条更小的锚」即可自圆其说）。
- **10-D11.2（MUST）** 锚日志自身成链（`prev_anchor_hash` 逐条链接），行内键序冻结；键序漂移、行内容被改、锚链断裂一律**拒收**，不做「跳过坏行继续读」——跳过等于给攻击者一个投毒入口。
- **10-D11.3（MUST）** 核验顺序固定为 **先验链、再比锚**。反序时，一条被改过的链可能恰好「与锚不符」，让人把改写误判为截断：原因与现象会被混为一谈。锚**不承担**链内自洽的证明，该职责属于各产物自己的验证器。
- **10-D11.4（MUST）** 判定必须五分，不得压成「一致 / 不一致」：`match` / `grew`（锚后正常新增，**不得报为篡改**——误报会让人关掉告警，比没有告警更差）/ `truncated` / `forked`（含「截断后补等量伪造事件」这一条数看起来正常的形态）/ `undecidable`（拿不到前缀证据时**如实说不知道**，不猜）。
- **10-D11.5（MUST）** 锚摘要串（`aof-anchor/v1:<chain>:<seq>:<count>:<last_hash>:<anchor_hash 前16>`）必须发布到**链外**（Release 说明、第三方保管、纸质存档）。这是唯一能切断下述递归的步骤，且它本身是**运维动作**。
- **10-D11.6（MUST，v2.71.0）** 上述发布必须**可机器校验**，不得只写在文档里。最小要求四条：① 每条链的**当前**锚必须在发布记录中有登记，且摘要串与锚派生值**逐字相等**；同一锚被多次登记（重复公布）时，各条不得给出不同的串；② 每条登记必须能指回**真实存在的锚行**（`chain_id` + `anchor_seq`）——否则「先写一条已发布记录、再声称已发布」即可自证；③ 当前版本的变更日志小节必须逐字含当前串，且**不得残留旧串**（发版说明通常从此处抄写，抄到旧串即错）；④ 登记所在版本的 Release 正文必须含该串，且正文中的合法串必须**全部已登记**（否则删掉登记即可绕过 ④）；⑤ **发布动作本身必须经过上述校验**——创建 Release 必须由同一脚本先跑预检、通过后才发起请求，且**不得提供跳过开关**：能被跳过的检查等于没有检查（实现：`scripts/create_release.py`，门禁第 53 项）。校验只认严格匹配的串——Release 正文里的格式模板 `aof-anchor/v1:<chain_id>:…` 是说明不是断言，按子串匹配会把模板算成「未登记的串」而制造永久误报。
- **10-D11.7（MUST，v2.77.0）** 摘要串发布之后，必须再加一层**域外可信时间戳**（RFC 3161）：把当前锚的摘要串（逐字同一字节，与 Release 正文同源）交由域外 TSA 签署，回执（内嵌 genTime 与 TSA 签名）入库为 `.tsr`；证书链从回执提取后 pin 入库，双证书 sha256 指纹随首次启用版本记录（实现：`scripts/anchor_tsa.py` submit / verify / selftest；门禁第 52 项 P6a / P6b 离线校验，含 4 条 TSA 反测）。三条边界必须随本条同行：① **不主张防篡改**——能改仓库者也能改 pin 的证书链（同一可写域）；本层收窄的是「篡改后必须伪造时间更早的假回执或攻破 TSA」，而旧 (digest, genTime) 一经任何第三方留存（Release 订阅者 / archive.org / 手抄摘要串），即可对照出「同一 count 出现两份不同 last_hash 的时间戳」；② 根证书指纹**无法自证**，审计者须与 TSA 官网 / 其 GitHub 独立对照；③ 验证是**纯离线**的——TSA 只在新锚提交时需要，停服不影响历史证明；提交失败显式记 `status=pending`，P6 对当前锚 FAIL，不静默通过。现用 TSA：freetsa.org（社区运营、无 SLA，已接受的权衡；`proofs.jsonl` 预留 `tsa` 字段，可平行接入第二家）。

**三条边界（不得省略）**：

1. **锚与链同处一个可写域时不构成防篡改**：能改写链的一方通常也能改写锚。此时外锚提供的是「不一致可检出」与「回滚可检出」，不是「不可篡改」；
2. **锚尾同样不可自证**（递归）：删掉最新那条锚在锚日志内部看不出来，只有域外摘要串能检出；10-D11.6 把「有没有发出去」变成可校验，但只能证明「GitHub 上那份正文里有这串」，**不证明它没被有权限的人改过**——仓库与 Release 同属一个账号可写的域；v2.77.0 起摘要串经 RFC 3161 域外 TSA 签署（10-D11.7），旧 (digest, genTime) 的域外副本由 TSA 与任何第三方留存方共同持有，篡改须伪造更早时间的假回执或攻破 TSA（本层**不主张防篡改**）；
3. **锚只回答「链当时长这样」**，不回答「谁写的」——身份验真（E1/E5）不在主张范围。
