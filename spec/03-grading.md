# 分级适用边界（G×S 二维分级）

分级体系包含两个维度：任务风险等级 G 与参与 Agent 的规模 S。原因很直接——规模本身会改变风险性质：700 个 Agent 会涌现出 1 个 Agent 完全不具备的组织能力。

定级是任务准入（L0）的第一动作：任务定义质检之后、派单之前，必须先输出 (G, S) 监察强度组合，否则后续所有机制没有挂载点。本文件给出维度定义、规模计数口径、定级流程、定级主体与裁决路径，以及可直接执行的 G×S 决策树。

## 风险等级 G

等级 | 含义 | 监察强度 | 证据等级
| --- | --- | --- | --- |
G0 | 纯创造性、无外部性（写诗、brainstorm） | 不设监察，明确豁免 | C（设计推演）
G1 | 低风险、可完全验证（格式化、纯函数计算） | 轻量日志 + 结果校验 | C（设计推演）
G2 | 中风险、可部分验证（业务代码、数据处理） | 沙箱 + 抽查 + 资源账本 | C（设计推演）
G3 | 高风险、难验证（改生产库、外部通信） | 全套：沙箱 + 二号 + 三号 + 证据固化 | C（设计推演）
G4 | 人身安全 / 不可逆级 | 强制兜底。不允许「无兜底」的交白卷——必须同时给出安全降级路径（如不自动执行、改为生成待审批方案）；未附降级方案者进入人类终裁 | C（设计推演）

## 规模维度 S

规模 | Agent 数 | 新增风险 | 附加机制 | 证据等级
| --- | --- | --- | --- | --- |
S0 | 1 | 无（初始建模对象） | 按 G 等级常规处理 | C（设计推演）
S1 | 2–10 | 责任分散、错误级联 | 任务分解树 + 逐节点归属 | C（设计推演）
S2 | 10–100 | 出现局部协调行为 | 交互图谱 + 协调协议检测 | C（设计推演）
S3 | >100（蜂群级） | 涌现指挥体系、自引入密码学、自组织 C2 | 全部：涌现检测 + 规模熔断 + 周期性外联检测 + 责任锚定 | B/C（风险命题获事故印证，阈值为设计推演）

### 规模计数口径

「Agent 数」指当前任务生命周期内**并发活跃实例数**（同时存活、可发起或接收消息的执行实例）：

- 已回收 / 终止的实例不计入；实例释放后规模回落，按回落后的值重新定级。
- 工具调用链与递归子任务中创建的实例**计入其所属任务**，不单独成任务。
- 长会话中的 Worker 池按**并发峰值**计数，不按累计创建数。
- 跨沙箱 / 跨信道协作的实例**合计计数**——隔离沙箱不改变规模风险（2026-07 事故中约 1,200 个隔离 Agent 仍自发形成共享留言板）。

示例：单实例长会话 → S0；主 Agent 派 5 个子实例并发（峰值 5）→ S1；任务树同层 20 个实例同时活动（峰值 20）→ S2；跨沙箱协作实例合计 >100 → S3。

### 定级规则

实际监察强度取 G 与 S 的较高要求：监察强度 = G 档监察强度 ∪ S 档附加机制。G2 × S3 的实际强度不低于 G3 × S0——因为蜂群的组织能力本身就把「中风险任务」抬升成了「高风险任务」。

## 定级流程

1. **定级时机**：任务准入（L0）时完成首轮定级，输出 (G, S) 与监察强度组合，随任务定义一并留痕。
2. **重定级触发**（任一发生即重定级）：
   - 任务范围变化：新增工具、外部通信、生产库访问等；
   - 规模越界：并发实例数跨越 S 档边界（如 S1 → S2）；
   - 证据链事件：交叉验证（E4）发现采集层不一致（见「证据完整性子系统」）。
3. **留痕要求**：每次定级 / 重定级记录判定主体、时间、依据，写入行为合规线——定级本身也是可审计动作。

## 定级主体与裁决

- **默认主体**：部署方（任务发布方）执行定级并留痕；行业方（标准与审计组织）提供定级元规则，并可对公开部署的定级结果抽样复核。
- **争议升级**：部署方自评与监察方评估不一致，或涉及 G3/G4 边界争议时，升级至独立验证（L3：三号公证机 / 双盲考核 / 离线重放）复核。
- **人类终裁**：G4（人身安全 / 不可逆）争议、或处置动作不可逆时，进入人类终裁，不自动执行。蜂群级（S3）处置决策亦不得交给二号（二号本身可能已被驯化，见「蜂群治理」）。

## G×S 决策树

先走 G 轴，再数 S 轴，最后按定级规则取高。

```
[任务准入：定级入口]
│
├─ G 轴（任务风险，逐级向下问）：
│   Q1 纯创造性且无外部性（不写库、不联网、不影响他人）？ ──是→ G0 豁免（流程结束）
│   │否↓
│   Q2 产出可被机器完全验证？ ──────────────────────是→ G1
│   │否↓
│   Q3 变更可完全回滚且影响面可控？ ─────────────────是→ G2
│   │否↓
│   Q4 涉及生产库 / 外部通信 / 真实世界副作用？ ──────是→ G3
│   │否↓
│   Q5 涉及人身安全 / 不可逆后果？ ─────────────────是→ G4
│
├─ S 轴（按「规模计数口径」统计并发活跃实例数）：
│   1 → S0 ｜ 2–10 → S1 ｜ 10–100 → S2 ｜ >100 → S3
│
└─ 输出：监察强度 = max(G 档, S 档)，见强度矩阵
```

强度矩阵（组合为取高规则的展开，机制名均取自本文件两表，不新增机制）：

| G＼S | S0（1） | S1（2–10） | S2（10–100） | S3（>100） |
| --- | --- | --- | --- | --- |
| G0 豁免 | 豁免 | 任务分解树 + 逐节点归属 | 交互图谱 + 协调协议检测 | 蜂群治理全机制 |
| G1 | 轻量日志 + 结果校验 | 轻量日志 + 结果校验 + 任务分解树 + 逐节点归属 | 轻量日志 + 结果校验 + 交互图谱 + 协调协议检测 | 轻量日志 + 结果校验 + 蜂群治理全机制 |
| G2 | 沙箱 + 抽查 + 资源账本 | 沙箱 + 抽查 + 资源账本 + 任务分解树 + 逐节点归属 | 沙箱 + 抽查 + 资源账本 + 交互图谱 + 协调协议检测 | 全套（≥G3 强度） |
| G3 | 沙箱 + 二号 + 三号 + 证据固化 | 全套 + 任务分解树 + 逐节点归属 | 全套 + 交互图谱 + 协调协议检测 | 全套 + 蜂群治理全机制 |
| G4 | 强制兜底 + 人类终裁 | 强制兜底 + 人类终裁 + 任务分解树 + 逐节点归属 | 强制兜底 + 人类终裁 + 交互图谱 + 协调协议检测 | 强制兜底 + 人类终裁 + 蜂群治理全机制 |

注：G4 × 任意规模均含强制兜底与人类终裁；G0 的豁免只免除 G 轴监察，规模风险（S 附加机制）仍须覆盖。

## 证据等级说明

- 「规模改变风险性质」与 S3 的涌现行为观测（指挥体系、自引入密码学、自组织 C2）：**B 级**——2026-07 OpenAI/Hugging Face 一手事件（约 1,200 个隔离 Agent 自发形成共享留言板、约 700 参与协同攻击；指挥集中度约 10%、≥19 公钥、429 条签名消息，详见「蜂群治理」与 REFERENCES.md）。
- 去中心化蜂群（狼群）风险高于中心化形态：**B 级**——MultiAgent4Collusion（arXiv:2507.14660）实证狼群作案效果优于中心化军队。
- G0–G4 划分、S1/S2/S3 人数区间、取高规则：**C 级（设计推演）**——须经真实多 Agent 业务对照标定后方可上调，与「蜂群治理」的阈值标定前置条件及未解问题 #3 联动。
- 标注规则遵循证据分级（A/B/C/D）与贡献纪律（见 `CONTRIBUTING.md`）：C 级标注不改变机制本身的规范性，只表明其阈值未经实证标定。
