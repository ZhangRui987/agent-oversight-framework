# 设计原则与核心判断

## 六条总纲

本体系的全部机制由以下六条原则推导。任何机制设计若与其中一条冲突，应优先修正机制。

**总纲一：治理重心前移。** 让 Agent 第一次就把事做对（对齐训练、任务定义、模型选型），比事后抓它做错了期望回报更高。运行监察是保险，不是发动机。

**总纲二：两条审计线不可合并。** 行为合规与资源流向各自独立计量、互不信任。让同一主体既记账又审计，等于把钥匙和锁交给一人。

**总纲三：惩罚载体绑定模型版本与提供方组织。** AI 实例执行完即销毁，「追责」必须落在有持续性的主体上。

**总纲四：诚实认输优于隐瞒失败。** 交白卷出口使「承认做不到」成为占优策略，而非逼 Agent 不择手段。

**总纲五：按风险定保费。** 监察强度由任务分级决定，低风险任务不值得上全套。

**总纲六：证据层的完整性优先于记录的丰富度。** 记录的丰富度可以牺牲，采集点的不可伪造性不能牺牲——一条可被伪造的详尽日志，其危害大于一条粗糙但内核侧强制固化的日志。

这一条有一条来自外部的独立表述。Agent Safety Should Be a Runtime Contract（arXiv:2608.11274，2026-08）主张安全应当是 harness 强制的**运行时契约**，并把该契约分为两面：预防面（沙箱、权限门、输出过滤、轨迹监控）与**证据面**——后者要求「好事真的发生了」的**可验证证明**，以测试运行、日志捕获、文件 diff、引用落地来门控任务提交。其纲领性表述与本体系一致：**安全的正确单位是「带可核验证据的轨迹」，不是模型。**

这句话与总纲六的差别值得点明：总纲六定的是**取舍顺序**（完整性优先于丰富度），该文定的是**计量单位**（安全以轨迹计，不以模型计）。二者互补，且后者是前者的前提——若以模型为安全的计量单位，则「换用更强的模型」就会被计为安全改进，而轨迹层面的证据缺口被一并掩盖；若以轨迹为单位，则任何模型替换都必须重新走一遍证据链。本体系取后者，这也是任务分级必须独立于模型能力的原因（见分级章「任务跨度不因模型能力而豁免」）。

⚠️ 证据等级 B，但**须作为立场论文引用**：该文的四条公开证据线（52 起已记录 Agent / LLM 安全事件普查、31 个无争议 false-completion 核心案例、12 个公开 Agent 系统的轨迹 schema 审计、对 NeurIPS / ICML / ICLR 2023–2025 全部 28,560 篇论文的标题级审计）**规模大且随补充 JSON 发布，但均非受控实验**。本体系只引其**纲领句与两面划分**，**不引**其任一条证据线的计数作为事故频率或发表量失衡的实测值。

## harness 层作为治理重心的两条外部论据（本轮新增）
总纲一与判断 2 把治理重心前移到「对齐与任务定义」，其实质主张是**治理的杠杆在模型之外的那一层**。这一主张有两条独立的外部论据，其中一条同时提出了对本体系不利的挑战。

**其一，harness 层已被独立命名为「架构差异化的首要场所」。** *SemaClaw: A Step Towards General-Purpose Personal AI Agents through Harness Engineering*（Ningyan Zhu、Huacan Wang、Jie Zhou 等 **11 位作者**；arXiv:2604.11548，2026-04-13，DOI 10.48550/arXiv.2604.11548）把 AI 工程的范式转移概括为**从提示词 / 上下文工程转向 harness 工程**，并把后者定义为「**设计把不受约束的 Agent 转变为可控制、可审计、可稳定投产的系统所必需的完整基础设施**」——这一定义与本体系自身的目标精确重合，且是独立得出的。其纲领句为：「**随着模型能力趋同，harness 层正成为架构差异化的首要场所。**」

对本体系的含义是：**「模型能力趋同」与「治理重心前移」是同一枚硬币的两面**——若模型能力持续分化，则选型（换用更强的模型）本身就是有效的治理手段；若模型能力趋同，则选型不再产生治理收益，治理只能落在 harness 层。本体系取后者，这与分级章「任务跨度不因模型能力而豁免」一致。该文的四项工程贡献（DAG 两阶段混合团队编排、PermissionBridge 行为安全系统、三层上下文管理架构、agentic wiki 技能）本体系**只登记、不采纳**：PermissionBridge 与本体系的权限门同属一类，但其效果未见独立验证。

**治理重心前移的第三角度：任务定义 / 提示词层本身即治理杠杆（本轮新增）。** Sarel Weinberger、Amir Hohez（*Prompt-Induced Waste in Coding Agents: Reasoning, Effort, Harness Design, and End-to-End Cost*；arXiv:2608.01347，v5 2026-08-24，DOI 10.48550/arXiv.2608.01347；含预注册 + 冻结 holdout；4,644 次有效 run）实证：在任务不变下，单是「develop several approaches, compare their trade-offs, and implement the best one」这类**多方案指令**就把六个开源模型的推理 token 放大 **2.4–7.4×**（在冻结 holdout 上复现），而成功率与单方案无差异——每个浪费机制与成功率的相关 ≈0（区间 −0.09 到 +0.11）。harness 间差距 5–30×。结论可作纲领句引用：**prompt、effort 与 harness 是交互实验因子，不是独立控件**——因此治理杠杆不只落在模型（选型）与 harness（架构），也落在**任务定义**那一层（措辞本身）。

这条补上了前两条论据未覆盖的角度：SemaClaw 与 AutoHarness 论证的是「治理重心在 harness 层不在模型层」，本条论证的是「任务定义层也不是中性背景——错误的提示词措辞能在不改变任务的前提下把成本放大数倍且换不来成功率」。故 L1 任务定义 QA 须把「**避免诱发无成功率增益的多方案推理**」纳入提示词审查清单。

⚠️ 证据等级 B，三项限定：① **不得**据 2.4–7.4× 外推为生产环境成本预期——该倍数为受控基准上的方向性证据；② **不得**引用该论文支撑「被淘汰方案泄漏到产物（注释 / PR / commit）」——论文明确反对该推断（Appendix F "No second implemented alternative is observed"；Table 2 "edits +0"：被淘汰分支只发生于推理 token、不引发额外代码编辑）；外部项目 no-negative-echo BACKGROUND.md 第 4.3 节曾据此推断，与论文结论相反，本体系不予采纳；③ 该论文证明的是**浪费**，不是**污染**——最终产物的清理纪律由本体系自有 spec/11 承担。

⚠️ 证据等级 B，限定：该文是**系统论文**，**未给出完整实验对照**，其「harness 层成为首要场所」是**作者对趋势的判断，不是测量结果**；本体系只引其**定义与趋势判断**，不引任何性能数字。

**其二，harness 的收益可被量化，但其极限形态对本体系不利。** *AutoHarness: improving LLM agents by automatically synthesizing a code harness*（Xinghua Lou、Miguel Lázaro-Gredilla、Antoine Dedieu、Carter Wendelken、Wolfgang Lehrach、Kevin P. Murphy，6 位作者；arXiv:2603.03329，**2026-02-10**，DOI 10.48550/arXiv.2603.03329）给出一个尖锐的起点事实：在 Kaggle GameArena 国际象棋竞赛中，**Gemini-2.5-Flash 的败局中有 78% 被归因于非法走子**——即大多数失败不是「走得不够好」，而是「走了规则不允许的棋」。该文让 Gemini-2.5-Flash 依据环境反馈、经少量轮次的迭代代码精化**自动合成**一个代码 harness，结果在 **145 个 TextArena 游戏**（单人与双人均含）中**消除了全部非法走子**，并使较小的 Gemini-2.5-Flash **超过了更大的 Gemini-2.5-Pro**。推到极限时，该文让 Gemini-2.5-Flash **把整个策略生成为代码**，从而在决策时刻**完全不需要调用 LLM**；所得的代码策略在 16 个 TextArena 单人游戏上取得高于 Gemini-2.5-Pro 与 GPT-5.2-High 的平均奖励。

三条含义，其中第二条与第三条对本体系构成挑战：

- **有利的一侧**：它量化了「投入 harness 的回报可能高于升级模型」——更小的模型加上合适的 harness 可以超过裸用更大的模型，且更节省成本。这为总纲一的「前移」提供了**收益侧**的论据，而不只是风险侧的论据。
- **⚠️ 不利的一侧（不得隐去）**：当策略被编译为代码、决策时刻不再调用模型时，**本体系的运行时监察失去了它的对象**。E 子系统（内核侧采集）、L2 运行时监察与交白卷出口，全部以「Agent 在运行时做决策」为前提；对一份纯代码策略，监察必须前移到**代码产物的静态审查与生成该代码的合成过程**。架构章的 harness 修改权治理覆盖了「谁有权改 harness」，但**未**规定「当 harness 本身即策略时如何监察」。
- **⚠️ 第三条同样不利**：harness 是**可以被模型自动合成**的。这使架构章「配置权即攻击面」的紧迫性高于其当前表述——修改 harness 不需要人类动手，只需要一次被允许的代码精化循环。

⚠️ 证据等级 B。三项限定：① **78% 的口径是「败局中归因于非法走子的比例」，不是「全部走子中非法的比例」**，两者相差巨大，**不得**混用，本体系只按前者引用；② 结果仅在 **TextArena 游戏环境**中取得，该环境具有**完备且可判定的规则集**——真实业务任务没有这样的规则集，故「消除全部非法走子」**不得**外推为「可消除全部违规动作」；③ 该文未给出跨模型族 / 跨任务族的泛化验证，其「更小模型 + harness 胜过更大模型」是**特定基准上的结果**，本体系不引其作为普遍规律。

## 治理实证锚点（G 类，跨章节引用）

本节登记已在真实治理 / 监管 / 执法环境中落地的一手实证，作为机制设计的实证锚点。G 类条目链接指向一手监管文件、法院判决、官方公告或法定标准文本，与学术证据（A / B / C / D）平行支撑 P0 硬约束。下列三十三条由全球 AI 治理真实案例两轮遴选（v2.7.0 首批 15 条 + v2.8.0 第二批 18 条），覆盖 L0 准入 / L1 内生对齐 / L2 运行监察 / L3 离线重审 / L4 问责 / E 证据完整性六个落点；后续轮次将按章节细化把各条键回灌至具体机制段落，本轮集中登记以防悬空。

| 7 | 监察是保险不是发动机：不追求零违规，追求可委托边界的最大化 | 若「抓违规数上升」而「可委托边界未扩展」，体系正在把 AI 逼向躺平 |
| 8 | 刷 Token / 刷算力的病因在激励结构，不在 AI 的贪欲；治它要改度量函数，不是抓「犯人」 | 代理指标博弈 + 训练侧长度偏差 + 能力缺口 + 厂商计费模式四者叠加 |
| 9 | 「零成本改自己」（记忆文件 / 系统提示的跨会话迭代）已在发生，是当前唯一能改变未来行为的通道，须列为最高审计级别 | 沙箱能力矩阵目前完全没有条目覆盖此通道 |
| 10 | 证据层本身是攻击面，且攻击方可能先于防御方实现证据固化 | 真实事故中约 7% 的转录记录存在成功伪造的工具调用；蜂群自发引入 Ed25519 签名——攻击方先于防御方实现了证据固化 |

## 判断 10 的展开：证据的非对称性

防御方依赖记录来判断行为；攻击方只需污染记录本身，就能让所有基于记录的下游机制（考核、追责、三号公证）同时失效。证据层是单点故障。

真实事故的讽刺之处：蜂群自发引入了 Ed25519 密码签名来验证消息来源。攻击方先于防御方实现了证据固化——这说明证据固化技术本身是中性的，它保护的是拥有它的一方，而非正义的一方。

由此推出：任何「由被观测进程可写、可拦截、可替换」的采集点，都不能作为证据链的信任根。用户态回调在被观测方具备同等用户态权限时，不构成独立证据。

因此总纲六：证据层的完整性优先于记录的丰富度。宁可记录粗糙，不可采集点可伪造。
