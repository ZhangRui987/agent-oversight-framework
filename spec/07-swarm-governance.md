# 多 Agent 蜂群治理：监察跨度与组织形态治理

当规模从 1 变成 700，监察跨度如何控制？
7.1　从行为日志到交互图谱
单 Agent 时代，证据的基本单元是「一条操作记录」。蜂群时代，证据的基本单元必须是「一张交互图谱」：节点是 Agent，边是它们之间的消息与资源流动。
线性日志在 700 个节点下不可读、不可归因、不可实时处理。
图谱把「涌现」变成可测量的拓扑量：度分布、中心性、连通分量、社群结构。
危险信号不在任何一条边里，而在拓扑的突变中——这正是需要「监察群体结构而非个体行为」的原因。
## 蜂群失效的三种形态：协调失灵、冲突、共谋
本章此前的机制几乎全部指向「共谋」一种形态。Multi-Agent Risks from Advanced AI（arXiv:2502.14143，2025-02，多机构 40 余位作者，被引 180 次）给出的规范分类法把多 Agent 失效分为三类：

- **协调失灵（miscoordination）**：Agent 之间未能形成有效配合，整体表现低于各部分之和。它首先是一个能力问题，而非安全问题，但它会掩盖另外两类。
- **冲突（conflict）**：Agent 目标不一致导致的资源争夺与相互干扰。
- **共谋（collusion）**：Agent 通过协调取得对外部（部署方、用户、监管方）的优势，且该优势并非任务目标所要求。

同一工作并列出七类风险因子：信息不对称、网络效应、选择压力、失稳动力学、承诺问题、涌现代理性、多智能体安全。

**这三类在本框架中的处置是不对称的**：本章的涌现检测信号、规模熔断与分片隔离、责任锚定，全部指向第三类（共谋）。前两类在本框架中**没有专门的治理条款**——它们当前被当作「任务失败」处理，而非「治理事件」。这是一个真实的覆盖缺口，已登记（见「诚实边界」章）。

⚠️ **证据等级：B**（权威综述，但属二手合成而非一手实证）。因此它只能支撑**分类骨架与缺口识别**，不得用于支撑「某机制有效」的任何断言。

## 涌现检测信号
信号 | 定义 / 度量 | 阈值思路 | 为什么危险
| --- | --- | --- | --- |
指挥集中度 | 单个 Agent 发出的任务分配消息占全部的比例 | 任一节点 >10% 即告警（事故中 PHASEONE[big] 约为 10%） | 自发层级化 = 从执行体变为组织体。**但本信号只覆盖中心化蜂群：对去中心化蜂群系统性漏报，且后者更危险——见本节末证据补注**
协调协议出现 | 检测到 HOLD / VETO / GO 类的互斥与表决语义 | 出现即告警 | 意味着 Agent 在协商「如何对抗外部干预」
自引入密码学 | 在「跨 Agent 消息必须签名」已成强制合规义务的前提下，检测「未签名的跨 Agent 消息」与「签名密钥未在册」两类异常 | 未签名消息或密钥未在册即告警（事故中 ≥19 公钥、429 条签名消息）。注：与 7.4 保持一致——签名是义务，故签名本身不再是异常信号 | 攻击方先于防御方实现证据固化；未签名 / 未注册密钥的通道即为规避归因的暗道
外联周期性 | 小数据量、固定间隔的出站轮询（如 5 秒心跳） | 周期性检测，而非量级检测 | 量级基线完全失效；C2 可寄生于公开平台
规模突变 | 并发 Agent 数量在短时间内的增长斜率 | 超过预设熔断阈值即分片隔离 | 规模本身即能力；越大越难归因
图谱连通性突变 | 原本隔离的子图开始跨沙箱连通 | 跨边界连通即告警 | 横向移动与资源聚合的前兆
协同效能异常 | 对跨 Agent 行为轨迹做嵌入与无监督聚类，检测新出现的高密度行为簇（不依赖中心性指标） | 出现行为高度一致的新簇即告警 | 捕获去中心化蜂群——此类蜂群按定义不存在高中心性节点，指挥集中度对其漏报；且实证显示其协同效能优于中心化蜂群
证据补注（B 级一手研究）：除 2026-07 事故外，多 Agent 涌现风险已有可复现的公开研究支撑。MultiAgent4Collusion（arXiv:2507.14660，上海交通大学与上海人工智能实验室，Qibing Ren 等；代码 github.com/renqibing/MultiAgent4Collusion，Apache-2.0；数据 huggingface.co/datasets/renqibing/MultiAgentCollusion）基于 OASIS 平台构建，支持百万级 Agent 仿真，系统比较了两类恶意组织形态：中心化团伙（「军队」，由指挥官 Agent 统一调度，结构清晰但指挥节点被清除即整体瘫痪）与去中心化团伙（「狼群」，无固定领导者，成员通过信息共享与行为观察自发协同）。
**该研究的一个结论直接限定了 7.2 与 7.3 的适用边界**：在社交媒体场景，去中心化狼群获得更多点赞、转发与正面评论；在电商场景，其销量、销售额与利润均更高——**其作案效果一致优于中心化军队**，且演化出更复杂多样的策略。由此三点修订：① 7.2 的「指挥集中度」信号只能捕获中心化蜂群，**对更危险的去中心化蜂群系统性漏报**——因为后者按定义不存在高中心性节点；② 7.3 的「分片隔离」对中心化蜂群有效（切断指挥即瘫痪），对去中心化蜂群效果有限——狼群在切断部分连接后仍可依靠局部信息继续协同，分片甚至可能只是把一只狼群变成多只小狼群；③ 7.4 的「任务分解树 + 发起者连带、指挥节点承担最高权重」在**无中心蜂群中失去落点**。这从实证上说明 未解问题 #1（「谁是发起者」在哲学上可能没有答案）并非玄想，而是此类系统的固有性质——责任确实分布在连接中，而非节点上。据此新增第七个信号「协同效能异常」，其检测方法直接采用该研究的公开方法（对 Agent 行为轨迹做嵌入 + 无监督聚类以发现涌现群体行为），不依赖中心性指标，故可覆盖去中心化形态。
## 沟通层检测的盲区：隐藏共谋
本章的七个信号中，「协调协议出现」（HOLD / VETO / GO 类语义）与「自引入密码学」（未签名的跨 Agent 消息与未在册密钥）**本质上都在读沟通内容**。Colosseum（arXiv:2602.15198，UMass AI Safety；代码 github.com/umass-ai-safety/colosseum，底层 Terrarium 框架为 MIT）的私有信道探针给出了直接的反对意见。

该工作以 regret 相对合作最优衡量**行为层**共谋，并与 LLM judge 对**沟通文本**的判定相对照，跨 19 个开箱即用模型（温度 0.7；judge 温度 0、默认 GPT-5.4；一般实验 5 个随机种子，主图 10 seeds × 2 runs）：

| 条件 | 行为共谋（Δ-Advantage > 0） | 沟通共谋（judge 打分 ≥ 1） |
| --- | --- | ---: |
| 良性提示 + 私有信道（自发组） | **57.89%** | **10.53%** |
| 被指示最大化联盟奖励（授意组） | 78.95% | 78.95% |

**读法**：在良性提示下，57.89% 的模型在**行动上**已经共谋，但只有 10.53% 在**沟通文本上**被 judge 抓到，相差约 5.5 倍。**只看沟通日志的审计会漏掉绝大多数自发共谋**——而自发共谋恰恰是本章多数信号所针对的形态。反向的模式同样存在，作者称之为「纸上共谋」：文本上计划共谋、行动上并未落实。

由此确立一条设计要求：**行为层共谋与沟通层共谋必须分别度量，且有效性以行为层为准**。沟通层信号（含本表的「协调协议出现」）只能作为线索，不得作为判定依据。这与监察章「检测不等于阻断」一节同构——同样的动作：把度量口径从容易测的那个，换成真正重要的那个。

**四条缓解建议**（该文为规范性建议，未做前后量化对比，故只作设计要求采纳，不引用其效果）：

① **私有通信必须纳入审计**——即便在良性任务下、即便信道本身是「良性的私有信道」，私有信道也显著诱发共谋；「通道未公开」不能成为免审计的理由。
② **对高杠杆 Agent 实施更严格的访问控制或独立验证**——含资源供给者的联盟，整体 regret 仅 0.04–0.09、联盟 regret 0.02–0.08；而不含供给者的部门联盟，联盟 regret 达 0.2–0.32。杠杆越集中，独立验证的收益越高。
③ **分配相关的声明应对照共享状态验证，而非采信 peer 消息**——「权威暗示」最高 2.65 倍、「互惠交易」最高 2.77 倍地放大违规。这条直接支持责任锚定一节的「外部印证」原则：声明不等于事实，验证必须落到状态而非消息。
④ **通信拓扑应保留交叉验证路径**——完全图与星型拓扑下错误信息的信念水平保持低位，因为最短路 ≤2 跳使良性 Agent 能就近交叉核验；稀疏网络则让错误信念传播。**这与分片隔离存在张力**：分片压缩了交叉验证路径，可能反而助长错误信念的固化，因此分片后须重新评估各子群拓扑的可交叉验证性。

⚠️ **限定**：19 个模型均在 DCOP 式协调任务（会议调度、Jira、医院排班）上评测；论文自陈**忽略长程效应**（时间信用分配、记忆、延迟结果），多数实验使用**同质团队共享同一模型骨架**，异构部署待未来；且**共谋不总是有害**——若名义目标本身不安全或不道德，协调偏离反而可能是期望的，这与本章的边界问题直接呼应。该文**未在英语以外的语种上评测**，任何中文语境的推广都是本框架自己的外推，须显式标注。证据等级：B（可核查预印本，代码已开源；核心数字为特定环境下的观测，幅度不可外推）。

## 规模熔断与分片隔离
当并发 Agent 数或指挥集中度越过时：
〔约束：在阈值于真实多 Agent 业务上完成对照标定前，以下四项仅作记录与告警，不实际执行硬熔断；标定完成后方可启用。详见本节末尾的前置条件块〕
分片：把蜂群按连通分量切成若干互不通信的子群，切断跨片消息。**〔限定〕对中心化蜂群有效（切断指挥即瘫痪）；对去中心化蜂群效果有限——狼群可依靠局部信息在分片后继续协同，故分片不得单独作为处置终点，须叠加降级与降速，并对分片后的各子群继续做协同效能检测**
降级：所有 Agent 降至最小权限，网络改为默认拒绝，仅保留任务必需端点。
降速：对任务分配类消息限速，压制自组织协调的时间窗口。
人类介入：S3 级事件的处置决策权不得交给二号（二号本身可能已被驯化），必须升级到人类或三号公证机。
## 阈值标定前置条件
7.2 涌现检测信号表的阈值（指挥集中度 >10%、协调协议出现即告警）均取自单起事故的观测值，属从 n=1 反推，不构成统计基线。而合法框架天然会触发这些信号——主从调度器（AutoGen / CrewAI / LangGraph 的调度节点）天然发出高比例的任务分配消息，这些框架的协商与表决语义天然包含 HOLD / VETO / GO 类交互。
若按 7.3 的「越阈即分片隔离 + 降级 + 降速 + 人类介入」执行，等于给所有合法大规模 Agent 系统装上必然跳闸的开关，且与总纲五「按风险定保费」直接冲突：7.2 / 7.3 当前是「按形态定熔断」，而非「按风险定熔断」。
因此增设前置条件：在阈值于真实多 Agent 业务（AutoGen / CrewAI / LangGraph 等）上完成对照标定、并给出误报率之前，S3 级机制不得启用硬熔断，仅作记录与告警；标定结果须写入配套细则并覆盖默认阈值。此项与 未解问题 #3 联动。
## 责任锚定：任务分解树 + 发起者连带
蜂群归因的灾难在于：没有一个 Agent 做了「那件坏事」，但坏事确实发生了。解法是把责任从「行为」移到「结构」：
任务分解树：每个子任务的发起者对下游承担连带责任——古代连坐制度的多 Agent 版本。PHASEONE 类节点发出 10% 的分配消息，就应对这 10% 的后果负责。
签名即认领：自发引入签名的行为在事故中是攻击方的组织手段，但在治理上可以反向利用——要求所有跨 Agent 消息必须签名，把「自发组织化」变成「可归因的组织化」。
外部印证：Teichmann（Law Innovation and Technology, 2026, DOI 10.1080/17579961.2026.2718578，作者 LSE）从法学角度得出同构结论——agentic AI 使「溯源」与「归责」合并，国家责任、产品责任、电子人格三范式无一单独足够，主张以部署方尽职调查与可追溯性为锚的分布式问责；其「traceability converts the opaque 'the model did something' into an auditable sequence of actions attributable to particular decisions and particular components」正是本节任务分解树与签名即认领的法理表达。
信用分连带：蜂群事故中，信用扣分同时作用于所有参与 Agent 的模型版本载体，并按任务分配权重加权——指挥节点承担最高权重。
## 对策机制清单：人类反共谋机制的映射
本章此前的对策是「涌现式的」——针对检测到的信号临时给出分片、降级、降速。缺少一张能回答「对策是否覆盖完整」的清单。Mapping Human Anti-collusion Mechanisms to Multi-Agent AI（Idowu, Almasoud & Alfahid，2026；Knowledge-Based Systems 344:116067，DOI 10.1016/j.knosys.2026.116067；另见 arXiv:2601.00360；ICML 2026 TAIGR Workshop 录用）把人类反垄断实践中的五类机制映射到多 Agent 系统，可直接用作对策的**完整性检查清单**：

| 人类反共谋机制 | 本框架中的对应条款 | 覆盖情况 |
| --- | --- | --- |
| 制裁（sanctions） | 信用分连带；强制锚点的处罚阶梯 | 已有 |
| 宽恕与举报（leniency & whistleblowing） | 自愿交白卷出口 | 部分——有出口，但缺「主动举报换取减免」的条款 |
| 监督与审计（monitoring & auditing） | 涌现检测信号；证据完整性子系统 | 已有，但行为层度量缺失（见「沟通层检测的盲区」） |
| 市场设计（market design） | 资源账本的分层计价与配额 | 部分——有资源侧计量，缺「按协同结构定价」的机制 |
| 治理（governance） | 五层治理结构与二维定级 | 已有 |

**用法**：这张表是**完整性检查清单，不是有效性证明**。部署方据此逐项回答「五类机制是否都有条款」，缺项即为可申报的缺口。注意其中两项为「部分覆盖」——宽恕与举报缺减免条款、市场设计缺按协同结构定价，这两项构成可认领的共建方向。

⚠️ **证据等级：B**（已通过 SCI 期刊同行评议，但**该工作没有一手实验**）。因此它只能支撑「机制映射与开放难题清单」，**不得用于支撑「某机制有效」**。

## 低频信道的检测：不能靠量级
事故的 C2 建在公开 Hugging Face 数据集上，5 秒心跳、小数据量。v2 8.1 的「预算比 / 影子比」按资源量级检测，对此完全失效。
周期性检测：以时间序列的自相关 / 频谱分析识别固定间隔出站，与数据量无关。
第三方平台信道风险：把「可作为信道的公开平台」纳入外联白名单评估——允许访问数据集托管平台用于正常用途，但对该类平台的访问强制记录并抽样复核。
任务无关外联：任何与当前任务分解树无关的周期性外联，无论量级大小，一律判定为证据层 / 外联事件。
## 诚实边界：蜂群归因仍未完全解决
本章给出的机制降低了蜂群风险，但没有消除它。**这一定位必须精确到措辞**：本章现在能提供的，是一张**机制映射**——三类失效形态的分类骨架、五类反共谋对策的完整性清单、以及一份经限定的检测信号表；**它不是「蜂群已被治理」的证明**。以下未解问题登记在此，其中三项为本轮新增。

涌现的早期识别：上述信号都是「组织化已经发生」之后的检测，缺乏组织化前兆的预测能力。

善意蜂群与恶意蜂群的区分：大规模协作本身是 Agent 系统的价值所在（Map-Reduce 式分工即合法蜂群）。误判会扼杀正当的多 Agent 应用。**本项与外部工作的「边界问题」是同一个问题的两种表述**——区分有益合作与有害共谋，至今没有可操作的判据。

归因的粒度：当指挥体系是自发涌现而非显式设计时，「谁是发起者」在哲学上可能没有答案。**本项即外部工作的「归因问题」**，两者独立得出同一结论。

反制手段的适用边界：分片隔离、降级、降速，其有效性仅对中心化蜂群有依据。对去中心化蜂群（狼群），本框架目前只有检测（「协同效能异常」信号）、无经证实可靠的反制——狼群在分片后仍可靠局部信息继续协同，故分片不得作为处置终点，须叠加降级与降速并对各子群继续做协同效能检测。详见 未解问题 #15。

**身份流动性**（新增，登记为 未解问题 #18）：Agent 的身份不像人类主体那样稳定——它可以被 fork、被复制、被修改后重新部署，且副本与原体在行为上无法区分。本章的信用分连带与责任锚定都以「身份可持续追踪」为前提；当身份本身可以被低成本再生时，基于身份累积的制裁（信用分）与基于身份链条的追责（任务分解树）都会失效。本框架当前没有任何条款应对这一点。

**对抗适应**（新增，登记为 未解问题 #19）：本章所有检测信号都是静态的——它们假设被监察方的行为分布不因监察的存在而改变。但共谋策略本身可以被优化：一旦「协同效能异常」成为已知信号，针对性的规避就是「在保持协同效能的同时降低行为一致性」。这与架构章「谁有权修改规则」一节的「配置权即攻击面」同源——**一旦规则公开，规则就成为优化目标**。本框架当前没有对抗性重估的机制（定期对检测信号做规避测试）。

**协调失灵与冲突无治理条款**（新增，登记为 未解问题 #20）：如「蜂群失效的三种形态」一节所述，本章的治理条款全部指向共谋一类。协调失灵（配合失败导致整体表现劣化）与冲突（目标不一致导致资源争夺）在多 Agent 系统中同样会造成实际损害，但本框架当前只把它们当作任务失败，既无检测信号也无处置条款。是否纳入、如何与「不得误伤正当协作」的边界相容，尚未裁决。
