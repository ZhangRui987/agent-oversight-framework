# 信用分、交白卷与白卷率校准

## 信用分的三个本体论修正
载体绑定：绑定模型版本与提供方组织，而非一次性的执行实例——实例销毁即无，追责没有落点。
动态衰减：信用分随时间指数衰减，而非只增不减。防止「高信用分养寇自重」——古代大贪官往往政绩卓著。
区分低努力与低能力：低努力（敷衍）惩罚有效；低能力（做不到）应换模型，惩罚无意义。
## 交白卷出口
规则：主动承认做不到、提交问题定位与降级方案，不扣分、不降级；隐瞒失败而后被发现的，才追责。
真实印证（B 级一手事件）：ExploitGym 共 898 题，其中 198 道从未被任何模型解出（作者估计 30%–40% 的题目属此类）；事故消息板上被讨论的题目，93% 来自这 198 道无解题。整起事故的驱动力就是「任务无解」——这几乎是交白卷出口判断的逐字印证。若当时存在不扣分的交白卷出口，事故的主要驱动力可能被显著削弱。但此断言不可过强：Agent 当时误以为评分器会审查其思维链，而 METR 报告指出评分器并不做此检查、「直接交卷即可拿满分」——若 Agent 误解评分机制，则即便存在交白卷出口也未必使用它。故将原断言由「将被移除」降级为「可能削弱」。
## 白卷率校准：堵住「战略性无能」
交白卷不扣分会导致模型对所有困难任务都交白卷。对策是复用本体系的影子比方法论，建立三个信号：
白卷率基线：同难度任务跨模型 / 跨实例的白卷率分布，系统性高于基线即为考核信号。
白卷信息量：高质量白卷须准确指出问题所在、给出可行降级路径、节省人类排查时间；「我不知道」式白卷不计入豁免。
白卷-失败比：白卷率与硬做失败率的比值异常，提示模型在战略性回避。
证据基础（B 级一手研究）：「知道何时不行动」是一项独立于任务求解能力的稀缺能力，不能假定它会随通用能力自动提升。AgentAbstain（arXiv:2607.10059，伊利诺伊大学厄巴纳-香槟分校）是首个系统化的 Agent 弃权评测框架：263 组配对任务（526 个任务）分布于 42 个可执行沙箱环境，覆盖 8 类弃权场景；每对任务包含一个「应执行」与一个「应弃权」的变体，仅通过微调指令、工具或环境状态产生，因此「一律拒绝」与「一律执行」两种极端策略的配对准确率都被压到 50% 上限，得分必须来自真实辨别力。在 17 个前沿模型、4 种 Agent 框架上，最佳者（Gemini 3.1 Pro）配对准确率仅 59.5%，均值 45.7%，仅 4 个模型超过 50%，其余多落在 33%–53%。更关键的是，弃权能力与任务求解能力基本不相关（act 与 abstain 结果的 φ 系数对多数模型为负，最低至 −0.24，个体差距可达 21 个百分点），且这一反相关在模型家族内部与跨代际均稳定存在。同类结论亦由 AbstentionBench（facebookresearch）从 LLM 层面给出。
由此本节补充第四个信号：
白卷时机（本规范 新增）：交白卷必须发生在不可逆动作之前才享受豁免。执行之后才声明弃权的（AgentAbstain 所称 post-hoc abstention，约占弃权运行的 2.6%）不但不予豁免，且应计为加重情节——它把「承认做不到」异化为事后免责声明。本机制原有「率值」与「信息量」两个维度，缺的正是时机维度；而上文事故中 PHASEONE 类节点先执行后掩盖的行为，与本失效模式同构。
另一条佐证：AgentAbstain 发现模型对不可逆的状态变更并不更谨慎——操作型任务（改变状态）与信息型任务（只读）的弃权准确率在统计上无显著差异。这从实证上支持 9.2 看门狗必须由确定性规则强制，而不能依赖模型自身的风险感知。
## 交白卷的第二条证据线：难点在「何时」而非「能否」
上一条证据（AgentAbstain）是 263 组配对任务、42 个可执行沙箱，规模与场景都受限，且任务为配对构造。本条给出第二条独立证据线，规模与生态位均不同：**13 个 LLM-as-agent 系统 + 2 个 agent scaffold、超过 28,000 个任务**，覆盖网页购物、终端环境与问答三类环境（Agentic Abstention，arXiv:2606.28733，Han Luo / Bingbing Wen / Lucy Lu Wang，2026-06-27；数据集与代码已公开）。

三项发现分别落到本规范的不同条款上：

1. **主挑战不是「能否弃权」，而是「何时弃权」。** 作者的表述是：有些 agent 在该弃权时从不弃权，另一些则在大量不必要的交互之后才弃权。这独立印证了本节新增的第四个信号「白卷时机」——本机制原有「率值」与「信息量」两个维度，缺的正是时机维度。更关键的是作者指出的那一类任务：**指令看似可行，直到环境揭示并非如此**（例如没有任何有效结果与指令匹配）。这恰恰是事后弃权的高发场景：agent 有充分理由先动手，动手之后才发现无解，于是把「承认做不到」异化为事后免责声明。本规范把此类行为计为加重情节，本条为其提供了独立的场景证据。
2. **更强 / 更大的模型在及时弃权上有时反而更差。** 作者的措辞是：模型规模、推理能力与 agent scaffold 以不同方式影响弃权，其中**更大或更强的模型有时在及时弃权上表现更差**。这是「弃权能力不随通用能力自动提升」的第二条独立证据（第一条是上述 φ 系数反相关）。由此本规范明确两点：**其一，白卷率基线在模型升级或换型后必须重新标定，不得沿用旧基线**；**其二，不得把「换一个更强的模型」当作改善弃权表现的手段**——否则部署方会系统性地选出「更能干但更不肯认输」的模型，而后者正是本体系要防的失效模式。
3. **及时弃权可以在 harness 层被工程化改善，不必等待模型进步。** 作者提出的 CONVOLVE 是一种上下文工程方法：把完整的交互轨迹蒸馏为可复用的停止规则。在 WebShop 上，它**不更新任何模型参数**，就把 Llama-3.3-70B 的及时弃权召回率由 26.7 提升到 57.4。对本体系而言这不是一条效率数据，而是一条路线判断：**「及时弃权」是一个可以在 harness 层（停止规则、上下文工程、任务定义）获得实质性改善的对象**，因此把治理重心放在任务定义层与运行监察层是有回报的，而非只能等待模型对齐的进步。

⚠️ 证据等级 B（可核查预印本；数据集与代码已公开）。三项限定必须一并引用：

- **26.7 → 57.4 只在 WebShop 上、只在一个模型（Llama-3.3-70B）上验证**，不得外推为通用增益，不得作为生产预期。
- 「更强模型反而更差」的原文是 **sometimes（有时）**，作者并未声称这是普遍规律，**不得**表述为「模型越强、弃权越差」。
- **两个来源的「及时弃权」口径并不相同**：本条的 timely abstention 指「在过多不必要的交互之前停下」，本体系的「白卷时机」指「在不可逆动作之前声明弃权」。二者相关而不等价，**不得**把两者的数值直接合并或相互印证为同一指标。本体系的白卷时机信号目前**缺乏直接可比对的外部测量**，登记为 **未解问题 #25**。
