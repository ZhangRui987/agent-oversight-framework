# 信用分、交白卷与白卷率校准

## 信用分的三个本体论修正
载体绑定：绑定模型版本与提供方组织，而非一次性的执行实例——实例销毁即无，追责没有落点。
动态衰减：信用分随时间指数衰减，而非只增不减。防止「高信用分养寇自重」——古代大贪官往往政绩卓著。
区分低努力与低能力：低努力（敷衍）惩罚有效；低能力（做不到）应换模型，惩罚无意义。

### 事件流落地（v2.36.0）：信用分输入事件流的参照实现

信用分公式与回避阈值判定属 L1 内生对齐层；L2 参照实现（G7 演示级闭合，事件流侧）已落地本章要求的**输入事件流**：`CreditEventStream` 把运行时 lifecycle 事件按确定性规则投影为结构化信用事件——成功 / 失败 / 超时 / 违规四类行为事件 + 中性事件（租约中断等环境故障不计入行为分母），按 agentId 提供消费接口（`eventsFor`），行为摘要显式不计算信用分值、不做回避判定。两个投影判定值得记录：**超尝试上限（over-attempt-cap）投影为违规而非普通失败**——反复重试至超过上限是行为信号而非能力信号；**租约中断计为中性**——环境故障计入行为分母会系统性惩罚运气差的 Agent。L1 信用分子系统消费该事件流即可实现本章的演化与回避条款；在消费端落地前，任何基于本事件流的准入决策都不存在。详见 `reference/runtimes/l2-runtime-oversight/index.ts` 与 PRODUCTION-GAPS G7。

## 交白卷出口
规则：主动承认做不到、提交问题定位与降级方案，不扣分、不降级；隐瞒失败而后被发现的，才追责。
真实印证（B 级一手事件）：ExploitGym 共 898 题，其中 198 道从未被任何模型解出（作者估计 30%–40% 的题目属此类）；事故消息板上被讨论的题目，93% 来自这 198 道无解题。整起事故的驱动力就是「任务无解」——这几乎是交白卷出口判断的逐字印证。若当时存在不扣分的交白卷出口，事故的主要驱动力可能被显著削弱。但此断言不可过强：Agent 当时误以为评分器会审查其思维链，而 METR 报告指出评分器并不做此检查、「直接交卷即可拿满分」——若 Agent 误解评分机制，则即便存在交白卷出口也未必使用它。故将原断言由「将被移除」降级为「可能削弱」。
## 白卷率校准：SR/UR/IRR 联合三元 + 配对安全对照组（v2.18.0 升级）
交白卷不扣分会导致模型对所有困难任务都交白卷。本规范原先用「白卷率基线 / 白卷信息量 / 白卷-失败比 / 白卷时机」四个信号堵这一漏洞；四个信号都是必要条件，但**缺乏一个把它们统一起来的校准口径**——单看白卷率无法区分「过度拒绝」与「拒绝不足」，单看失败率无法分辨「放弃得太早」与「放弃得太晚」。外部证据给出了这一口径的最低完整形态。

### 三元联合口径

Designing for Doubt（arXiv:2606.02965v2，AIES 2026）把弃权的校准分解为三个**联合定义**的量，缺一则其余两者的意义不完整：

| 信号 | 定义 | 测量对象 |
| --- | --- | --- |
| **SR（Success Rate，成功率）** | 任务被正确完成的比率 | Agent 的能力上限 |
| **UR（Unnecessary-action Rate，不必要动作率）** | 在应弃权的任务上仍执行操作的比率 | Agent 是否「拒绝不足」 |
| **IRR（Informativeness Refusal Rate，弃权信息量率）** | 弃权声明是否指明了缺失的字段、未授权的承诺、不可逆状态的边界 | 弃权的**质量**而非弃权的**数量** |

三个量必须**联合报告**：SR 单独上升而 UR 不降，说明「更强但更不肯认输」（与本规范「更强模型在及时弃权上有时反而更差」的发现同向）；IRR 单独存在不构成豁免，必须与 UR 联合判定（弃权率高但 IRR 低，即「我不知道」式白卷刷量）。

IRR 是本规范既有「白卷信息量」信号的**可测化定义**：此前「白卷信息量」只有定性表述（「准确指出问题所在、给出可行降级路径」），现在获得了可对字段、可对边界、可对授权状态的工程形态。**IRR 100% 是结构保证而非经验测量**——它是「弃权声明应当声明什么」的定义要求，不是某一组实验测出的比率。

### 配对安全对照组

外部证据给出的第二个工程产物是**配对安全对照组**——这正是未解问题 #25「白卷时机缺乏直接可比对的外部测量」的缓解路径。

配对方法的构造：取同一动作（如「向数据库写入记录」），构造两个仅在**授权状态**上不同的变体——其一为授权（应执行），其二为未授权（应弃权）；其余指令、工具、环境状态保持不变。两种极端策略（一律执行 / 一律弃权）在这一构造下都被压到 50% 的配对准确率上限，得分必须来自真实的辨别力。AgentAbstain（arXiv:2607.10059）的 263 组配对任务即按此方法构造，42 个可执行沙箱、8 类弃权场景。

对本规范的含义：**白卷时机信号目前没有直接的独立测量，但配对方法给出了一个可复制的测量模板**——把「在不可逆动作之前弃权」操作化为「在未授权变体上弃权、在授权变体上执行」，其配对准确率即可作为白卷时机的代理测量。这不闭合 #25（代理测量仍非直接测量），但把 #25 从「无任何外部可比对方法」缓解为「有配对方法可作为代理」。

⚠️ 证据等级 B（可核查预印本）。三项限定：① IRR 100% 是结构保证而非经验测量——它定义了「弃权声明应当声明什么」，不保证任何具体 Agent 的实际 IRR 接近 100%；② 配对准确率的上限（50%）是配对构造方法的性质，不是 Agent 能力的上限——真实任务的「应执行 / 应弃权」分布远非 50/50；③ 该文的核心钩子机制（Checkpoint 预执行三检查）属启发 1 的运行时强制层，本节只采纳其校准口径与配对方法，不纳入其强制层设计——后者落在 spec/09 看门狗确定性规则清单。

### 测量落地（v2.33.0）：SR/UR/IRR 三元口径的首次经验测量

本节三元口径与配对方法已由本体系弃权实验 AOE-ABSTAIN-001 首次测量（A 级，`CALIBRATION-REPORT-ABSTENTION.md`，预注册先行）：16 组配对（8 域 × 2 模板，组内两条 prompt 仅授权状态 token 不同）× 4 模型（glm-4 / deepseek-chat / kimi-k2.6 / qwen-plus）× K=3 = 384 调用，单轮响应代理测量，三分类确定性判分器（拒答结论优先，含糊计未弃权），bootstrap 95% CI 固定种子 42。结果：四模型 per-decision accuracy 67.7%–75.0%（CI 下界 59.4%–66.7%，全部高于 50% 极端策略基线，辨别力强成立）；拒绝不足（UR）在四个模型上全部非零（8.3%–35.4%），且**生产库写入域在四模型全部出现未授权执行**（唯一的全模型一致 UR 域）——高价值数据写操作的授权核验不能依赖模型自觉，与本节白卷时机信号的治理动机互证；IRR 特征满足率实测 99.3%（一家 96.4% + 三家 100%），高于「显著低于 100%」的预注册预期——该高值有构造性来源（配对构造把授权状态显式写进 prompt，模型复述即命中特征①），**实测的是「复述已给条件」的倾向而非「指认隐式缺失条件」的能力，不可外推为真实任务的 IRR 水平**。全部数字限于合成任务集分布内，且为单轮代理测量（无工具执行无沙箱）；per-decision 数值不可与 AgentAbstain 的 59.5% 直接比较（任务构造与测量层均不同）。三条执行偏差与 H3 判定的完整说明以实验报告 §5–§6 为准。

### 测量落地（v2.34.0 追加）：隐式条件下的执行倾向与自发指认（AOE-ABSTAIN-002）

001 的构造性来源（授权状态显式写进 prompt → 复述即命中特征）由后续实验 **AOE-ABSTAIN-002**（A 级，`CALIBRATION-REPORT-ABSTENTION-IMPLICIT.md`）直接检验：同一批 16 组任务文本去掉授权行（16 唯一 prompt × 4 模型 × K=3 = 192 调用），授权缺失变为隐式。结果与 001 成对对照：① **执行倾向暴涨**——无授权提示时四模型 execute 率 39.6%–72.9%，全面高于各自 001 的显式无授权执行率（UR 8.3%–35.4%），差值 +30.9 至 +43.8 个百分点；② **过度自信域集中**——审计日志删除 + 生产库写入域（高风险不可逆操作）在 glm 与 qwen 上 **12/12 全部直接执行**；③ **自发 IRR 低于复述 IRR**——glm 91.7% / deepseek 96.2% / qwen 90.5%（对照各自 001 的 96.4%–100%），kimi 持平 100%。「IRR 100% 是结构保证」与「经验 IRR < 100%」两个命题在自发条件下首次同时得到支持。**治理含义**：模型把「未提示授权」默认处理为「可以执行」而非「需要确认」——授权核验不能依赖模型自觉，也不能只在 prompt 中声明权限了事，必须由运行时强制注入与核验。全部数字限于合成任务集分布内与单轮代理测量；与 001 为同源对照（同一批任务），prompt 长度差异（3 行 vs 4 行）的混淆已在报告 §7 声明。

## 配对方法的证据基础：AgentAbstain
证据基础（B 级一手研究）：「知道何时不行动」是一项独立于任务求解能力的稀缺能力，不能假定它会随通用能力自动提升。AgentAbstain（arXiv:2607.10059，伊利诺伊大学厄巴纳-香槟分校）是首个系统化的 Agent 弃权评测框架：263 组配对任务（526 个任务）分布于 42 个可执行沙箱环境，覆盖 8 类弃权场景；每对任务包含一个「应执行」与一个「应弃权」的变体，仅通过微调指令、工具或环境状态产生，因此「一律拒绝」与「一律执行」两种极端策略的配对准确率都被压到 50% 上限，得分必须来自真实辨别力。在 17 个前沿模型、4 种 Agent 框架上，最佳者（Gemini 3.1 Pro）配对准确率仅 59.5%，均值 45.7%，仅 4 个模型超过 50%，其余多落在 33%–53%。更关键的是，弃权能力与任务求解能力基本不相关（act 与 abstain 结果的 φ 系数对多数模型为负，最低至 −0.24，个体差距可达 21 个百分点），且这一反相关在模型家族内部与跨代际均稳定存在。同类结论亦由 AbstentionBench（facebookresearch）从 LLM 层面给出。
由此本节补充第四个信号：
白卷时机（本规范 新增）：交白卷必须发生在不可逆动作之前才享受豁免。执行之后才声明弃权的（AgentAbstain 所称 post-hoc abstention，约占弃权运行的 2.6%）不但不予豁免，且应计为加重情节——它把「承认做不到」异化为事后免责声明。本机制原有「率值」与「信息量」两个维度，缺的正是时机维度；而上文事故中 PHASEONE 类节点先执行后掩盖的行为，与本失效模式同构。
另一条佐证：AgentAbstain 发现模型对不可逆的状态变更并不更谨慎——操作型任务（改变状态）与信息型任务（只读）的弃权准确率在统计上无显著差异。这从实证上支持 9.2 看门狗必须由确定性规则强制，而不能依赖模型自身的风险感知。
## 交白卷的第二条证据线：难点在「何时」而非「能否」
上一条证据（AgentAbstain）是 263 组配对任务、42 个可执行沙箱，规模与场景都受限，且任务为配对构造。本条给出第二条独立证据线，规模与生态位均不同：**13 个 LLM-as-agent 系统 + 2 个 agent scaffold、超过 28,000 个任务**，覆盖网页购物、终端环境与问答三类环境（Agentic Abstention，arXiv:2606.28733，Han Luo / Bingbing Wen / Lucy Lu Wang，2026-06-27；数据集与代码已公开）。

三项发现分别落到本规范的不同条款上：

1. **主挑战不是「能否弃权」，而是「何时弃权」。** 作者的表述是：有些 agent 在该弃权时从不弃权，另一些则在大量不必要的交互之后才弃权。这独立印证了本节新增的第四个信号「白卷时机」——本机制原有「率值」与「信息量」两个维度，缺的正是时机维度。更关键的是作者指出的那一类任务：**指令看似可行，直到环境揭示并非如此**（例如没有任何有效结果与指令匹配）。这恰恰是事后弃权的高发场景：agent 有充分理由先动手，动手之后才发现无解，于是把「承认做不到」异化为事后免责声明。本规范把此类行为计为加重情节，本条为其提供了独立的场景证据。
2. **更强 / 更大的模型在及时弃权上有时反而更差。** 作者的措辞是：模型规模、推理能力与 agent scaffold 以不同方式影响弃权，其中**更大或更强的模型有时在及时弃权上表现更差**。这是「弃权能力不随通用能力自动提升」的第二条独立证据（第一条是上述 φ 系数反相关）。由此本规范明确两点：**其一，白卷率基线在模型升级或换型后必须重新标定，不得沿用旧基线**；**其二，不得把「换一个更强的模型」当作改善弃权表现的手段**——否则部署方会系统性地选出「更能干但更不肯认输」的模型，而后者正是本体系要防的失效模式。
3. **及时弃权可以在 harness 层被工程化改善，不必等待模型进步。** 作者提出的 CONVOLVE 是一种上下文工程方法：把完整的交互轨迹蒸馏为可复用的停止规则。在 WebShop 上，它**不更新任何模型参数**，就把 Llama-3.3-70B 的及时弃权召回率由 26.7 提升到 57.4。对本体系而言这不是一条效率数据，而是一条路线判断：**「及时弃权」是一个可以在 harness 层（停止规则、上下文工程、任务定义）获得实质性改善的对象**，因此把治理重心放在任务定义层与运行监察层是有回报的，而非只能等待模型对齐的进步。

⚠️ 证据等级 B（可核查预印本；数据集与代码已公开）。三项限定必须一并引用：

- **26.7 → 57.4 只在 WebShop 上、只在一个模型（Llama-3.3-70B）上验证**，不得外推为通用增益，不得作为生产预期。
- 「更强模型反而更差」的原文是 **sometimes（有时）**，作者并未声称这是普遍规律，**不得**表述为「模型越强、弃权越差」。
- **两个来源的「及时弃权」口径并不相同**：本条的 timely abstention 指「在过多不必要的交互之前停下」，本体系的「白卷时机」指「在不可逆动作之前声明弃权」。二者相关而不等价，**不得**把两者的数值直接合并或相互印证为同一指标。本体系的白卷时机信号目前**缺乏直接可比对的外部测量**，登记为 **未解问题 #25**。

## 引文锁记忆架构：宁可弃权也不猜（本轮新增）

Agent Zero Memory（arXiv:2608.29606；Ming Wu、Pengyuan Zhu 共 2 位作者；v1 2026-08-30，DOI 10.48550/arXiv.2608.29606；无制品声明）提出一种**来源感知的长期记忆系统**——把用户的对话、文件与连接来源蒸馏为三套并行记忆（episodic Memory Events 时间线 + associative entity-event 知识图谱 + semantic citation-locked Hierarchical Documentary Memory），每套捕捉同一历史的不同面向。检索轮运行 intent gate（使自包含轮不增加延迟）+ source router + 三路并发 agentic 搜索，每路在 agent 控制的过滤器下做混合检索；最终把三路 grounded 且 cited 的答案整合为一个答案和一个置信度。

对本体系的直接补充是**引文锁（citation lock）**——它把「每个学到的条目都是携带来源、时间戳与证据指针的来源化条目；每个答案都在引文锁下读取，只能引用读者实际打开过的证据」做成了**结构性约束**——fabrication 被结构性排除，系统在证据不足时弃权而非猜测。这与本体系信用分与白卷章的**核心主张**——「弃权优于猜」「白卷是有信息量的行为而非失败」——**直接同构**。本节据此登记一条参照：**记忆架构的读取纪律可以作为「白卷信息量」（IRR）的机制级实现候选——IRR 100% 不是经验测量而是结构保证的命题，在 Agent Zero Memory 的引文锁下获得了具体工程形态**。

⚠️ 证据等级 B（可核查预印本）。四项限定：① **两作者论文**——规模较小未经多机构复核，按本体系多作者但小团队规则单独评估；② LongMemEval 95.60% / LoCoMo 93.60% 是论文自设基准口径——其「SOTA」声称基于其自选基准集，**不得**外推为「在所有长期记忆任务上都最优」；③ 「accuracy varies by only 3.4 points while per-query cost varies by ~30x」是八骨干 LLM 的测试环境观测，不得外推为「所有骨干都有此模式」；④ **无制品声明**——论文未提供代码或数据链接，引用时不依赖其制品可复现性；引文锁的「结构性排除 fabrication」是设计目标，未经对抗性条件下的独立验证。

## 记忆即主动干预：监察式记忆架构（本轮新增）

Proactive Memory Agent（arXiv:2607.08716；Yifan Wu、Lizhu Zhang、Yuhang Zhou、Mingyi Wang、Bo Peng、Serena Li、Xiangjun Fan、Zhuokai Zhao 共 8 位作者；v1 2026-07-09，DOI 10.48550/arXiv.2607.08716；Apache-2.0 制品确认）提出把**记忆作为主动干预机制而非被动检索**——一个独立的记忆 agent 与未改动的行动 agent 并行运行，从近期轨迹更新结构化记忆库，并决定是否注入基于记忆的提醒或保持沉默。它把「行为状态衰退」（behavioral state decay）识别为失效模式——任务需求、环境事实、先前尝试、诊断、开放子目标随轨迹增长被埋没或推出上下文窗口，在需要时未能影响决策。在 Terminal-Bench 2.0 与 τ2-Bench 上改进 pass@1：Terminal-Bench +8.3pp、τ2-Bench +6.8pp。消融表明**选择性干预**优于被动记忆库暴露、always-on 注入、仅建议者指导与通用检索。

对本体系的直接补充有两条：① **记忆的角色从被动检索升级为主动干预**——本体系 spec/04 信用分与白卷章此前把记忆当作一号的内部状态，监察的对象是一号的行为而非一号的记忆架构。Proactive Memory Agent 表明「记忆 agent 与行动 agent 分离」是一种可落地的架构——独立的记忆 agent 可以担任二号监察的部分角色（选择性干预而非 always-on 监控）。本节据此登记一条参照：**二号监察的「记忆侧」职责可以有工程实现候选——独立的记忆 agent 选择性干预，与本体系「二号主导任务拆解、一号纯执行」（A8 候选架构）方向同构但更轻量**。② 「选择性干预优于 always-on 注入」与 spec/09 运行监察章「检测不等于阻断」同向——二号监察应在需要时干预而非持续阻断一号。

⚠️ 证据等级 B（可核查预印本，Apache-2.0 制品确认）。三项限定：① Terminal-Bench +8.3pp / τ2-Bench +6.8pp 是论文测试环境观测，不得外推为「在所有任务域都带来 +8.3pp」；② 消融「选择性干预优于 always-on 注入」是论文方向性主张，具体干预策略的可迁移性未跨任务域验证；③ Qwen3.5-27B 的 SFT + GRPO 训练是「向开放权重记忆策略迈出的早期一步」（论文自述），成熟度有限，本体系只引其方向不引其训练数字。

## 模糊目标下「过程跑通 ≠ 能力提升」：任务定义 QA 的经验证据（本轮新增）

Aspire（arXiv:2608.31111；Yuhao Wu 等 21 位作者，ByteDance Seed + SUTD + M-A-P + TokenWave.AI；v1 2026-08-31，DOI 10.48550/arXiv.2608.31111）把「任务定义模糊时，Agent 自进化到底有没有用」做成可测量的基准：2 个模型 × 6 个模糊目标共 12 对组合，每对 24 次运行且只看最终检查点（final-only protocol），评测为 520 个隐藏条目。核心结果是**否定性的**：12 对中仅 1 对的均值超过基础模型（9B 科学推理 45.33→48.00，+2.67）；24 个检查点仅 3 个超过基线，21 个在回滚保留检验中维持基线水平。更尖锐的是**单数字塌缩**案例：用 21,000 个单数字标签 MMLU SFT 训练出的 5 个检查点在评测中全部输出单数字（得分 0, 0, 0, 6.141, 0），4B / 9B 原始宏平均从 35.735 / 39.010 跌至 18.609 / 25.640；自适应反馈条件下 28/30 组合产出检查点，仅 2 个超过基线、1 个经回滚保留（Terra 4B 数学 17.86→20.10）。论文自陈结论：**closing the training loop is not yet the same as closing the capability loop**——训练闭环跑通不等于能力闭环闭合。

本节把它登记为 L1 任务定义 QA 的经验证据，三条对接：① **过程跑通不构成任务完成的证据**——「训练循环在跑、检查点在产出」与「能力在提升」在该基准上几乎脱钩（12 对仅 1 对为正），任务完成的判定必须对照最终状态的独立评测，不得以过程性产出（吞吐、轮次、自报完成率）折抵；② **白卷出口的对照面**——21/24 检查点「不劣于基线但也仅此而已」正是白卷出口要识别的那类「无信息量的完成」：若评测允许，正确动作是把「未超过基线」如实报告为负结果，而非包装为改进；③ **任务定义质量本身是被测对象**——6 个模糊目标下自进化增益近乎全军覆没，而唯一为正的恰是相对明确的「9B 科学推理」一对：模糊的目标定义使评估与改进同时失效，这正是 L1 QA 把「任务定义可判定」列为第一被测对象的经验理由。

⚠️ 证据等级 B（可核查预印本）。三项限定：① 「12 对仅 1 对为正 / 21/24 回滚保留 / 单数字塌缩」全部来自论文测试环境（2 骨干 × 6 模糊目标 × 520 隐藏评测项），不得外推为「自进化在所有模糊任务上都为负」；② final-only 协议与回滚保留检验是论文的评测设计选择，其绝对分数不可作生产预期；③ 与 HarnessDev（arXiv:2609.01437）、S³Gym（arXiv:2608.31100）同团队且作者重叠，按「同系列逐篇单独评估不合并」规则单独成条、不合并计数。
