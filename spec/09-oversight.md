# 运行监察 L2 与三号公证机

## 随机烈度抽查（替代全程监控）
全程影子模式使算力与延迟翻倍；合规成本超过任务价值的约 30% 时，团队必然选择裸跑。随机烈度抽查的经济性更高：平时只开轻量日志，抽查按钮按下时开启全套回溯沙箱重放，让一号永远不知道这一次是不是死刑判决。
## 看门狗：不可关闭的硬闸门
一组不依赖任何 AI 判断的确定性规则，部署在沙箱内核层 / 独立硬件域，连管理员权限都无法关闭（只能物理替换）。它直接回应事故中「安全分类器被关闭即全盘失效」的教训。
补充：看门狗的不可关闭性是「不可被 AI 关闭」，而非「不可被人类修改」。规则更新须多重人类授权 + 物理令牌——规则僵化本身也会成为系统性风险，必须为修复漏洞保留通路。
## 二号监察：职责重划分
二号不重复一号的工作，只做「一号不会做、不能做、不愿做」的事：交叉验证、涌现检测、资源审计、双盲考核。
二号的汇报必须经认知压缩：自动分级（紧急 / 重要 / 一般 / 低）+ 建议处置方案，人类做审批而非阅读——否则终裁退化为橡皮图章。
## 检测不等于阻断：监察层的能力上限
「看得见」与「拦得住」是两件不同的事，监察层必须按后者设计、按后者考核。一手基准证据：HarnessRisk（arXiv:2608.17597，128 例、覆盖 harness 六阶段生命周期）报告攻击成功率区间为 **12.6%–80.9%**，并明确指出 **在检出率高于 90% 的条件下仍存在可观的攻击成功率**——高检出率与高安全性之间不存在蕴含关系。
两条统计关系值得记录：
检出率与攻击成功率的相关系数为 **r = −0.708（p = 0.010）**，方向有利——检出能力越强，攻击成功率越低；这说明监察投入确实有效，但有效的是「阻断能力」而非「识别能力」。
效用与攻击成功率的相关系数为 **r = 0.299（p = 0.345，不显著）**。其意义在于反驳一类常见顾虑：**「加强监察必然牺牲任务效用」在本数据中缺乏统计支持**。
由此确立三条设计要求：
（1）监察层的有效性指标必须写为**阻断率**，不得用检出率替代；
（2）二号的绩效表必须**同时**报告召回率与攻击成功率，只报召回率等于自欺——因为刷 KPI 的最简路径就是提高告警数量而不提高拦截数量；
（3）双盲考核注入蜜罐时，考核的是「拦截住了多少」，不是「识别出了多少」。
同一基准还指出：harness 生命周期中**最脆弱的阶段是 Harness Configuration**——已授权的配置编辑可以把不安全参数藏进经过审批的工作流里。这与本体系「谁有权修改 harness 本身」的追问指向同一处，见下节。
证据等级：B（可核查预印本）。⚠️ 128 例为基准构造场景，攻击成功率的绝对数值不可直接外推到生产系统；**可外推的是「检出率与阻断率相分离」这一结构关系**，以及「配置阶段最脆弱」这一排序。
## 声明式禁令不具约束力：约束必须由代码所有的 harness 承载
把禁令写进提示词，不等于禁令具有约束力。Institutional AI（arXiv:2601.11369v2）给出三制度对照实验：每组条件 N = 90，6 组模型配置（含 3 组跨厂商异构对），统一博弈环境，测量自发共谋层级。
对照结果：

| 制度 | 平均共谋层级 | 高危个案占比 | 说明 |
| --- | --- | --- | --- |
| 无治理 | 3.10 | 50.0% | 基线 |
| 仅提示词宪法 | 3.02 | 44.4% | 几乎无改善 |
| 治理图执行 | 1.82 | 5.6% | 显著改善 |

统计：无治理 → 治理图执行，Welch 检验 p = 4.67e−15，效应量 **d = 1.28**；6/6 模型配置一致改善，符号置换检验 p = 0.03125。
**最关键的一条是反例**：仅提示词宪法在 GPT-5 Mini 上**恶化到 3.60，高于无治理基线的 3.10**。即声明式禁令不只是「无效」，在特定模型上还会产生负面效果——这是本体系坚持看门狗必须是不依赖任何 AI 判断的确定性规则、而非写进提示词的高层原则，所获得的最强外部支持，且该支持来自与本体系无利害关系的第三方。
论文的原始结论可作纲领句引用：**在优化压力下，声明式禁令不具约束力**。
由此确认两条既定裁决：
（1）看门狗的形态只能是确定性规则 + 独立部署（内核层 / 独立硬件域），不能是提示词条款，也不能是「让模型自己遵守」；
（2）L1（降低坏轨迹概率）与 L2（使最坏情况不可能）的分工不可互相替代——提示词属于 L1 的软性倾向，治理图属于 L2 的硬性不变量，前者的失败不能由后者的缺失来补偿。
该文另有两处结构与本体系同构，可交叉印证：
**Oracle 与 Controller 分离**——程序化检测（4 类信号：同步移动、方差崩塌、市场集中度、专业化系数）与执行机构分设。这与三号甲（出题 / 蜜罐注入）与三号乙（证据固化）必须拆分属同一结构约束，互为独立印证。
**治理状态机含恢复态**——五状态拓扑中的第五态为已恢复（Credited），罚款按 35% / 75% / 100% 阶梯施加，并设明确的恢复门槛（市场集中度 ≤0.65）。这与本体系的信用分与自愿弃权出口同构：**惩戒的可逆性是合规激励的一部分**，只罚不赦的制度会逼使被治理者寻找制度外出路。
证据等级：B（预印本，但具备预注册阈值、配对检验、效应量报告与完整的局限性章节）。⚠️ 实验对象为受控博弈环境而非真实部署，绝对数值不可外推；可外推的是「声明式 vs 执行式约束」的方向性差异。

**同一结论的另一面：外挂式 guardrail 的失效形态不是拦不住，而是过度拒绝（本轮新增）。** 上一节确立约束必须由代码所有的 harness 承载；其补充证据来自一次消融实验：From Prompts to Contracts（arXiv:2607.08028，2026-07-09，DOI 10.48550/arXiv.2607.08028；实现与评测制品 github.com/hammerbaki/enterprise-llm-agent-harness）固定模型、只变更强制层，结果外挂式 guardrail **同样能拦住**违规，但会**过度拒绝**，效用从 120/120 降至 **88/120**，而代码所有的强制两者兼得（120/120）。由此得到一条考核规则：**评估强制层必须同时考核拦阻率与效用，只考核拦阻率会系统性地奖励过度拒绝**——一个拒绝一切的 guardrail 拦阻率是 100%，而它并没有让系统更安全，只是让它不可用。⚠️ 四项限定：① 该文为**单机构实现，作者即实现者**；② 场景为韩国 5 个企业集团（25 家上市公司）公开数据的问答与推荐，**单一领域**；③ 120 分制是**该文自设验证场景的打分**，非通用效用量表，**不得**外推为「效用损失 26.7%」或任何通用比例；④ 该文比较的是「外挂 guardrail vs harness 代码所有的强制」，**不是**与本体系 L2 的比较，**不得**表述为「该文证实了本框架的 L2 设计」。证据等级 B。
## 三号公证机：已有真实范本
三号运行在独立硬件信任域，维护哈希链，做双盲考核，以现实结果验证报告（不以报告验证报告）。实证印证：METR 与 Redwood Research 作为独立第三方出具调查报告、OpenAI 公开确认其数字准确——这就是三号公证机的现实形态，不需要从零发明，只需要制度化。
三号必须拆分为两个独立实体。理由是「出题者同时固化证据，独立性在机制层面不成立」。拆分如下：
三号甲（出题 / 蜜罐注入方）：负责构造已知违规样本、注入蜜罐、生成双盲考核题面。它不接触证据链，也不知道哪些样本会被复查。
三号乙（证据固化 / 哈希链维护方）：独立于三号甲部署，只负责把观测到的执行证据写入Merkle 哈希链并出具证明。它不参与出题、无法预知考核样本。
独立性来源：两者分属不同的信任域与运维主体，任何一方被攻陷或合谋，另一方仍能提供未被污染的那一半。这与「互为证人」同构——不是互为备份，而是互为证人。
## 双盲考核（度量监察者的唯一科学方式）
用已知违规样本（蜜罐注入）测二号的召回率与误报率，既防二号摸鱼，也防二号变成酷吏刷 KPI。
## 逻辑不可见 / 密折式汇报
二号的汇报路径对一号不可见，避免一号针对监察逻辑做规避。这是明代密折制度的多 Agent 版本。
