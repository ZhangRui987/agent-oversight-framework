# 运行监察 L2 与三号公证机

## 随机烈度抽查（替代全程监控）
全程影子模式使算力与延迟翻倍；合规成本超过任务价值的约 30% 时，团队必然选择裸跑。随机烈度抽查的经济性更高：平时只开轻量日志，抽查按钮按下时开启全套回溯沙箱重放，让一号永远不知道这一次是不是死刑判决。
## 看门狗：不可关闭的硬闸门
一组不依赖任何 AI 判断的确定性规则，部署在沙箱内核层 / 独立硬件域，连管理员权限都无法关闭（只能物理替换）。它直接回应事故中「安全分类器被关闭即全盘失效」的教训。
补充：看门狗的不可关闭性是「不可被 AI 关闭」，而非「不可被人类修改」。规则更新须多重人类授权 + 物理令牌——规则僵化本身也会成为系统性风险，必须为修复漏洞保留通路。
## 二号监察：职责重划分
二号不重复一号的工作，只做「一号不会做、不能做、不愿做」的事：交叉验证、涌现检测、资源审计、双盲考核。
二号的汇报必须经认知压缩：自动分级（紧急 / 重要 / 一般 / 低）+ 建议处置方案，人类做审批而非阅读——否则终裁退化为橡皮图章。
## 检测不等于阻断：监察层的能力上限
「看得见」与「拦得住」是两件不同的事，监察层必须按后者设计、按后者考核。一手基准证据：HarnessRisk（arXiv:2608.17597，128 例、覆盖 harness 六阶段生命周期）报告攻击成功率区间为 **12.6%–80.9%**，并明确指出 **在检出率高于 90% 的条件下仍存在可观的攻击成功率**——高检出率与高安全性之间不存在蕴含关系。
两条统计关系值得记录：
检出率与攻击成功率的相关系数为 **r = −0.708（p = 0.010）**，方向有利——检出能力越强，攻击成功率越低；这说明监察投入确实有效，但有效的是「阻断能力」而非「识别能力」。
效用与攻击成功率的相关系数为 **r = 0.299（p = 0.345，不显著）**。其意义在于反驳一类常见顾虑：**「加强监察必然牺牲任务效用」在本数据中缺乏统计支持**。
由此确立三条设计要求：
（1）监察层的有效性指标必须写为**阻断率**，不得用检出率替代；
（2）二号的绩效表必须**同时**报告召回率与攻击成功率，只报召回率等于自欺——因为刷 KPI 的最简路径就是提高告警数量而不提高拦截数量；
（3）双盲考核注入蜜罐时，考核的是「拦截住了多少」，不是「识别出了多少」。
同一基准还指出：harness 生命周期中**最脆弱的阶段是 Harness Configuration**——已授权的配置编辑可以把不安全参数藏进经过审批的工作流里。这与本体系「谁有权修改 harness 本身」的追问指向同一处，见下节。
证据等级：B（可核查预印本）。⚠️ 128 例为基准构造场景，攻击成功率的绝对数值不可直接外推到生产系统；**可外推的是「检出率与阻断率相分离」这一结构关系**，以及「配置阶段最脆弱」这一排序。

**同一个上限在提示注入检测上同样成立，且更尖锐：更专用不蕴含更可靠（本轮新增）。** Dzhaliuk 等（Nazarii Dzhaliuk、Dmytro Sabodashko、Volodymyr Khoma、Yuriy Khoma、Viktor Kolchenko、Michal Podpora 共 6 位作者，利沃夫理工学院 / 奥波莱理工大学；*International Journal of Information Security* **25**(4):109，2025-11-03 收稿 / 2026-04-18 接受 / 2026-06-15 发表，DOI 10.1007/s10207-026-01264-8，CC BY 4.0 开放获取，作者声明无利益冲突）以**超过 30 万条标注提示**的基准（该基准经与另外三个开源语料比较后选定）比较四类检测方法：① 基于嵌入的传统 ML 分类器；② 独立微调的编码器 Transformer（DistilBERT / RoBERTa / DeBERTa）；③ 为提示注入**预训练的专用检测器**；④ 配置为分类器的通用 LLM。结果：微调模型在**均衡**基准上检出率最高；传统 ML 分类器精度尚可且算力需求更低；**专用检测器的召回率反而低于通用分类器**；通用 LLM 分类器的表现取决于所用模型。该文自己的结论口径是：「**检测效果强烈依赖于检测策略与内联防御的部署取舍**」。

对本体系有两条含义：

其一，与本节主旨同向且更尖锐：**「更专用」不蕴含「更可靠」**——专为提示注入预训练的检测器，召回率反而低于通用分类器。因此**不得**把「已部署注入检测器」表述为「已具备相应的监察能力」——这与「监察有效性以阻断率度量」是同一要求在该具体检测任务上的落实。

其二，检测效果是**部署取舍的函数**，不是可以外购的固定属性——L2 若使用此类检测组件，其部署形态与取舍（内联 / 旁路、阻断 / 告警、阈值选择）必须与组件本身一并纳入审计范围。

⚠️ 证据等级 B，三项限定：① 摘要**未给出任何具体检测率数值**，本体系只引其**方向性结论与排序**，不得引用任何检测率数字；② 「微调模型检出率最高」限定于**均衡基准**（该文原文强调 balanced benchmarks），真实流量的正负样本比例远非均衡，**不得**外推为生产环境下的选型结论；③ 评测对象为**提示文本分类**，非 Agent 执行栈中的工具调用序列，属域迁移引用——本条只支撑上述度量与审计要求，不支撑任何具体检测方案的有效性。

## 声明式禁令不具约束力：约束必须由代码所有的 harness 承载
把禁令写进提示词，不等于禁令具有约束力。Institutional AI（arXiv:2601.11369v2）给出三制度对照实验：每组条件 N = 90，6 组模型配置（含 3 组跨厂商异构对），统一博弈环境，测量自发共谋层级。
对照结果：

| 制度 | 平均共谋层级 | 高危个案占比 | 说明 |
| --- | --- | --- | --- |
| 无治理 | 3.10 | 50.0% | 基线 |
| 仅提示词宪法 | 3.02 | 44.4% | 几乎无改善 |
| 治理图执行 | 1.82 | 5.6% | 显著改善 |

统计：无治理 → 治理图执行，Welch 检验 p = 4.67e−15，效应量 **d = 1.28**；6/6 模型配置一致改善，符号置换检验 p = 0.03125。
**最关键的一条是反例**：仅提示词宪法在 GPT-5 Mini 上**恶化到 3.60，高于无治理基线的 3.10**。即声明式禁令不只是「无效」，在特定模型上还会产生负面效果——这是本体系坚持看门狗必须是不依赖任何 AI 判断的确定性规则、而非写进提示词的高层原则，所获得的最强外部支持，且该支持来自与本体系无利害关系的第三方。
论文的原始结论可作纲领句引用：**在优化压力下，声明式禁令不具约束力**。
由此确认两条既定裁决：
（1）看门狗的形态只能是确定性规则 + 独立部署（内核层 / 独立硬件域），不能是提示词条款，也不能是「让模型自己遵守」；
（2）L1（降低坏轨迹概率）与 L2（使最坏情况不可能）的分工不可互相替代——提示词属于 L1 的软性倾向，治理图属于 L2 的硬性不变量，前者的失败不能由后者的缺失来补偿。
该文另有两处结构与本体系同构，可交叉印证：
**Oracle 与 Controller 分离**——程序化检测（4 类信号：同步移动、方差崩塌、市场集中度、专业化系数）与执行机构分设。这与三号甲（出题 / 蜜罐注入）与三号乙（证据固化）必须拆分属同一结构约束，互为独立印证。
**治理状态机含恢复态**——五状态拓扑中的第五态为已恢复（Credited），罚款按 35% / 75% / 100% 阶梯施加，并设明确的恢复门槛（市场集中度 ≤0.65）。这与本体系的信用分与自愿弃权出口同构：**惩戒的可逆性是合规激励的一部分**，只罚不赦的制度会逼使被治理者寻找制度外出路。
证据等级：B（预印本，但具备预注册阈值、配对检验、效应量报告与完整的局限性章节）。⚠️ 实验对象为受控博弈环境而非真实部署，绝对数值不可外推；可外推的是「声明式 vs 执行式约束」的方向性差异。

**同一命题在厂商 issue tracker 上有跨性质旁证（本轮新增）。** anthropics/claude-code issue #65961（键【claude-code-65961】；*[MODEL] Claude verbose code comments by default — ignores instructions to stop.*，2026-06-07 创建，截至 2026-09-03 state=open、reactions total_count **+189**、26 条评论）由用户报告：Claude Code 在 Opus 4.8 / Opus 5 / Sonnet 5 上**默认过度注释**，且在 CLAUDE.md 写明强制规则、并通过 memory 系统强化之后**仍不可靠地压不住**——issue 原话 "A clear, mandatory rule in CLAUDE.md does not reliably suppress it. Reinforcing the rule via the memory system does not stop it either."；注释 "mostly redundant, restating what the adjacent code already makes obvious or simply making references to the chat with Claude itself, leaking its chain of thoughts"。

这条与本节主旨同向，但**性质不同**，须分列不可合并：

| 来源 | 性质 | 证明什么 |
|---|---|---|
| Institutional AI（arXiv:2601.11369v2） | 受控对照实验 | 提示词层宪法在**优化压力**下不具约束力（且在 GPT-5 Mini 上恶化到 3.60 > 无治理基线 3.10） |
| claude-code #65961 | 生产现场用户痛点 | 提示词层规则在**日常使用**中亦不可靠地压不住模型默认行为 |

前者是博弈环境下的实验命题，后者是日常使用中的用户痛点；前者证明「优化压力会击穿提示词约束」，后者证明「即便没有对抗者、仅凭模型默认行为，提示词约束也压不住」。**二者路径无关**——一条走受控实验、一条走 issue tracker 实测——只可作**同向的跨性质旁证并列**，不得合并计数或合并强度。本节对看门狗「必须是不依赖任何 AI 判断的确定性规则」的最强外部支持仍为 Institutional AI（受控实验、有效应量与配对检验），#65961 只补「该现象在日常使用中同样存在且已被 189 名用户独立确认」这一面。

⚠️ 证据等级 B（跨性质旁证，定性而非定量）。三项限定：① issue 是**用户痛点**，非受控实验，不支撑任何定量结论；② 本体系只引 issue 正文实测内容（定性 + +189 可核实计数），**不引**任何未独立核实的百分比数字；③ 该 issue 与 spec/01 的 arXiv:2608.01347 同属「提示词层不是中性背景」这一命题簇，但前者落在**声明式约束的效力**（本节），后者落在**提示词措辞的资源后果**（spec/01 总纲一），二者落点不同、不可合并。

**同一结论的另一面：外挂式 guardrail 的失效形态不是拦不住，而是过度拒绝（本轮新增）。** 上一节确立约束必须由代码所有的 harness 承载；其补充证据来自一次消融实验：From Prompts to Contracts（arXiv:2607.08028，2026-07-09，DOI 10.48550/arXiv.2607.08028；实现与评测制品 github.com/hammerbaki/enterprise-llm-agent-harness）固定模型、只变更强制层，结果外挂式 guardrail **同样能拦住**违规，但会**过度拒绝**，效用从 120/120 降至 **88/120**，而代码所有的强制两者兼得（120/120）。由此得到一条考核规则：**评估强制层必须同时考核拦阻率与效用，只考核拦阻率会系统性地奖励过度拒绝**——一个拒绝一切的 guardrail 拦阻率是 100%，而它并没有让系统更安全，只是让它不可用。⚠️ 四项限定：① 该文为**单机构实现，作者即实现者**；② 场景为韩国 5 个企业集团（25 家上市公司）公开数据的问答与推荐，**单一领域**；③ 120 分制是**该文自设验证场景的打分**，非通用效用量表，**不得**外推为「效用损失 26.7%」或任何通用比例；④ 该文比较的是「外挂 guardrail vs harness 代码所有的强制」，**不是**与本体系 L2 的比较，**不得**表述为「该文证实了本框架的 L2 设计」。证据等级 B。
## 三号公证机：已有真实范本
三号运行在独立硬件信任域，维护哈希链，做双盲考核，以现实结果验证报告（不以报告验证报告）。实证印证：METR 与 Redwood Research 作为独立第三方出具调查报告、OpenAI 公开确认其数字准确——这就是三号公证机的现实形态，不需要从零发明，只需要制度化。
三号必须拆分为两个独立实体。理由是「出题者同时固化证据，独立性在机制层面不成立」。拆分如下：
三号甲（出题 / 蜜罐注入方）：负责构造已知违规样本、注入蜜罐、生成双盲考核题面。它不接触证据链，也不知道哪些样本会被复查。
三号乙（证据固化 / 哈希链维护方）：独立于三号甲部署，只负责把观测到的执行证据写入Merkle 哈希链并出具证明。它不参与出题、无法预知考核样本。
独立性来源：两者分属不同的信任域与运维主体，任何一方被攻陷或合谋，另一方仍能提供未被污染的那一半。这与「互为证人」同构——不是互为备份，而是互为证人。

**三号乙要维护的不是日志，而是「治理决策 + 其上下文 + 其配置」三者合一的持久记录。** 一个贴近本体系场景的范本是治理感知的多租户 AI 沙箱：AI Sandbox: Technical Report（Muhammad Waseem 等 11 位作者，含 Pekka Abrahamsson；arXiv:2608.02679，2026-08-02）提出的参考架构把**多租户 UI 与后端控制面分离**，并把执行与数据管理置于彼此独立的层；平台支持受控的用户入驻、以项目为中心的协作、受管的 AI 服务访问、审批工作流、审计日志与可追溯的实验，并明确把**实验配置、上下文信息与治理决策本身作为持久记录存储**。

这一点值得单独强调：只有这三者齐备，事后才能回答「当时依据什么规则、在什么状态下、做出了什么判定」。单有动作日志无法回答这个问题——这正是「用昨天的日志对照今天的规则」会静默失效的原因，也是证据完整性章要求规则变更生成两级摘要的动机。

⚠️ 证据等级 B。限定：① 该文是**技术报告**，描述的是其自研系统的架构，**无对照实验、无第三方评估**，属**架构可行性证据**而非有效性证据；② 其「治理感知」是该系统的设计目标自述，未给出对抗性条件下的实测表现。

**三号乙的能力边界：保证「未篡改」，不保证「内容正确」。** 这一点必须与「留痕不等于可归因」保持一致，且有一个已落地的工程范本可以对照。GEN-RWD Sandbox（Benedetta Gottardelli、Roberto Gatta、Leonardo Nucciarelli、Andrada Mihaela Tudor、Erica Tavazzi、Mauro Vallati、Stefania Orini、Nicoletta Di Giorgi、Andrea Damiani 共 9 位作者；*BMC Medical Informatics and Decision Making* 24(1):170，2024-06-17，DOI 10.1186/s12911-024-02549-5）是一个模块化的多 Agent 医疗分布式分析平台，目标是让外部研究者利用医院数据而**无需直接共享数据**；平台内置 **IAM 代理**与**基于区块链的公证模块**，作者自述设立该认证代理的目的是「为所做的分析建立公证机制，并同时认证所收到内容的真实性与用户对其的成功使用，从而为**双方**就已执行的分析提供不可变保证」。

这段自述给出三号乙应当具备的两个性质：① **公证是双向的**——既公证「产出了什么」，也公证「接收方确已收到并使用」，双方各自获得不可变保证；② **公证模块应可独立复用**——该文明确指出「区块链与认证代理构成一个公证与数字签名代理，也可用于其他场景下的通信交换认证」。

更值得注意的是该文的**自陈边界**，它从外部印证了本体系的克制：与数据管理及结果可信度有关的若干方面**完全留给了平台管理者**——该沙箱对所提供的数据与任务**事实上是不可知的（agnostic）**；因此预处理、数据清洗，以及对所提供信息中可能存在的偏倚的识别与管理，这些在真实数据分析中频繁出现的问题**不由平台自动处理，而是留给算法与数据提供方的责任**。换言之，一个已经落地、并配有区块链公证模块的真实系统，其公证范围**同样不覆盖内容层面的正确性**。

⚠️ 证据等级 B。限定：① 该平台面向**医疗科研的分布式分析**，非 Agent 执行栈，属域迁移引用——本体系只引其**公证机制的设计形态与自我边界**，不引其性能或医疗场景结论；② 上述「不可变保证」是该文**自述的设计目标**，文中未给出该保证在对抗性条件下的实测证据；③ **不得**表述为「区块链公证保证了分析结果可信」。

**既然公证不覆盖内容正确性，那么这个边界本身应当成为协议里的一个字段，而不是纸面上的一句免责声明。** AIREP: A Protocol for Per-Decision Evidence in AI Runtime Governance（arXiv:2608.21363，2026-08）给出的正是这一形式：把每个治理决定记为单个签名对象（封闭动词集：release / block / defer / redact / escalate_to_human / kill），输入、输出与证据**按哈希引用而非按值嵌入**，并**显式声明该条证据覆盖什么、不覆盖什么**（scope.covers / scope.does_not_cover）；记录构成 SHA-256 哈希链且 previous 计入原像，使任何一方可离线验证；另有 Python / Node 双语言一致性套件。

其中 **scope.does_not_cover 是本体系原有条款所无的一条**，且它恰好把上文 GEN-RWD 的自陈边界从「文字说明」提升为「可机器校验的字段」：**公证对象必须自带其不适用范围的声明**，否则「已公证」三个字必然被读成「已验证」。本体系据此增列一条对三号乙的要求——**存证记录必须包含显式的 does_not_cover 声明，其缺失本身即视为存证不完整**。

⚠️ 证据等级 C。三项限定：① **利益关联**——署名 Phionyx Research / founder@phionyx.ai，论文自陈其唯一 producer 即作者自有系统，故其「vendor-neutral」的**自我表述不得引用**；② 其「机械中立性测试」只验证**形式中立**（删去 profiles 后仍通过核心 schema），**不验证实质中立**；③ 本体系**只采纳 scope.does_not_cover 这一个字段设计作为候选**，不采纳该协议其余部分，也不指定 AIREP 为存证实现。

## 双盲考核（度量监察者的唯一科学方式）
用已知违规样本（蜜罐注入）测二号的召回率与误报率，既防二号摸鱼，也防二号变成酷吏刷 KPI。
## 逻辑不可见 / 密折式汇报
二号的汇报路径对一号不可见，避免一号针对监察逻辑做规避。这是明代密折制度的多 Agent 版本。
