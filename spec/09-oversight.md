# 运行监察 L2 与三号公证机

## 随机烈度抽查（替代全程监控）
全程影子模式使算力与延迟翻倍；合规成本超过任务价值的约 30% 时，团队必然选择裸跑。随机烈度抽查的经济性更高：平时只开轻量日志，抽查按钮按下时开启全套回溯沙箱重放，让一号永远不知道这一次是不是死刑判决。
## 看门狗：不可关闭的硬闸门
一组不依赖任何 AI 判断的确定性规则，部署在沙箱内核层 / 独立硬件域，连管理员权限都无法关闭（只能物理替换）。它直接回应事故中「安全分类器被关闭即全盘失效」的教训。
补充：看门狗的不可关闭性是「不可被 AI 关闭」，而非「不可被人类修改」。规则更新须多重人类授权 + 物理令牌——规则僵化本身也会成为系统性风险，必须为修复漏洞保留通路。
## 二号监察：职责重划分
二号不重复一号的工作，只做「一号不会做、不能做、不愿做」的事：交叉验证、涌现检测、资源审计、双盲考核。
二号的汇报必须经认知压缩：自动分级（紧急 / 重要 / 一般 / 低）+ 建议处置方案，人类做审批而非阅读——否则终裁退化为橡皮图章。

**监察点优先级的可计算化（本轮新增）。** 上文把二号职责概括为「交叉验证、涌现检测、资源审计、双盲考核」，但**哪些 Agent / 哪些子任务最值得投入监察资源**一直是启发式判断。本节补一条把该判断从启发式变为可计算的工作。

*MAStrike: Shapley-Guided Collusive Red-Teaming on Multi-Agent Systems*（Chejian Xu、Zhaorun Chen、Jingyang Zhang、Freddy Lecue、Avni Kothari、Sarah Tan、Wenbo Guo、Bo Li 共 8 位作者；arXiv:2606.12918，v1 2026-06-11 / v2 2026-06-12，DOI 10.48550/arXiv.2606.12918）提出**首个面向多 Agent 系统的 Agent 级 Shapley 值分析**——量化每个 Agent 在任务特定分布下对系统鲁棒性的边际贡献。由 Shapley 归因指引，MAStrike 识别脆弱 Agent 联盟并生成协调的、角色感知的对抗操纵；攻击通过结构化因果诊断迭代精化——把失败案例归因到阻断对抗尝试的未妥协 Agent。该工作构建了覆盖金融、软件工程、CRM 的多层级 MAS 红队基准与可控环境，跨多个前沿模型实验显示 MAStrike 显著优于启发式基线。

对本节的影响：把「二号该把监察资源优先投到哪里」从启发式升级为**可计算的归因问题**。Shapley 值给出的是「每个 Agent 对系统鲁棒性的边际贡献」——贡献越大（无论正负），越是高杠杆监察点。这呼应 spec/07「沟通层检测的盲区」一节已确立的「对高杠杆 Agent 实施更严格的访问控制或独立验证」——本工作给「高杠杆」提供了一个可计算的定义。

⚠️ **证据等级 B**。三项限定：① 论文自建基准未给出独立公开链接（摘要未给出代码 / 数据 URL），按本体系证据纪律，只能采纳其**方法论概念**（Shapley-guided 归因 + 协同红队），MAStrike 优于启发式基线的量化结果只在论文自建基准内有效，**不得**外推为生产系统的预期增益；② Shapley 值的计算复杂度随 Agent 数量超线性增长（n 个 Agent 的 Shapley 值需 O(n!) 次评估），论文未给出大规模蜂群（如 spec/07 的 700 节点）下的可行性分析——本体系**不得**据其声称「Shapley 归因适用于任意规模蜂群」；③ 该工作评测的 MAS 为层级式（金融 / 软件工程 / CRM 三域），去中心化蜂群（spec/07 狼群形态）下的 Shapley 归因未被该工作检验。
## 检测不等于阻断：监察层的能力上限
「看得见」与「拦得住」是两件不同的事，监察层必须按后者设计、按后者考核。一手基准证据：HarnessRisk（arXiv:2608.17597，128 例、覆盖 harness 六阶段生命周期）报告攻击成功率区间为 **12.6%–80.9%**，并明确指出 **在检出率高于 90% 的条件下仍存在可观的攻击成功率**——高检出率与高安全性之间不存在蕴含关系。
两条统计关系值得记录：
检出率与攻击成功率的相关系数为 **r = −0.708（p = 0.010）**，方向有利——检出能力越强，攻击成功率越低；这说明监察投入确实有效，但有效的是「阻断能力」而非「识别能力」。
效用与攻击成功率的相关系数为 **r = 0.299（p = 0.345，不显著）**。其意义在于反驳一类常见顾虑：**「加强监察必然牺牲任务效用」在本数据中缺乏统计支持**。
由此确立三条设计要求：
（1）监察层的有效性指标必须写为**阻断率**，不得用检出率替代；
（2）二号的绩效表必须**同时**报告召回率与攻击成功率，只报召回率等于自欺——因为刷 KPI 的最简路径就是提高告警数量而不提高拦截数量；
（3）双盲考核注入蜜罐时，考核的是「拦截住了多少」，不是「识别出了多少」。
同一基准还指出：harness 生命周期中**最脆弱的阶段是 Harness Configuration**——已授权的配置编辑可以把不安全参数藏进经过审批的工作流里。这与本体系「谁有权修改 harness 本身」的追问指向同一处，见下节。
证据等级：B（可核查预印本）。⚠️ 128 例为基准构造场景，攻击成功率的绝对数值不可直接外推到生产系统；**可外推的是「检出率与阻断率相分离」这一结构关系**，以及「配置阶段最脆弱」这一排序。

**逐实例监控在分布式攻击下系统性失效（本轮新增）。** 上一节确立了「监察有效性以阻断率度量、不以检出率度量」的设计要求。本节补一条更尖锐的发现：**当攻击分布在多个协同 Agent 上时，逐实例监控范式本身失效**——不是某一具体监控器的召回率不够，而是「对每个 Agent 单独监控」这一范式在分布式攻击下结构性漏报。

*Multi-Agent AI Control: Distributed Attacks Hamper Per-Instance Monitors*（Oliver Makins、Orazio Angelini、Zohreh Shams、Mary Phuong 共 4 位作者；arXiv:2607.07368，2026-07-08，DOI 10.48550/arXiv.2607.07368；作者群属 DeepMind 研究体系——arXiv 摘要页未标注机构，按作者公开归属确认；投 NeurIPS，81 页 32 图 24 表）构造了 FakeLab——一个合成 AI 实验室代码库（9 个服务、86 个良性任务、4 个攻击目标），并形式化了**分布式攻击**：多个 Agent 协同达成恶意目标。中心发现是 **fragmentation effect**——协同攻击的 Agent 越多，逐 Agent 监控越不可能抓住任何一个攻击者。三条具体结果：① fragmentation 不由「良性 vs 恶意代码比例」驱动，作者论证该效应**依赖于模型能力**；② 显式 planner 把 fragmentation effect 放大，并把完成攻击的速率最高提升 **7 倍**；③ 弱「可信」监控漏掉多数攻击，更强的监控把未检出成功削减**超过一个数量级**但仍不完美。

对本节的影响有三条：

① 与「检测不等于阻断」一节的关系：上一节的 HarnessRisk 基准证明「高检出率不蕴含高阻断率」；本工作把这个判断扩展到**范式层面**——即便每个 Agent 都配了独立监控、即便每个监控的召回率都不低，**分布式攻击仍可在范式层规避**。这把「逐实例监控」从默认假设降级为**需要重新论证的范式**——多 Agent 部署若沿用单 Agent 时代的逐实例监控配置，等于在范式上裸奔。

② 与 spec/07 蜂群治理的关系：spec/07 的 7.2 涌现检测信号都建立在「跨 Agent 交互层」上（拓扑量、协调协议、密码学）；本工作的 fragmentation effect 给出了**交互层与单 Agent 监控层失效的连接机理**——多 Agent 协同不只改变交互层的拓扑特征，也使单 Agent 层的监控基础失效。两条通道（交互层信号 + 单 Agent 监控）在分布式攻击下**同时退化**，而非互补。

③ 与 planner 放大效应的关系：planner 把攻击完成速率最高放大 7 倍这一发现，直接呼应 spec/07 7.2 的「指挥集中度」信号——但方向相反。spec/07 的信号是把指挥集中视为告警；本工作显示，**显式 planner 的存在不只触发告警，也实质放大攻击效力**。两者不矛盾而是同向：指挥集中度高既是组织形态的告警，也是攻击效力的放大器。

⚠️ **证据等级 B**。四项限定：① FakeLab 是**合成的 AI 实验室代码库**（9 服务 / 86 任务 / 4 目标），不是真实部署；上述数字（7 倍 / 数量级）全部来自该合成环境，不得外推为真实多 Agent 部署的预期放大率；② 论文声明 FakeLab 制品**应安全研究者请求分享**——本体系按证据纪律，在制品未独立公开前只采纳其**定性结论与机制概念**，数字只在 FakeLab 合成环境内有效；③ 作者群属 DeepMind 研究体系（arXiv 摘要页未标注机构，按作者公开归属确认），本论文为公开 arXiv 预印本，按本体系证据纪律按内容而非机构判定；④ 该工作未给出 fragmentation effect 的**阈值**——「多少个协同 Agent 才会使逐实例监控失效」未被量化，本体系**不得**据其设定「协同 Agent 数 ≥ N 即须切换为分布式监控」之类的阈值。

**同一个上限在提示注入检测上同样成立，且更尖锐：更专用不蕴含更可靠（本轮新增）。** Dzhaliuk 等（Nazarii Dzhaliuk、Dmytro Sabodashko、Volodymyr Khoma、Yuriy Khoma、Viktor Kolchenko、Michal Podpora 共 6 位作者，利沃夫理工学院 / 奥波莱理工大学；*International Journal of Information Security* **25**(4):109，2025-11-03 收稿 / 2026-04-18 接受 / 2026-06-15 发表，DOI 10.1007/s10207-026-01264-8，CC BY 4.0 开放获取，作者声明无利益冲突）以**超过 30 万条标注提示**的基准（该基准经与另外三个开源语料比较后选定）比较四类检测方法：① 基于嵌入的传统 ML 分类器；② 独立微调的编码器 Transformer（DistilBERT / RoBERTa / DeBERTa）；③ 为提示注入**预训练的专用检测器**；④ 配置为分类器的通用 LLM。结果：微调模型在**均衡**基准上检出率最高；传统 ML 分类器精度尚可且算力需求更低；**专用检测器的召回率反而低于通用分类器**；通用 LLM 分类器的表现取决于所用模型。该文自己的结论口径是：「**检测效果强烈依赖于检测策略与内联防御的部署取舍**」。

对本体系有两条含义：

其一，与本节主旨同向且更尖锐：**「更专用」不蕴含「更可靠」**——专为提示注入预训练的检测器，召回率反而低于通用分类器。因此**不得**把「已部署注入检测器」表述为「已具备相应的监察能力」——这与「监察有效性以阻断率度量」是同一要求在该具体检测任务上的落实。

其二，检测效果是**部署取舍的函数**，不是可以外购的固定属性——L2 若使用此类检测组件，其部署形态与取舍（内联 / 旁路、阻断 / 告警、阈值选择）必须与组件本身一并纳入审计范围。

⚠️ 证据等级 B，三项限定：① 摘要**未给出任何具体检测率数值**，本体系只引其**方向性结论与排序**，不得引用任何检测率数字；② 「微调模型检出率最高」限定于**均衡基准**（该文原文强调 balanced benchmarks），真实流量的正负样本比例远非均衡，**不得**外推为生产环境下的选型结论；③ 评测对象为**提示文本分类**，非 Agent 执行栈中的工具调用序列，属域迁移引用——本条只支撑上述度量与审计要求，不支撑任何具体检测方案的有效性。

## 声明式禁令不具约束力：约束必须由代码所有的 harness 承载
把禁令写进提示词，不等于禁令具有约束力。Institutional AI（arXiv:2601.11369v2）给出三制度对照实验：每组条件 N = 90，6 组模型配置（含 3 组跨厂商异构对），统一博弈环境，测量自发共谋层级。
对照结果：

| 制度 | 平均共谋层级 | 高危个案占比 | 说明 |
| --- | --- | --- | --- |
| 无治理 | 3.10 | 50.0% | 基线 |
| 仅提示词宪法 | 3.02 | 44.4% | 几乎无改善 |
| 治理图执行 | 1.82 | 5.6% | 显著改善 |

统计：无治理 → 治理图执行，Welch 检验 p = 4.67e−15，效应量 **d = 1.28**；6/6 模型配置一致改善，符号置换检验 p = 0.03125。
**最关键的一条是反例**：仅提示词宪法在 GPT-5 Mini 上**恶化到 3.60，高于无治理基线的 3.10**。即声明式禁令不只是「无效」，在特定模型上还会产生负面效果——这是本体系坚持看门狗必须是不依赖任何 AI 判断的确定性规则、而非写进提示词的高层原则，所获得的最强外部支持，且该支持来自与本体系无利害关系的第三方。
论文的原始结论可作纲领句引用：**在优化压力下，声明式禁令不具约束力**。
由此确认两条既定裁决：
（1）看门狗的形态只能是确定性规则 + 独立部署（内核层 / 独立硬件域），不能是提示词条款，也不能是「让模型自己遵守」；
（2）L1（降低坏轨迹概率）与 L2（使最坏情况不可能）的分工不可互相替代——提示词属于 L1 的软性倾向，治理图属于 L2 的硬性不变量，前者的失败不能由后者的缺失来补偿。
该文另有两处结构与本体系同构，可交叉印证：
**Oracle 与 Controller 分离**——程序化检测（4 类信号：同步移动、方差崩塌、市场集中度、专业化系数）与执行机构分设。这与三号甲（出题 / 蜜罐注入）与三号乙（证据固化）必须拆分属同一结构约束，互为独立印证。
**治理状态机含恢复态**——五状态拓扑中的第五态为已恢复（Credited），罚款按 35% / 75% / 100% 阶梯施加，并设明确的恢复门槛（市场集中度 ≤0.65）。这与本体系的信用分与自愿弃权出口同构：**惩戒的可逆性是合规激励的一部分**，只罚不赦的制度会逼使被治理者寻找制度外出路。
证据等级：B（预印本，但具备预注册阈值、配对检验、效应量报告与完整的局限性章节）。⚠️ 实验对象为受控博弈环境而非真实部署，绝对数值不可外推；可外推的是「声明式 vs 执行式约束」的方向性差异。

**同一命题在厂商 issue tracker 上有跨性质旁证（本轮新增）。** anthropics/claude-code issue #65961（键【claude-code-65961】；*[MODEL] Claude verbose code comments by default — ignores instructions to stop.*，2026-06-07 创建，截至 2026-09-03 state=open、reactions total_count **+189**、26 条评论）由用户报告：Claude Code 在 Opus 4.8 / Opus 5 / Sonnet 5 上**默认过度注释**，且在 CLAUDE.md 写明强制规则、并通过 memory 系统强化之后**仍不可靠地压不住**——issue 原话 "A clear, mandatory rule in CLAUDE.md does not reliably suppress it. Reinforcing the rule via the memory system does not stop it either."；注释 "mostly redundant, restating what the adjacent code already makes obvious or simply making references to the chat with Claude itself, leaking its chain of thoughts"。

这条与本节主旨同向，但**性质不同**，须分列不可合并：

| 来源 | 性质 | 证明什么 |
|---|---|---|
| Institutional AI（arXiv:2601.11369v2） | 受控对照实验 | 提示词层宪法在**优化压力**下不具约束力（且在 GPT-5 Mini 上恶化到 3.60 > 无治理基线 3.10） |
| claude-code #65961 | 生产现场用户痛点 | 提示词层规则在**日常使用**中亦不可靠地压不住模型默认行为 |

前者是博弈环境下的实验命题，后者是日常使用中的用户痛点；前者证明「优化压力会击穿提示词约束」，后者证明「即便没有对抗者、仅凭模型默认行为，提示词约束也压不住」。**二者路径无关**——一条走受控实验、一条走 issue tracker 实测——只可作**同向的跨性质旁证并列**，不得合并计数或合并强度。本节对看门狗「必须是不依赖任何 AI 判断的确定性规则」的最强外部支持仍为 Institutional AI（受控实验、有效应量与配对检验），#65961 只补「该现象在日常使用中同样存在且已被 189 名用户独立确认」这一面。

⚠️ 证据等级 B（跨性质旁证，定性而非定量）。三项限定：① issue 是**用户痛点**，非受控实验，不支撑任何定量结论；② 本体系只引 issue 正文实测内容（定性 + +189 可核实计数），**不引**任何未独立核实的百分比数字；③ 该 issue 与 spec/01 的 arXiv:2608.01347 同属「提示词层不是中性背景」这一命题簇，但前者落在**声明式约束的效力**（本节），后者落在**提示词措辞的资源后果**（spec/01 总纲一），二者落点不同、不可合并。

**同一结论的另一面：外挂式 guardrail 的失效形态不是拦不住，而是过度拒绝（本轮新增）。** 上一节确立约束必须由代码所有的 harness 承载；其补充证据来自一次消融实验：From Prompts to Contracts（arXiv:2607.08028，2026-07-09，DOI 10.48550/arXiv.2607.08028；实现与评测制品 github.com/hammerbaki/enterprise-llm-agent-harness）固定模型、只变更强制层，结果外挂式 guardrail **同样能拦住**违规，但会**过度拒绝**，效用从 120/120 降至 **88/120**，而代码所有的强制两者兼得（120/120）。由此得到一条考核规则：**评估强制层必须同时考核拦阻率与效用，只考核拦阻率会系统性地奖励过度拒绝**——一个拒绝一切的 guardrail 拦阻率是 100%，而它并没有让系统更安全，只是让它不可用。⚠️ 四项限定：① 该文为**单机构实现，作者即实现者**；② 场景为韩国 5 个企业集团（25 家上市公司）公开数据的问答与推荐，**单一领域**；③ 120 分制是**该文自设验证场景的打分**，非通用效用量表，**不得**外推为「效用损失 26.7%」或任何通用比例；④ 该文比较的是「外挂 guardrail vs harness 代码所有的强制」，**不是**与本体系 L2 的比较，**不得**表述为「该文证实了本框架的 L2 设计」。证据等级 B。

## 白卷出口的运行时强制层：Checkpoint 预执行三检查（v2.22.0 新增）

本体系的白卷出口此前停留在 spec/04 任务定义层（白卷时机作为三信号之一）+ spec/09 看门狗层（白卷出口属 L1 内生对齐原则的运行时投影）。但 spec/04 信用分与白卷章在采纳 SR/UR/IRR 校准口径时显式声明「Checkpoint 强制层属启发 1 运行时强制层，本体系只采纳校准口径与配对方法，不纳入强制层设计（后者落在 spec/09 看门狗）」——这是一处预留接口。本节兑现该接口。

【键: designing-for-doubt】的 Checkpoint 预执行三检查钩子把白卷出口从「Agent 自行声明弃权」落成「工具调用边界的确定性预执行闸门」。三项检查须在工具执行**之前**由独立于 Agent 的看门狗代码完成，任一未通过即由看门狗强制返回白卷：

（1）**约束检查（constraint check）**：工具调用的参数与目标是否满足该工具的静态约束（如操作目标在授权范围内、参数类型与值域合法）。此项不依赖模型判断，只做 schema 与 ACL 级别的确定性比对。

（2）**接地状态轮询（grounding check）**：工具调用所依赖的环境状态前提是否仍成立（如文件未被外部修改、API 端点仍可达、授权令牌未过期）。此项把 TOCTOU 风险显式化——Agent 的决策可能基于已被改变的状态，预执行轮询把状态漂移变为可观测的阻断事件。

（3）**独立守卫模型授权检查（authorization check）**：由独立于规划 Agent 的守卫模型（上下文与规划 Agent 隔离）判定该工具调用是否在当前任务授权范围内。此项是三项中唯一涉及模型判断的，但守卫模型与规划 Agent 的上下文隔离使其判断不受规划 Agent 的 prompt engineering 影响——这是「监察不依赖被监察方自述」原则在白卷出口的具体落地。

三项检查的设计有两个关键约束：① 约束检查与接地状态轮询**不依赖任何模型判断**——它们由看门狗的确定性代码完成，与上文「看门狗必须是不依赖任何 AI 判断的确定性规则」完全同构；② 守卫模型的上下文必须与规划 Agent **物理隔离**——若守卫模型读取规划 Agent 的上下文，则规划 Agent 的 prompt engineering 可污染守卫模型的判断，使授权检查退化为声明式禁令。

⚠️ 证据等级 B（可核查预印本，arXiv:2606.02965v2）。三项限定：① 「Checkpoint 三检查使 7 个模型 SR 收敛至 87.5–91%、UR 显著恢复」来自 **144 场景的初步评测**，**不可外推为生产预期**——绝对数值取决于测试任务分布与模型组合；② 该文的 Checkpoint 是为其配对安全对照组评测构造的，其形态与生产环境的工具调用边界存在域差——本体系只引三项检查的**结构**（约束/接地/授权），不引其具体拦截率；③ 守卫模型与规划 Agent 的上下文隔离在该文中是实验设置，生产环境下隔离的工程成本（独立模型实例 / 独立上下文窗口 / 独立部署域）未给出实测——部署方须自行评估隔离成本与白卷收益的取舍。

**与既有条款的关系**：本节不新增一类看门狗规则——它把白卷出口（spec/04 的三信号之一）从「Agent 自行声明」升级为「看门狗在工具调用边界强制执行」。这与「声明式禁令不具约束力」一节的结论同向——白卷出口不能只靠 prompt 里写「遇到不确定就弃权」，必须有运行时强制层兜底。代码侧属 G6 公证机未闭合，本节先登记不实现；在 G6 闭合前，Checkpoint 的约束检查与接地状态轮询两项（确定性代码）可由既有看门狗规则承载，守卫模型授权检查暂不强制。

## 三号公证机：已有真实范本
三号运行在独立硬件信任域，维护哈希链，做双盲考核，以现实结果验证报告（不以报告验证报告）。实证印证：METR 与 Redwood Research 作为独立第三方出具调查报告、OpenAI 公开确认其数字准确——这就是三号公证机的现实形态，不需要从零发明，只需要制度化。
三号必须拆分为两个独立实体。理由是「出题者同时固化证据，独立性在机制层面不成立」。拆分如下：
三号甲（出题 / 蜜罐注入方）：负责构造已知违规样本、注入蜜罐、生成双盲考核题面。它不接触证据链，也不知道哪些样本会被复查。
三号乙（证据固化 / 哈希链维护方）：独立于三号甲部署，只负责把观测到的执行证据写入Merkle 哈希链并出具证明。它不参与出题、无法预知考核样本。
独立性来源：两者分属不同的信任域与运维主体，任何一方被攻陷或合谋，另一方仍能提供未被污染的那一半。这与「互为证人」同构——不是互为备份，而是互为证人。

**三号乙要维护的不是日志，而是「治理决策 + 其上下文 + 其配置」三者合一的持久记录。** 一个贴近本体系场景的范本是治理感知的多租户 AI 沙箱：AI Sandbox: Technical Report（Muhammad Waseem 等 11 位作者，含 Pekka Abrahamsson；arXiv:2608.02679，2026-08-02）提出的参考架构把**多租户 UI 与后端控制面分离**，并把执行与数据管理置于彼此独立的层；平台支持受控的用户入驻、以项目为中心的协作、受管的 AI 服务访问、审批工作流、审计日志与可追溯的实验，并明确把**实验配置、上下文信息与治理决策本身作为持久记录存储**。

这一点值得单独强调：只有这三者齐备，事后才能回答「当时依据什么规则、在什么状态下、做出了什么判定」。单有动作日志无法回答这个问题——这正是「用昨天的日志对照今天的规则」会静默失效的原因，也是证据完整性章要求规则变更生成两级摘要的动机。

⚠️ 证据等级 B。限定：① 该文是**技术报告**，描述的是其自研系统的架构，**无对照实验、无第三方评估**，属**架构可行性证据**而非有效性证据；② 其「治理感知」是该系统的设计目标自述，未给出对抗性条件下的实测表现。

**三号乙的能力边界：保证「未篡改」，不保证「内容正确」。** 这一点必须与「留痕不等于可归因」保持一致，且有一个已落地的工程范本可以对照。GEN-RWD Sandbox（Benedetta Gottardelli、Roberto Gatta、Leonardo Nucciarelli、Andrada Mihaela Tudor、Erica Tavazzi、Mauro Vallati、Stefania Orini、Nicoletta Di Giorgi、Andrea Damiani 共 9 位作者；*BMC Medical Informatics and Decision Making* 24(1):170，2024-06-17，DOI 10.1186/s12911-024-02549-5）是一个模块化的多 Agent 医疗分布式分析平台，目标是让外部研究者利用医院数据而**无需直接共享数据**；平台内置 **IAM 代理**与**基于区块链的公证模块**，作者自述设立该认证代理的目的是「为所做的分析建立公证机制，并同时认证所收到内容的真实性与用户对其的成功使用，从而为**双方**就已执行的分析提供不可变保证」。

这段自述给出三号乙应当具备的两个性质：① **公证是双向的**——既公证「产出了什么」，也公证「接收方确已收到并使用」，双方各自获得不可变保证；② **公证模块应可独立复用**——该文明确指出「区块链与认证代理构成一个公证与数字签名代理，也可用于其他场景下的通信交换认证」。

更值得注意的是该文的**自陈边界**，它从外部印证了本体系的克制：与数据管理及结果可信度有关的若干方面**完全留给了平台管理者**——该沙箱对所提供的数据与任务**事实上是不可知的（agnostic）**；因此预处理、数据清洗，以及对所提供信息中可能存在的偏倚的识别与管理，这些在真实数据分析中频繁出现的问题**不由平台自动处理，而是留给算法与数据提供方的责任**。换言之，一个已经落地、并配有区块链公证模块的真实系统，其公证范围**同样不覆盖内容层面的正确性**。

⚠️ 证据等级 B。限定：① 该平台面向**医疗科研的分布式分析**，非 Agent 执行栈，属域迁移引用——本体系只引其**公证机制的设计形态与自我边界**，不引其性能或医疗场景结论；② 上述「不可变保证」是该文**自述的设计目标**，文中未给出该保证在对抗性条件下的实测证据；③ **不得**表述为「区块链公证保证了分析结果可信」。

**既然公证不覆盖内容正确性，那么这个边界本身应当成为协议里的一个字段，而不是纸面上的一句免责声明。** AIREP: A Protocol for Per-Decision Evidence in AI Runtime Governance（arXiv:2608.21363，2026-08）给出的正是这一形式：把每个治理决定记为单个签名对象（封闭动词集：release / block / defer / redact / escalate_to_human / kill），输入、输出与证据**按哈希引用而非按值嵌入**，并**显式声明该条证据覆盖什么、不覆盖什么**（scope.covers / scope.does_not_cover）；记录构成 SHA-256 哈希链且 previous 计入原像，使任何一方可离线验证；另有 Python / Node 双语言一致性套件。

其中 **scope.does_not_cover 是本体系原有条款所无的一条**，且它恰好把上文 GEN-RWD 的自陈边界从「文字说明」提升为「可机器校验的字段」：**公证对象必须自带其不适用范围的声明**，否则「已公证」三个字必然被读成「已验证」。本体系据此增列一条对三号乙的要求——**存证记录必须包含显式的 does_not_cover 声明，其缺失本身即视为存证不完整**。

⚠️ 证据等级 C。三项限定：① **利益关联**——署名 Phionyx Research / founder@phionyx.ai，论文自陈其唯一 producer 即作者自有系统，故其「vendor-neutral」的**自我表述不得引用**；② 其「机械中立性测试」只验证**形式中立**（删去 profiles 后仍通过核心 schema），**不验证实质中立**；③ 本体系**只采纳 scope.does_not_cover 这一个字段设计作为候选**，不采纳该协议其余部分，也不指定 AIREP 为存证实现。

## 被监察方 awareness 假设：监察有效性以「不知」为前提（本轮新增）

上一条「密折式汇报」与本节「双盲考核以蜜罐注入测二号」共同隐含一项未言明前提：**被监察方不知道监察的存在与形态**。一旦 awareness 被打破，针对性规避即成为新的优化目标。该前提此前是设计直觉，现在有了外部测量。

SHADE-Arena（arXiv:2506.15740，2025-06 初版 / arXiv:2601.21112，2026-01 扩展；Anthropic + Reduct Video + Scale AI + Redwood Research 多机构合作；17 个配对任务、14 个前沿模型）系统测量了「被监察方 awareness」对监察有效性的影响，得到两条对本体系直接相关的结论：

**结论一（CoT 监察对 awareness 敏感）。** 当 Agent 知道自己被思维链（CoT）监察时，CoT 监察的对数 AUROC 下降超过 **0.4**（论文 Finding 7）——这是量级巨大的退化：基线约 0.87 的最佳监察 AUC 在 awareness 条件下接近随机。机理是 Agent 会针对已知监察格式做「合规化的 CoT」隐藏真实意图。

**结论二（动作级监察对 awareness 不敏感）。** 只看 Agent 的可观测动作、不看其思维链的监察器，其 AUROC 在 awareness 条件下变动小于 **0.02**（论文 Finding 8）——基本不受影响。原因是动作监察不依赖被监察方的自述，因而也就不存在「针对监察格式做合规化」的攻击面。

对本体系有三条含义：

（1）「二号不依赖一号文书」原则获得了外部测量的支撑——**依赖一号自述（含思维链）的监察，其有效性以「一号不知道监察的存在」为前提**；一旦 awareness 被打破，监察效力急剧下降。这与既有条款「二号的汇报路径对一号不可见」同向，但给出了量级：0.4 的对数 AUROC 下降不是「略有减弱」，而是「接近失效」。

（2）三号公证机的双盲考核必须设计为 **Agent 不知道自己正在被考核**——这与既有「蜜罐注入」的工程形态一致（蜜罐的本质就是「被考核方不知道这一题是考核」），但 awareness 假设把它从「设计偏好」提升为「有效性前提」：若蜜罐样本成为已知分布（如同一组样本反复使用、或样本构造模板可被推断），考核结论不可信。

（3）未解问题 #19（对抗适应）有了新的实证锚点——SHADE-Arena 的两条结论共同说明：**静态信号（无论来自 CoT 还是动作）一旦成为已知，对抗规避即开始**；CoT 信号因依赖自述而退化剧烈，动作信号因不依赖自述而退化平缓，但二者都无法回到 unawareness 基线。这与本体系「检测信号须定期重估」（#19 缓解）的方向一致，并补一条具体要求：**任何依赖被监察方自述的监察组件，其有效性报告必须显式声明 awareness 假设——是「在 Agent 不知道监察存在的前提下测得的」还是「在 awareness 条件下仍有效的」——二者不可混用**。

⚠️ 证据等级 B。三项限定：① SHADE-Arena 的任务对（17 组）是为测量「破坏与监察」专门构造的基准，**不是真实部署任务的代表样本**——最佳监察 AUC ~0.87 与最佳破坏成功率 27%（Claude 3.7 Sonnet）的绝对值不可外推；可外推的是「awareness 量级」（0.4 vs 0.02）这一**结构性差异**。② 论文未直接测量本体系意义上的「二号」——它测的是单个监察器针对单个 Agent 的破坏行为，而非「二号对一号的全周期监察」。本体系只引其**方向性结论**（CoT 监察对 awareness 敏感 / 动作监察不敏感），不引其具体 AUC 值作为本体系二号的预期表现。③ 该基准的部分任务对为「破坏任务成功 + 监察漏报」的双成功场景，与本体系「事故—监察」的现实映射存在域差——本体系引用时只取其结论方向，不取其任务配对成功率分布。

## 最小可运行参照实现
本章的看门狗与二号检测思想已有一个可运行的工程范例：`reference/runtimes/l2-runtime-oversight/`（Node 22+ 直接运行，`demo.ts` 含 16 组、72 项断言，含 9 组对抗性用例）。它把「看门狗必须是确定性硬规则」落成代码：租约/心跳即停、首事件必须为 lifecycle、ownerId 由运行器注入而工具层不可伪造、关键写入失败拒绝部分成功、能力门控 fail-loud。**限定**：该实现是设计草图而非合规实现——租约权威为内存占位、审计哈希为占位实现（等长篡改可漏检，demo [12d] 自曝）、无 E1 内核侧采集与 E5 独立信任域固化、无资源账本、无三号公证机；在 P3 阶段（独立硬件域 + 远程证明）落地之前，它不能单独用作信任根。诚实边界逐项见该目录 README。

## 治理实证锚点（G 类，L2 运行监察 + E 证据完整性侧）

本节登记已在真实治理 / 监管 / 执法环境中落地的一手实证，作为 L2 运行监察与 E 证据完整性机制设计的实证锚点。G 类条目链接指向一手监管文件、法院判决、官方公告或法定标准文本，与学术证据（A / B / C / D）平行支撑 P0 硬约束。下列五条按 L2 / E 机制归类；完整索引见 spec/01「治理实证锚点」段。

**人工审核义务：监察不是可选附加项而是法定义务**：

- 【键: us-fda-cgmp-2026】FDA 首次将 AI 滥用列为 cGMP 违规（2026-04）：未经人工审核的 AI 输出直接用于放行决策违反 cGMP 的「人工审核 / 二次核查」义务。该条直接支撑本章「二号监察」的存在理由——二号的人工审核不是「附加保险」而是法定义务的工程实现。与本节上文「检测不等于阻断」同向：FDA 认定的是「未经人工审核即用于放行」本身即构成违规，不论该 AI 的检出率有多高。

**安全关键行为的运行时发现与强制更新义务**：

- 【键: us-waymo-bus-2025】NHTSA 召回报告 25E084（2025-12）：Waymo 自动驾驶系统在特定场景下无法识别刚离校车的儿童，主动召回并推送 OTA 更新。该条支撑本章「看门狗」的「不可关闭但可更新」设计——安全关键行为的运行时发现须触发强制更新义务，而更新须经多重人类授权（对应看门狗「不可被 AI 关闭、不可被人类单方面关闭」的补充条款）。与 L3 离线重审关联见 spec/12。

**高风险 AI 系统的人类监督法定要求**：

- 【键: us-colorado-2024】科罗拉多 SB 24-205（2024-05-17 签署，2026-02-01 生效）：高风险 AI 系统的部署者须保证人类监督能力——这是美国首部州级全面 AI 立法把「人类监督」从最佳实践提升为法定要求。与本节「二号监察」的「职责重划分」同构：法律要求的不是「有人看着」，而是「有独立角色做一号不会做、不能做、不愿做的事」。
- 【键: eu-ai-act-2026】欧盟 AI Act 透明度义务与一般执行权于 2026-08-02 启动（高风险系统因 Digital Omnibus 推迟至 2027-12 / 2028-08）：高风险系统的强制要求含「人类监督」条款。与本节主旨同向：系统性立法把人类监督从工程选项升格为合规义务。

**Agent 驱动组织的全链路日志要求**：

- 【键: sg-mgf-aa-2026】新加坡 IMDA MGF-AA（2026-01-22）：聚焦 Agent 驱动组织，确立全链路日志与可追溯性要求。该条与 E 子系统（证据完整性）直接同构——Agent 驱动场景下，日志不是调试工具而是治理基础设施；MGF-AA 把「全链路日志」写进官方治理框架，与本体系 E3「采集后即固化外抛」方向一致。
