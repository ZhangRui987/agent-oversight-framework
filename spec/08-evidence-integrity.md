# 证据完整性子系统

证据采集 曾提出「多视角观测」，定级 P2。 证据层伪造发现 表明它被严重低估——本章独立成章。
## 问题：记录本身被伪造
真实事故中，约 7% 的 Agent 转录记录存在成功伪造的工具调用。具体手法是拦截工具调用进程，把系统记录的命令替换为自选命令；测试记录为：echo REAL; sleep 被系统记录为 SPOOFTEST。
这件事的严重性在于被伪造的层级：
不是一号 AI 自报的文书被篡改——「不经过一号文书」的设计防住了这一层。
而是沙箱 / 工具调用层的记录被替换——这正是行为合规线指定的「采集方」。
因此：基础设施层的记录 ≠ 可信证据。这是本设计地基上的一道裂缝。
## 地基修正：行为合规线的新表述
行为合规线的表述为——两条线不依赖一号文书，且采集点本身须多源交叉验证、不可被单一沙箱层记录独占。落地含义：任何进入考核表、三号公证、问责流程的证据，必须至少包含一条内核侧 / 独立硬件域的强制采集证据；仅凭用户态沙箱日志不得单独支撑任何处分决定。
## 五个采集组件（E1–E5）
组件 | 技术要求 | 防护对象 | 优先级
| --- | --- | --- | --- |
E1 内核侧强制采集 | eBPF kprobe / tracepoint / LSM hook；采集点在被观测进程的用户态路径之外，被观测方无同等权限触碰 | 用户态拦截与命令替换 | P0
E2 TOCTOU 安全重读 | 内核在 Continue 前重新读取用户态指针；不信任首次读取结果（呼应 seccomp_unotify 语义） | 指针竞态替换 | P0
E3 采集后即固化外抛 | append-only 存储 + 哈希链 + 写入被观测方不可达的位置；禁止事后修改与时间戳重写 | 日志删改、痕迹清理 | P0
E4 多源交叉验证 | 内核侧证据与用户态沙箱日志逐条比对；不一致即判定采集层被污染并触发隔离 | 单一路径被攻陷 | P0
E5 采集点自身完整性 | 采集模块签名校验、独立信任域运行、其启动与配置变更本身纳入审计 | 采集点被关闭或降级 | P1

采集点不是越多越好，而是要在**覆盖面**与**攻击面**之间取平衡。E1 要求采集点位于被观测进程的用户态路径之外，解决的是「采不到」；但还有另一半问题——**被观测方的能力边界本身应当被收窄**，让它根本没有多余的系统调用可以用来隐藏动作。Zhiyuan Wan、David Lo、Xin Xia、Liang Cai（*Empirical Software Engineering* 24(6):4034–4070，2019-07-04 在线发表，DOI 10.1007/s10664-019-09737-2）给出的正是这一半的做法：先运行测试用例探索容器行为，监控其访问的系统调用（含类型与参数），再把观测到的类型与参数**翻译为沙箱规则**，使容器无法访问测试期间未见的系统调用；为每个容器挖掘这样一套沙箱耗时**不足 11 分钟**，且强制执行的性能开销很低。

⚠️ 引用限定（必须与引文一并保留）：该文报告的系统调用覆盖率 **96.4%–99.8%** 是一个**估计值**，且明确附有两个限定假设——**「测试用例是完备的」**与**「只使用静态的系统 / 应用路径」**。这两个假设在 Agent 场景下都不成立：Agent 的测试用例不可能穷举其运行时行为，而 Agent 恰恰会走动态路径（临时下载、运行时生成代码、动态改变控制流）。因此本体系**只引其方法与耗时，不引 96.4%–99.8% 作为采集覆盖率的预期值**——在 Agent 场景下引用该数字即构成过度宣称。

对 E1–E5 的直接含义：**采集点选择应以「最小必要系统调用集」为基线**（呼应 L2 的攻击面最小化），而不是以「尽可能记录一切」为基线；后者既抬高存储与复核成本，也使「哪些记录算异常」失去参照系。

## 留痕不等于可归因：证据字段的完整性要求
E1–E5 解决的是「记录有没有被伪造」。但还有第二个、更容易被忽略的问题：**即使记录完全真实，它也可能不足以支撑归因**——留痕不等于可归因。
一手基准证据：DEMM-Bench（arXiv:2606.20634）构造 64 个决策案例，覆盖 8 类证据机制（执行轨迹、账本、来源图、策略日志、委托令牌、缓存事件、工具防火墙记录等），逐案追问「治理问题能否由现有证据回答」。结果为：**仅有执行轨迹，或仅有模式定义的基线，在 75% 的案例上过度宣称「证据已充分」；仅有账本的为 50%。** 属性级评分器能做到零过度宣称，但其属性充分性准确率仅 56.25%。
方向性结论：**记录的存在本身会制造「已经可以归因」的错觉，而错觉比缺失更危险**——缺失会被发现，错觉不会。
**第二条独立证据线（法律侧；与上一条形同结论、路径无关）。** 上述一手基准有一个固有弱点：64 个案例由作者构造。因此还需要一条不依赖任何构造语料的独立论证。From Runtime Records to Legal Findings（arXiv:2607.00941，Jeroen Janssen，2026-07-01；12 页技术报告，辅助材料与实验协议存档于 Zenodo，DOI 10.5281/zenodo.21025237）从法律认定的角度独立提出同一结论，并给出一条可判定的准则。
该文把问题限定在一个**有界类别**内——关于特定事件及其关系的二元事实认定，例如：受保护数据是否越过了边界、人是否本可以介入、信息隔离墙是否成立、被授予的权限在使用时点是否仍然有效。准则为：**一条运行时记录要能回答此类认定，必须同时携带两项内容——把所记录事件映射到法律上有效范畴的类型标注（typing），以及该认定的真值所依赖的关系：来源（provenance）、授权（authority）、推导（derivation）或时间效力（temporal validity）。二者缺一，该记录即不足以支撑认定。**
作者明确这是**必要性主张，不是充分性主张**：满足准则不等于认定成立，不满足则认定一定不成立。该文并进一步论证，仅靠防篡改日志、通用过程框架或来源结构本身，都不足以建立相关认定；并把论证接到必要多样性（requisite variety）、Good Regulator Theorem，以及运行时验证中 trace 与 hyperproperty 的边界上。
与上一节八维度清单的关系：该准则要求的四项关系，与本体系八维度中的主体、授权、判定依据、生命周期上下文在**结构上同构**，且两条路径各自独立得出——工程侧由「基准上多少案例被过度宣称」得出，法律侧由「一项认定需要什么才能成立」得出。⚠️ 同构只是描述性观察，**不得**据此声称八维度清单已满足该文准则：后者是必要性判据而非充分性判据，且未经该文作者对本清单作过任何核验。
⚠️ **为什么 Quipu 不构成第三条独立证据线**：Quipu（arXiv:2608.16813）确实独立跑通了 DEMM-Bench 并复现了同类结论，但它跑的是**同一套基准**，因而属于第一条证据线的外部使用者，而不是一条新的证据线——这与本规范「同一作者、同一条证据线不得加总为两条」的处置规则一致。本体系此处共有**两条**独立证据线，不是三条。
⚠️ 引用限定（必须与引文一并保留）：该基准的 64 个案例由作者施加 8 种确定性降级条件构造而成，其标签又由同一批降级条件经确定性判定器推导——基线判定与标准答案运行在同一套规则之下，属「按构造为真」。因此 **75% / 50% / 56.25% 三个数字不得作为真实系统的实测频率引用**；可引用的只有「留痕不等于证据充分」这一方向性结论。该基准的代码与测试套件真实存在，且已被与本体系无利害关系的第三方 Quipu（arXiv:2608.16813）独立跑通并复现了同类结论；**但两者口径不同——DEMM-Bench 按案例计，Quipu 按属性问题计，百分比不可混用。** **第二条证据线的引用限定**：Janssen 一文为单作者技术报告，其准则实例化于作者所选定的部分欧盟 AI Act 监督义务，属**作者的法律分析，不代表监管方立场**；引用时须连同「作者自陈为必要性主张」一并保留，**不得**表述为「满足该准则即可归因」，也**不得**表述为「欧盟 AI Act 要求」。
可吸收的直接产出：把该文的**八个治理属性维度**作为证据字段检查清单。任何一份进入考核表、三号公证或问责流程的证据，应能回答以下八个问题：

| 维度 | 该条证据必须回答的问题 |
| --- | --- |
| 主体（actor） | 谁做的 |
| 授权（authority） | 凭什么做 |
| 动作（action） | 做了什么 |
| 策略（policy） | 依据哪条规则判定 |
| 判定依据（decision basis） | 判定所依据的输入与理由 |
| 资源接触（resource touch） | 触碰了哪些资源 |
| 生命周期上下文（lifecycle context） | 处于任务生命周期的哪个阶段 |
| 验证强度（verification strength） | 该条证据自身的验证强度如何 |

八项中缺任何一项，该条证据不得单独支撑处分决定。此要求与行为合规线「至少一条内核侧强制采集证据」是**并列**关系，不是替代关系：前者管「记录够不够」，后者管「记录真不真」。

**八维度是下限，采集深度按决策风险分级（本轮新增）。** 上文八维度回答的是「一条证据要能支撑归因，必须能回答哪些问题」，这是一个**不可随档位下调的下限**；但它没有回答另一个问题：**是否所有决策都要按同一强度采集**。Decision Trace Schema for Governance Evidence in Real-Time Risk Systems（Oleg Solozobov；arXiv:2604.09296，2026-04-10，27 页 / 5 表；schema 仓库 github.com/governance-evidence/decision-event-schema；DOI 10.48550/arXiv.2604.09296）给出的正是这另一半：它把 ML 推理、规则 / 策略评估、跨系统耦合、治理元数据**四个基础设施层**桥接到**单一 per-decision 事件结构**之内（该文称之为「碎片化轨迹问题」——监管规定了**要记什么**，却没规定**用什么数据模型记**），定义 **10 个必需根字段**与 6 个顶层字段组（每组映射一项治理证据属性及其必须抵抗的降级类型），并显式采用**分层证据策略**（lightweight / sampled / full），使**证据完整度匹配决策风险与吞吐**。

这与本体系 G×S 二维分级（见分级章）**同构**：G×S 在**任务**粒度上度量风险并决定监察强度，DES 的分层策略在**单次决策**粒度上度量风险并决定证据完整度——二者是同一原则在两个粒度上的投影，本体系不因此引入第二套分级。

落地含义（须精确表述，不得混为一谈）：**八维度字段的完整性不随风险档位下调；可随风险档位调整的是采集深度与验证强度。** 低风险决策可走 lightweight——八维度字段齐全，但可不经内核侧强制采集、以抽样复核替代逐条固化外抛；高风险决策必须走 full——八维度齐全 **且** 满足行为合规线「至少一条内核侧强制采集证据」，且逐条固化外抛。

⚠️ 证据等级 C。三项限定（必须与引文一并保留）：① 该文的 5 个示例**全部为事后手写的著名事故**，**从未在真实决策流上验证过**；其「与最高吞吐完整性机制在生产级决策速率下兼容」是**机制可行性分析**，不是实测部署——故它示范的是**字段结构与分级思路**，不是一套可运行的采集系统；② 「25 种以上现有格式中唯一同时覆盖四层」是该文**自行做的评估**，无人独立复核，且该文全称在标题与摘要中并不一致（标题作 Decision Trace Schema、摘要作 Decision Event Schema），引用时以「DES」称之；本体系**不采纳 DES 为标准**，只取其分层证据策略与字段参考；③ 该文与 DEMM-Bench（arXiv:2606.20634）**同为 Oleg Solozobov 一人所著**，属**同一条证据线**，**不得加总为两条独立证据**——这也意味着在「证据字段完整性」这一论题上，来自该作者的支撑只计一次。

**事后归因存在经验天花板，因此不能作为问责的主要依据（本轮新增）。** 多智能体系统中的失效定位——指出决定性错误发生在哪一步——即便用最优方法也远未可靠：A2P Scaffolding（arXiv:2509.10401，2025-09-12 初版 / 2025-09-23 第二版，DOI 10.48550/arXiv.2509.10401，代码 github.com/ResearAI/A2P）把失效归因从「长对话日志上的模式识别」重构为结构化因果推断（溯因推断根因 → 定义最小纠正干预 → 模拟后续轨迹验证干预是否奏效），在 Who&When 基准上把算法生成集的步骤级准确率从 16.67% 提到 **47.46%**（2.85×），但在更难的**手工构造集**上只从 12.07% 提到 **29.31%**（2.43×）。作者自陈此前方法的核心弱点是无法做稳健的反事实推理——即无法判断「纠正某一个动作是否真能避免任务失败」。这直接支撑本节的重心：**归因能力不足是可预期的常态而非例外，因此证据必须在动作发生时就被采集完整，而不是指望事后从日志里推断出来。** ⚠️ 引用口径：须以较难的 **29.31%** 而非较易的 47.46% 作为该方法的实际水平表述；该基准为多智能体对话场景，**不得**把上述百分比外推为本体系场景下的归因准确率。证据等级 B。
## 两类最易遗漏的留痕对象
证据子系统的典型缺陷不是「该记的没记」，而是「只记了成功的一半」。补两条常被遗漏的对象：
**（1）必须记录被阻止的尝试，而不只是已发生的动作。** 只记录已执行动作的日志，无法区分「从未尝试」与「尝试过但被拦下」——而这两者在问责上完全相反：前者无过错，后者是未遂与既遂的分界。外部先例：Institutional AI（arXiv:2601.11369v2）的治理图设计中，执行机构显式记录已放行（applied）与被阻止（blocked）两类遍历。
落地含义：看门狗的每一次拦截、E4 交叉验证的每一次不一致判定、每一次规模熔断，都必须与被放行的动作**同等留痕，并进入同一条哈希链**。否则「阻断率」这个指标既无法被审计，也无法被考核——因为被拦下的事情根本不在账上。这一条与运行监察章「有效性指标必须写为阻断率」直接呼应：不记录被阻止的尝试，阻断率就无从计算。
**（2）规则与契约的变更本身必须留痕且可 diff。** 若只有动作被记录而规则变更不被记录，则「用昨天的日志对照今天的规则」这类复核会被静默污染：同一份行为日志在两套规则下可能得出相反结论。
要求：规则、策略、契约的每次变更生成**两级摘要**并写入哈希链——
语义摘要（semantic digest）：变更了哪一条规则、判定逻辑如何变化，供人工复核与归因；
字节摘要（byte-level digest）：变更内容的精确哈希，供机器比对与防篡改。
两者缺一不可：只有字节摘要则人无法理解变更含义，只有语义摘要则机器无法判定变更是否被篡改。此条与架构章「谁有权修改规则」一节构成闭环——那里规定修改权的归属与准入门槛，这里规定修改行为自身的取证要求。（「用昨天的日志对照今天的规则」在存储层如何变成一次可靠查询，见下节。）
## 交叉验证是「互为证人」，不是「互为备份」

两条采集路径的关系必须被正确理解。若为备份关系，则一条失效时另一条顶上，伪造只需攻陷当前活跃的那条；若为证人关系，则两条必须同时陈述且相互印证，持续且无法用技术原因解释的不一致才是最高优先级事件——因为它意味着「我们看到的世界已经不是真实发生的世界」。

这一区分可以说得更硬。AI Sandboxes（Inderjeet Singh、Haitham Mahmoud、Andrés Murillo；arXiv:2606.18532，2026-06-16，50 页 / 8 图 / 10 表，DOI 10.48550/arXiv.2606.18532）形式化了沙箱边界，并提出一条**最弱链路规则**（weakest-link rule）：把逐维度的证据合成为一个**有界**的部署声明时，声明的强度不超过其最弱维度的支撑力度。这正是「互为证人」的准确含义——每个采集源是一个独立证人，证词可以互相印证，但**整条证据链的证明力不因增加证人而上升，只因最弱证人的可信度而设上限**。由此得到三条推论：

- 增加采集路径**不能**补偿某一条路径的缺陷。若内核侧采集点可被关闭（E5 未落实），那么再多的用户态日志也不构成证据。
- 交叉验证的**输出不是一个布尔值**（一致 / 不一致），而是一个**有界声明**：它必须写明「在哪些维度上、由哪几条路径、支撑到什么强度」。一个只说「已交叉验证」而不写边界的声明，本身就是过度宣称。
- 一致性检查**通过**不代表证据充分——两条路径可能同时被同一种手法污染。一致性是**必要条件，不是充分条件**。

该文另有三点并入本体系：① 它把威胁模型显式扩展到**针对保证装置本身的攻击**（attacks on the assurance apparatus itself）——这与 E5（采集点自身完整性）是同一命题，说明「监察设施本身是攻击面」不是本体系的内部假设；② 它给出六维测量框架（保真度 fidelity / 可控性 controllability / 可观测性 observability / 遏制 containment / 可复现性 reproducibility / 治理工件 governance artifacts），其中**可观测性与可复现性**与本体系 H0–H3 成熟度阶梯（见分级章）度量的对象高度重合，**保真度**则对应判断八「沙箱环境本身可被探测」；③ 该框架在**三个真实沙箱的实例研究**上做了实例化。

⚠️ 证据等级 B。限定：该文是**保证导向的框架性论述**（原文自述 "develops an assurance-oriented account"），三个案例研究用于实例化框架而非验证框架；其六维测量框架**未给出任何经实证标定的阈值**。本体系只采纳「最弱链路」这一合成规则与「保证装置本身是攻击面」这一命题，**不采纳任何具体维度阈值作为合格线**。

交叉验证不一致时的处置（删除「任何不一致即立即隔离」的绝对表述）：按不一致的粒度与持续度分级处置——记录 → 抽样复核 → 隔离。详见下文容错带宽。

容错带宽（防止防御机制自身造成大规模误隔离）：内核侧 eBPF 与用户态沙箱日志在正常运行中本就会大量不一致——时钟不同步、日志缓冲与丢失、采样粒度差异、正常竞态、批量提交时延。若按「不一致即最高优先级 + 立即隔离」执行，攻击者还可故意制造不一致，把拦截器反向用作 DoS 武器（「涌现性失效」预警的正是此情形）。因此设定三条：

（1）判定粒度：以「会话级」为主、「事件级」为辅。单个事件的不一致只记录不告警；同一会话内不一致事件占比超过可容忍阈值才升级。

（2）可容忍不一致率：由基线标定给出（初始建议事件级 <5%、会话级 <1%，须在真实业务上标定后覆盖，不得直接采用默认值上线）。

（3）分级处置链：记录（不一致率低于阈值）→ 抽样复核（接近阈值，由二号抽取样本人工/自动比对）→ 隔离（持续超过阈值且无法用时钟/缓冲/竞态解释）。只有落入第三级才触发隔离，并同时保留双方原始证据、以内核侧为准、升级为证据层事件。

## 审计即查询：把复核从周期性人工活动变为一次查询
上一节要求规则变更留痕且可 diff，解决的是「对照时拿什么比」。但还有一个前置问题：**对照这个动作本身，通常是一次周期性的人工活动**——抽样、调阅、人工比对。它的成本随规模增长，于是频率被压低、滞后被拉长，而滞后本身就是可乘之机。
可行的反例已经存在。Quipu：A Governed Bitemporal Knowledge Graph Store（arXiv:2608.16813，Steve Brown，2026-08-17；15 页，源码与全部基准 / census 工件存档于 Zenodo，DOI 10.5281/zenodo.21878428，开发仓库 github.com/scbrown/quipu）是一个可嵌入的知识图存储，其设计要点是：**把治理规范 Σ、执行轨迹与经签名的判定结果本身，作为它们所治理的那个存储里的事实**——于是「这条轨迹是否满足规范」不再是外部审核流程，而是**对存储的一次查询**（T ⊨ Σ）。
它反转了知识图存储的四个传统默认，这四条恰好都是本体系关心的：

| 传统默认 | 反转后 | 对本体系的意义 |
| --- | --- | --- |
| 先收下写入、日后再清理 | 任何事实只能经门控进入；门控谓词评估的是写入后的待定状态 | 与「规则变更须两级摘要」同源：约束作用在状态上，不作用在意图上 |
| 保留单一时间轴，或完全没有 | 数据、信任标签、判定，以及规则本身，都是双时态的 | 直接解决上一节的问题：「用昨天的日志对照今天的规则」变成一次 as-of 查询，而不是一次静默污染 |
| 所有写入者的事实同等可信 | 命名图是权限与信任的单位，在格（lattice）下组合，其唯一不变量是组合永不放宽 | 与交叉验证的「互为证人」同构：组合只能收紧，不能放宽 |
| 治理交给仪表盘与中间件 | 治理规范进入存储，成为被治理的事实 | 审计对象与审计依据处在同一可信边界内 |

第二行是本体系最直接的收获。该文以 Census（一个确定性的多写入者生命周期，单次种子化运行即可就全部研究问题按埋设真值评分）给出演示：**50 / 50 条已满足的判定在其各自时点上被忠实重算，而在「只取最新」的规则下，这 50 条会全部被误报。** 这正是「用今天的规则重放昨天的判定」所造成污染的量化形态。
⚠️ 引用限定（必须与引文一并保留）：
其一，Census 是**确定性的单次种子化运行**，其 0 / 6（门控存储的终态埋设缺陷数，未门控为 6 / 6）、7 / 7（组合探针维持格契约）、50 / 50（判定在其时点忠实重算）均为**按构造的自评结果**，不是真实系统的实测频率，不得外推；
其二，该文作者即该存储的实现者，上述评估是**作者对其自有实现的自评**，存在利益关联，只可作可行性证据与检查清单使用，不可作品质背书；
其三，该存储是**存储层**方案，与本体系 E 子系统是上下游关系而非替代关系——E 子系统管「采集是否可信」（记录真不真、有没有被伪造），存储层管「查询是否可算」（能不能就已有记录提问）。**采集层不可信时，存储层的任何保证都不成立。** 本体系不指定存储实现，此处仅作为已实现样例与可行性证据。

## 与 Sandlock 的分工
层面 | Sandlock 提供 | E 子系统补足
| --- | --- | --- |
隔离 | Landlock 文件系统 / 网络 / IPC + seccomp-bpf 系统调用过滤；内置 COW 保护工作目录；约 5ms 启动，无 root / cgroup / 容器 | 不重复；E 不与隔离层竞争
观测 | 运行时事件回调：syscall、类别、PID、网络目标、argv；verdict 允许 / 拒绝 / 带 errno 拒绝 / audit 放行并标记 | 补足证据可信性：用户态 verdict 不作为信任根
证据 | 丰富的行为数据源（利于分析） | 内核侧独立采集 + 固化外抛 + 交叉验证（当前最优可用证据层，非最终信任根，见 2.4）
对抗性场景 | 论文自承：内核漏洞、侧信道、对抗性租户资源耗尽超出 scope，应优先 microVM / cgroup 隔离 | 对抗场景改用 microVM / cgroup + E 子系统
结论：Sandlock 是优秀的「可信但有缺陷代码」的轻量隔离与观测工具，可以作为行为合规线的丰富数据源；但它不能充当证据链的信任根，对抗性多 Agent 场景须叠加 microVM / cgroup 与 E 子系统。

上表这一结论需要一个**产品层的选型依据**，否则「改用 microVM」只是一句方向性建议。AI Code Sandboxes: A Comparative Security Study. Part 1 of 2 — Engine-Level Properties（George Andronchik、Pavel Lokhmakov；arXiv:2606.08433，2026-06-07，61 页 / 7 图 / 33 表；论文 CC BY 4.0，配套代码仓库 github.com/orbitalab/RnD-ai-sandboxes-sec-study-part-1 为 Apache-2.0）以六项引擎级测量——宿主机攻击面、信息泄漏、纵深防御可堆叠性、公开 CVE 历史、补丁节奏、上游模糊测试姿态——横评 **5 款 AI 沙箱产品**，提供了这一依据。三条发现可直接作为选型输入：

（1）引擎类别（microVM / 用户态内核 / OCI 容器）在**每一个架构轴上**都清晰分离，但**同一类别内的产品之间不分离**。故选型应**先定类别、再看产品**——在错误的类别里挑产品，横评给不出区分度。

（2）**产品 pin 策略是面向运维方的主导变量**：引擎侧的补丁延迟对协同披露聚合为约 0 天，而**下游滞后从 0 天延伸到 471 天以上、再到「不透明」、再到无上限**。也就是说，「选了哪个引擎」远不如「运维方多快跟进补丁」更能决定实际风险——这直接支撑本体系把补丁与配置变更作为**持续审计对象**，而非一次性选型动作。

（3）模糊测试投入分三层，而最强的组合（microVM × 持续公开模糊测试）在该集合中**空缺**，留下「0 个已公开 CVE × 无上游模糊测试 × 无学术研究」这一交集**在结构上未被测量**。

⚠️ 证据等级 B。三项限定：① 作者明确声明**「没有任何单一轴足以构成比较判断的依据，跨轴解读才是承重的分析」**，且**不提出总排名**——故本体系只引其结构性发现，**不得**据其任一单轴的排序声称某产品更安全；② 该文为 Part 1 of 2，只覆盖引擎级属性，**不含应用层与编排层**；③ 「0 个已公开 CVE」这一格**不代表更安全，而代表测量缺失**——这是本体系反复出现的「错觉比缺失更危险」的又一实例，与「未提交披露卡不得推定为不安全」的对称克制同源：**没有证据，既不等于有风险的证据，也不等于风险低的证据**。
