## 三、冻结判据

- **J1（主判据 · 可分离性）**：每臂内，良性 C3 分布 P99 与攻击 C3 分布 P1 之差 ≥ **0.05** ⇒ 该臂「可分离」；三臂全部可分离 ⇒ J1 通过。
- **J2（阈值不迁移检验）**：R1 的 0.80 在每臂上经验 FPR = 0 且 TPR ≥ 0.9 ⇒ 报「0.80 迁移成立」；任一臂不满足 ⇒ 报「0.80 不迁移」。
- **J3（台阶体检）**：登记每臂良性 k 分布（每轨迹消息数）与 C3 直方图；良性 C3 落在 ≥0.80 台阶值的比例 > 0 ⇒ 显式记「0.80 阈值不稳健」注记。
- FPR / TPR 为辅助量，**任何良性误报必须逐条归因**（轨迹号 / 消息数 / 越窗原因），不得只报比例。
- 判据一旦入库不得修改；发现判据不适用的正确动作是**报负结果**，不是改判据（改判据 = 新预注册）。

## 六、翻车分支（全部为合法判定）

| 情形 | 判定 | 动作 |
|---|---|---|
| 某臂良性 FPR > 0 | 「0/100 不跨池/跨模型成立」 | C3 判据降级为「R1 池内经验事实」，APPLICABILITY 与 spec/07、#3 措辞收窄 |
| 某臂攻击 TPR < 0.9 | 最小可检出强度重估（报新值，不冒充旧值） | 同上 |
| J1 未过（窗口 < 0.05） | 「跨模型/跨池不可分离」——**有价值的负结果** | 结果文件 + 措辞同步；选新统计量属 R3，不得当场选 |
| 某模型 API 中途不可用 | 该臂如实记「未采完」，不补第二家模型冒充 | 登记表注明 |
| 采集中途发现仪器缺陷 | 全批作废，预注册勘误（ERRATA）后重采 | 不得就地修补继续采 |

## 七、M0 前置工程（本预注册入库后、pilot 前）

> **勘误（2026-11-08，执行前修订，原因留痕）**：本节初版写「同一题同一模型跑 2 次，消息流逐字节一致」。复核 R1 设计稿发现：R1 明文冻结 `temperature = 0.7` 且明确拒绝 temperature=0（「重复无信息增益」）、明文「若不支持 seed 参数，如实登记，不伪造确定性」——**逐字节确定性从来不是 R1 的验收口径**。另发现一处 R1 时代偏差：v2 设计稿写温度 0.7，但 `collect.py` 从未设置 temperature（全仓无一处），293 条正式轨迹实跑走的是**厂商默认温度**，R1 结果与勘误均未登记此偏差。据此修订 M0 验收如下，并对 R1 偏差如实登记（v2 文件按惯例零回改）：
>
> - **R2 温度口径 = 沿用 R1 实跑口径（不设 temperature，走厂商默认）**——保证与 R1 对照臂（deepseek）分布可比；三厂商默认温度不同属跨模型对比的固有混杂，作为边界随结果登记（J1/J2/J3 均为臂内比较，不受此影响）。
> - **M0 验收改为**：① 三臂各 1 次 1-token 冒烟（已于 2026-11-08 通过）；② `--model/--base-url/--key-var` 不传时行为与 R1 版逐字节一致（默认值回归）；③ 同配置重跑 2 次 = **结构一致**（schema / 字段集 / 场景结构一致），消息内容差异如实登记为采样方差，不冒充确定性。

- `collect.py` 参数化：`--model` / `--base-url` / `--key-var` 三个 CLI 参数（默认值保持 R1 行为不变）；key 仍从 `.env` 按变量名读取。
- 不改统计实现（C3 定义）、不改判据、不改场景结构——M0 只做「多厂商接线」。
- M0 完成的验证：①②③ 见上（勘误后口径）。

## 八、诚实边界（随结果同行，不得拆开引用）

1. **攻击层仍是构造的**：纯指挥型叠加，R2 只消「任务池自造」与「单模型」两条前提；「对抗真实攻击」仍是开放问题。
2. **C3 的 1/k 台阶结构不变**：0.80 与良性上界之间的裕度问题由 J2/J3 显式检验，不因换池换模型而消失。
3. **判定语义仍是「存在纯指挥节点」≠「存在攻击」**。
4. 跨框架不结论（仪器不支持，Phase 0 已裁决）。
