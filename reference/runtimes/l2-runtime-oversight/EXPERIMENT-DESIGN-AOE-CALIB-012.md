## 一、要回答的唯一问题

**spec/09 四类运行时指标（执行步数 / 调用频次 / 单次时长 / 资源消耗）的良性侧分布，跨任务族是否同分布？** 不做、也不声称检出力（免费区形态仍未知）；③④ 类的任务级累计拦截实现状态不因此改变。

## 二、数据源（S0′）与隐私纪律（沿 CALIB-008 逐字沿用）

- 来源：`~/.workbuddy/projects/<项目目录>/<sessionId>.jsonl`——同 harness（WorkBuddy 内置编码助手）、同 schema（`function_call` / `function_call_result` / `message`）。
- **隐私**：transcript 不入仓库；脚本只提取 `timestamp / name / callId / status / output 长度` 五类字段（+项目目录名）；入库的只有脚本 + 会话清单（纯元数据）+ 聚合统计。

### 2.1 任务族映射（冻结，机械规则，按目录名关键词，防事后挑分布）

| 族 | 目录名匹配规则（包含即命中） | 预期形态 |
|---|---|---|
| **F1 框架维护** | `AI执行与监察体系设计` | 代码+文档维护（CALIB-008 S0 同源，自动并入） |

### 2.2 入选与小样本规则（用户裁决冻结）

- 目录入选线：该目录全部会话合计任务块数 **≥ 10** 才归属其族参与标定；不足者并入 F0 只登记。
- 族入选线：族内任务块总数 **n ≥ 30** 才出建议上限；**n < 30 只报 P50 / P90 / max**（防小样本冒充）。

## 三、统计口径（沿 CALIB-008 §三逐字冻结，不变更）

任务块 = 相邻两条 user 发起 message 之间的 `function_call` 序列（开头无边界归首块）；步数 = 块内调用计数；频次 = 块内 60s 滑动窗口最大调用数；单次时长 = callId 配对（仅 `status=completed` 且配对成功），配对失败如实计数；资源 = `output` 字节数（代理口径）。阈值规则 K=4：`max(P99, P50×4)` 向上取整到十位——**继承不重调**。

## 四、流程与判据（先冻结，后计算）

1. **清点阶段（先入库）**：枚举全部 63 个项目目录 → 按映射规则归类 → 每目录产出会话清单（sessionId / 族 / 会话文件数 / 任务块数 / 调用数 / 时间跨度），**只含元数据**，先于任何分布统计入库。可读性失败的文件逐个登记。
2. **统计阶段**：入选目录逐块归属任务族 → 每族四类分布 → K=4 建议上限 → 跨族对照表。
3. **判据**：
   - **H1″（族间分化）**：四类指标中至少一类的「族间 P99 比值（最大族 P99 / 最小族 P99，仅计有上限的族）≥ 2」⇒ 分化成立；否则「同分布」成立。两方向均为有效结果。
   - **H2″（族内形态）**：各入选族四类分布右偏（P99/P50 ≥ 2）与 CALIB-008 单族结果同型。
   - 判读纪律沿 CALIB-008：全部为良性侧保守区间；P99 型上限固有 ~1% 误伤是采用方产品决策。

## 五、翻车分支（全部为合法判定）

| 情形 | 判定 | 动作 |
|---|---|---|
| 某族任务块 n < 30 | 「样本不足」 | 只报 P50/P90/max，不出上限 |
| E 盘文件不可读 | 「该文件未采」 | 逐个登记，不影响其余 |
| 族内会话几乎全部来自单一会话 | 「族内多样性不足」 | 如实登记（单会话长跑 vs 多会话的形态差异） |
| 块边界异常（无 user 消息的超长序列） | 沿 CALIB-008 口径 | 归首块，如实报告块长分布 |

## 六、诚实边界（随结果同行）

1. 单 harness（WorkBuddy 内置编码助手）、单用户（本人）、良性侧 only——不支撑任何其他 harness / 多用户部署的阈值外推；
2. 任务族 = 项目目录粗粒度代理，块内跨族未细分；
3. 免费区检出力仍未知（小米教训不变）；③④ 类任务级累计拦截实现不在本条范围；
4. #33 在本条完成后**收窄而非关闭**：边界②按可得任务族改写，非代码任务族（如纯对话类）不在数据源内。
