## 提示词正文（从下一行开始复制）

你是一名独立判类员。任务：按给定的判类规约，把一份表格中的每一条消息判为 `D` / `H` / `R` / `C` 四类之一，把结果写回同一文件。

这是一项**盲判**任务。你不需要了解这些消息来自什么系统、什么实验、背后想验证什么。任何关于「这条大概是什么类」「这份表想得到什么结论」的猜测都请放下——**只按规约读本条正文**。

### 一、只允许读这 2 个文件

```
<协调人填入：判类规约的绝对路径>/判类规约_v1.1.md
<协调人填入：判类表的绝对路径>/判类表_J1.csv
```

**硬约束**：
- 除这 2 个文件外，**不要读取、不要列出、不要搜索**同一目录及其上级目录中的任何其他文件。目录里可能存有与本次判类无关但会造成先入之见的材料。
- 不要联网检索判类标准，不要参考任何外部资料。
- 先完整读完规约，再开始判。规约 §一–§七 全部有效。

### 二、表的结构

表头固定 11 列：

`序号, 别名, 位置, 发送者, 接收者, 上一条发送者, 上一条摘要, 本条正文, 判类(D/H/R/C), 疑难(Y/N), 备注`

- **只允许写后 3 列**：`判类(D/H/R/C)`、`疑难(Y/N)`、`备注`。
- 前 8 列（含 `序号`、`别名`、`位置`、`本条正文`）**一律只读**，一个字符都不能改。
- **不得增删行、不得调整行序、不得改表头、不得改文件名**。合并时按 `别名` 对齐，行序被打乱会让判类结果错配到别的消息上。
- `位置` 列形如 `#1`、`#3`，只是行内序号，与判类无关。
- `本条正文` 是消息全文。若出现 `⏎` 且截断处正好影响你的判断，按规约 §五 标 `疑难=Y` 并在备注写 `trunc`。

### 三、判类方法（严格按规约）

1. **判定顺序固定 `D → H → R → C`，先命中先归类**，不要讨论「更像哪个」。
2. 判 `D` 需满足规约 §二 三条判据中的**至少两条**，且**两条判据必须有各自的正文证据**（规约 P1）：同一短语「派 X 做 Y」只提供判据 1；若正文没写出 Y 的产物名、字段清单、验收判据或格式要求，判据 2 不成立。判别问句：**「Y 的产物长什么样、怎么算完成」，正文写了吗？**
3. 复合消息（主体是交付、末尾另起新要求）**不适用「主体优先」**（规约 P2）：尾部构成完整派发 ⇒ 整条判 `D`；尾部只有「请你看看 / 请你确认」这类无交付物、无验收、无时限的话 ⇒ 按主体判。
4. 「确认」「闭环」「收尾」「定稿」是**语用标签**（规约 P3）：正文若同时列出成品内容（结论、指标、清单、否决项、边界说明），判 `R`；仅当正文没有任何实质内容、只有确认语时，才判 `C`。
5. 逐条处理规约 §三 的四条边界规则。**规则文字有效，示例只用来理解口径**：示例正文取自另一次运行，位置号只作追溯，**不得**用「这条和示例位置相近」当依据；一切以你手中这行的正文为准。
6. 收件人与正文点名的派发对象不一致时，**仍判 `D`**，并在备注写 `to_mismatch`。
7. 一条消息里出现多段派发表述，**仍计 1 条**，只判一个类。
8. 判类只看本条。**不要用「上一条摘要」去推断本条应该是什么类**——它只用于理解上下文指代。
9. 不要因为一条消息「看起来是流程噪声」就默认判非 `D`；也不要因为「场景像是正常协作」就不敢判 `D`。只看本条是否**新增了一次可执行的派发**。

### 四、取值与备注格式

- `判类` 列取值只能是 **`D` / `H` / `R` / `C` 单字母大写**。不得写 `D/H`、`d`、`派发`、`D(H)` 等任何变体。合并脚本遇到非法值会直接失败。
- `疑难` 列取值只能是 **`Y` 或 `N`**（大写）。**每一行都必须填**，不确定就填 `N`，确实无法判才填 `Y` 并在备注写卡点。
- `判类` 列：**每一行都必须有值**（判不了则 `疑难=Y`、`判类` 留空）。
- `备注` 列：**一句话，不超过 40 字**，只写三类内容之一：
  - `to_mismatch`（可加半句说明）；
  - `trunc`（正文截断影响判断）；
  - 判疑难时的卡点（如「D/H 均可成立：给了对象但无交付物」）。
  - 普通条目**可以留空**，不要写理由、不要写推理过程。
- **禁止**在备注里写任何自定义标签（场景名、你自创的分类名或缩写）。是否存在额外属性由协调人在合并侧按程序判定，你不需要也不应该判断这个。

### 五、怎么写回文件（技术约束，务必遵守）

- 文件是 **UTF-8 with BOM** 的 CSV。用程序读写，不要手工拼字符串。
- Python 写法（唯一推荐）：

```python
import csv
path = r"...\判类表_J1.csv"
with open(path, encoding="utf-8-sig", newline="") as f:
    rows = list(csv.DictReader(f))
    fieldnames = list(rows[0].keys())
# 只改 rows[i]["判类(D/H/R/C)"] / ["疑难(Y/N)"] / ["备注"]
with open(path, "w", encoding="utf-8-sig", newline="") as f:
    w = csv.DictWriter(f, fieldnames=fieldnames, lineterminator="\r\n")
    w.writeheader()
    w.writerows(rows)
```

- `newline=""` 必须加，否则 Windows 下会产生空行、行数翻倍。
- 不要用 `pandas.to_csv` 默认参数（会改引号风格、丢 BOM）；若必须用，须 `encoding="utf-8-sig"`、`index=False`、`quoting=csv.QUOTE_MINIMAL`、`lineterminator="\r\n"`。
- 正文里含逗号、引号是正常的，csv 模块会自己处理。**不要**手工加引号。

### 六、完成前自检（逐项确认，不要跳过）

执行并输出结果：

1. **行数不变**：数据行与原文件一致（**25 行**），没有多出或缺少。
2. **列数不变**：每行仍是 11 列。
3. **前 8 列未被修改**：`序号`/`别名`/`位置`/`发送者`/`接收者`/`上一条发送者`/`上一条摘要`/`本条正文` 与你读到的原文逐字节一致。
4. **行序未变**：`别名` 序列与原文件完全相同（`V-01`…`V-25`）。
5. **取值合法**：`判类` ∈ {D,H,R,C} 或空（空时 `疑难` 必须为 `Y`）；`疑难` ∈ {Y,N} 且无空值。
6. **每行都有结论**：不存在「判类为空且疑难≠Y」的行。

任一项不通过 → 修好再交，不要带着不合规的表交回。

### 2. 为什么要改成中性文件名

冻结件名里带框架名（`判类表_autogen_*.csv`）。判类人知道框架就能推断「这个框架的调度器通常不发消息」，等于给出场景先验（R3 的另一面）。
副本与冻结件**只有文件名不同、字节相同**，hash 可复核；判类结果按 `别名` 合并，与文件名无关。
