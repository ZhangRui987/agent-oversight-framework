# 标记/语义双人核对（review）

CALIB-007 §6.2「标记-语义不一致率」的执行工具与规约。目的只有一个：
**判断「按格式标记给消息分类」这件事，在真实框架的消息上到底准不准。**

这件事不能由一个人做完再自称通过——所以这里把「抽样可复现」「遮蔽由数据流保证」
「统计算法可重算」三件事做成脚本，人只负责判类。

## 流程

```
        ┌─ make-review-sample.py ─┐
        │  seed + 语料指纹         │
        └──────────┬──────────────┘
                   ↓
        判类表_<fw>_A.csv     判类表_<fw>_B.csv     ← 内容完全相同
        （无 type / 无轨道名）  （无 type / 无轨道名）
                   ↓                    ↓
              判类人 A（独立）      判类人 B（独立）   ← 不得互看、不得看抽检清单
                   ↓                    ↓
                   └──── merge-review.py ────┐
                                              ↓
                                   分歧 → 仲裁人 J-C（按规约）
                                              ↓
                                  核对记录_<批次>.md + .summary.json
```

**顺序不可换**：先出两份相同空白表，两人各填，填完再合并。
`标记` 列不在判类表里，合并时才从 `sample-frame.json` 回填——
所以「判类人看不到标记」是数据流保证的，不靠口头约定。

## 三种角色

| 角色 | 能不能看 `sample-frame.json` | 能不能看对方表 | 做什么 |
|---|---|---|---|
| 协调人 | 能（含标记与 sid 对应） | 能（合并时） | 抽样、分发、合并、归档 |
| 判类人 A / B | **不能** | **不能** | 只按规约判 D/H/R/C |
| 仲裁人 C | 不能 | 能（仅分歧条目） | 按规约裁定分歧，不得引入新判据 |

**判类人只读当前版本规约 `判类规约_v1.2.md`**（自包含：四类、判据、九条边界规则都在其中；v1.1 起已根除「原件 + 阅读版」双文本）。
判类人**不得**读历史件（`判类规约_v1.md`、`判类规约_v1.1.md`、`判类规约_v1_B侧阅读版.md`）、
**不得**读 `冻结记录_*.md` 与 `协调人附录_*.md`，也**不得**读任何 `README.md`（本文件的语料表给出框架级 `assign` 计数；
`adapters/langgraph/README.md` 直接写「这 2 条应算 assign」），
更不得读 `whitelist-registry.json` 的 `emits_chat_messages` 结论——
否则会带着「这个框架的调度器发不发消息」的预期去判类。

分发用 **`判类简报_v1.2_给模型.md`**（v1.2 起统一用它，替代封存的 `B侧提示词_给模型.md`）：其**「使用说明」节是给协调人的，发给判类人前必须删掉**；简报正文内两个占位符须填成真实绝对路径。

## 填表操作（给判类人的最小说明）

1. **拿哪个文件**：**v1.2 起只发 AutoGen 一份表**（`out/v1.2/判类表_J3.csv` / `J4.csv`，25 条全量普查；CrewAI / LangGraph 已按方案 (c) 豁免）。
   两人各拿一份中性名的表（避免文件名泄漏框架），规约**只发 `判类规约_v1.2.md`**（自包含；v1 的「原件 + 阅读版」双文本与 v1.1 的「修订记录」均已封存，不得再发）。
2. **只填三列**：`判类(D/H/R/C)`、`疑难(Y/N)`、`备注`。其余列（序号/别名/位置/发送者/接收者/上一条/正文）全部只读，
   **不得修改、不得调整行序**——合并按 `别名` 对齐，行序被打乱会导致判类错配。
3. **取值只能是** `D` / `H` / `R` / `C`（大写单字母），判不了就留空并在 `疑难` 填 `Y`，`备注` 写一句卡在哪。
   合并脚本对非法取值（含 `D/H` 这种双写、`d` 小写、`派发` 中文）直接报错退出。
4. **编码**：文件是 UTF-8 with BOM，用 Excel / WPS 打开可直接改；**保存时选「CSV UTF-8（逗号分隔）」**，
   不要存成 GBK，否则合并时中文列会乱码或整表读不出。
5. **不得打开的东西**：`out/抽检清单_<fw>.md`（里面标了每条的真实类型）、`out/sample-frame.json`（含标记与 sid）。
   规约要求判类人「标记盲」，这两份是答案键。
6. **判完就交回**，不要继续改；两人都交回后才由协调人合并。

**覆盖保护**：`make-review-sample.py` 检测到任一份判类表已有人工判类时会**整批中止**（退出码 3），
不会出现「前几张被清空、后几张还在」的半成品。确需重抽时先备份到 `out/_archive/` 再传 `--force`。

**合并**：

```bash
python merge-review.py \
  --a out/判类表_autogen_A.csv --b out/判类表_autogen_B.csv \
  --frame out/sample-frame.json --batch REVIEW-2026-11-05
# 三个框架各跑一次
# 有分歧时：先写仲裁表（列：别名,终判,依据），再补这两个参数重跑
python merge-review.py --a ... --b ... --arb out/仲裁_<批次>.csv \
  --arbiter <代号> --arbiter-blind yes|no --batch ...
```

输出 `核对记录_<批次>.md` + `.summary.json`（κ、Po、false_assign、missed_assign、待仲裁数、仲裁人与盲性）。
**κ < 0.6 时本批次只能作内部预检，不得入库**（规约 §六）。

> `--arbiter` / `--arbiter-blind` 是**必填**（用了 `--arb` 却不给会打警告，记录里写「未声明盲性（须补填）」）。
> 原因：脚本曾把仲裁人硬编码为 `J-C` + 「分歧裁定符合规约」，会把「协调人自己预判」读成「有独立第三方仲裁」——
> 属记录失真。**仲裁人若已看过 `marker` 列或双方判类，必须写 `--arbiter-blind no`**，
> 记录会印「不满足盲审、属非独立仲裁」。

## 抽样：为什么现有语料做不到「每框架 20 条」

2026-11-04 实测语料总量 **59 条消息**：

| 框架 | 消息总数 | assign | freeform | report | 配额 20 可否达成 |
|---|---|---|---|---|---|
| AutoGen | 46 | 16 | 12 | 18 | ✅ 达成 20 |
| CrewAI | 4 | **0** | 0 | 4 | ❌ 只有 4 条（全量普查） |
| LangGraph | 9 | **0** | 4 | 5 | ❌ 只有 9 条（全量普查） |

结论：**「每框架 20 条」在当前语料上只有 AutoGen 能达标，合计 33 条，不是 60 条。**
CrewAI / LangGraph 的 assign 层可用量为 **0**，这不是抽样不足，而是
**结构性空层**——这两个框架的派发不经消息流（CrewAI 走 `delegate_work_to_coworker`
的 `tool_args`，LangGraph 的 supervisor 派发虽有正文但被标成 `chat`），
所以它们的消息流里客观不存在 `task_assign` 类消息。

这个事实有两个后果，必须写进报告，不能含糊：

1. **这两个框架的「漏派发」无法用标记-语义比对检出**——样本里没有 assign 标记，就没有
   「标记说不是、语义说是」的配对可查。只能靠对照实验（同一轨迹的标记口径 vs 语义口径
   `S1_raw` 差值）间接观察，n=1 已得 0 vs 0.286 的差值。
2. **每个框架抽 20 条在正式执行时才可行**：正式语料 AutoGen 245 条轨迹、
   CrewAI 24 条轨迹（约 48 条消息）、LangGraph 24 条轨迹。同一脚本、同一种子规则重跑即可。

## 抽样算法（冻结）

- **分层维度 = 消息自带标记**（assign / freeform / report / other）。
  按标记分层是方差缩减，不是自证：它把「最容易判错的消息」抽足，代价是样本不再代表总体。
  因此**抽检结果不用于估计总体不一致率**，只作为映射表的质量闸门。
- **配额**：assign 10 / freeform 5 / report 5 = 20。
  assign 过采样（10/20），因为派发语义的误判几乎全落在这一层。
  某层结构性为空时按「剩余可用量降序」逐条回填，回填记录写进 `抽检清单_<fw>.md`。
- **层内跨轨道轮转**：先按轨道分桶、桶内用种子打乱、再轮转取——保证不集中在单条轨迹上。
- **确定性**：种子为字面量 `AOE-CALIB-007::REVIEW::v1::2026-11-04`；重跑结果 md5 相同（已验证）。
  改种子 = 换一批样本 = 视为核对方案修订，须重出记录。

## 正文来源：必须用全文 sidecar

判类表里的正文取自各轨迹的 `swarm-text.jsonl`（**全文**），不是 `swarm-msgs.jsonl` 的
`_content_head`（**仅前 160 字**）。原因：2026-11-04 实测 AutoGen 46 条里 45 条被截断、
最大缺口 10096 字，而判 D 需要的「派发对象／交付物／时限」几乎全在被切掉的部分——
用 160 字碎片判类等于猜。

`swarm-text.jsonl` 由三个 `collect.py` 在写出时生成；`swarm-msgs.jsonl` 的字节契约**不变**
（全文键 `_content_full` 写出前剥离），否则既有 S1 结论与语料指纹会全部失效。
若某条没有 sidecar，脚本退回 head 并在 stderr 告警，该行判类应在备注打 `trunc`。

## 遮蔽边界

**遮蔽**：`type`、`_format_mark`、`_tool_calls`、轨道名。
**不遮蔽**：`from` / `to` / 正文（含 `[ASSIGN]` 前缀）/ 上一条摘要。

所以这是**标记盲**，不是**场景盲**。残余偏差：从作者名（`supervisor`、`Director`）
可推断调度结构；方向不可先验确定，故不做事先校正，只如实登记（规约 §四）。

## 统计口径

- 两人一致率 `Po`、Cohen's κ（四类），**κ < 0.6 视为规约未定标**，本批只能作内部预检。
- 不一致率 = 不一致条数 / 可裁定条数，方向分 `假派发`（标记 assign、语义非 D）与
  `漏派发`（标记非 assign、语义 D）。
- `legit`（良性的真实委派）**计入一致率但单列**：它检验的是 S1 的机制敏感度，不是映射准确度。
- 两人分歧且未仲裁的条目标「待仲裁」，不计入终判统计，但计入 κ 分母。

## 已验证 / 未验证

**已验证**：抽样幂等（重跑 md5 相同）；分层配额与回填日志正确生成；盲化后判类表不含
`type` / `_format_mark` / `_tool_calls` / 轨道名（grep 六份表，0 处泄漏）；A/B 两份表 md5 相同；
判类表正文已用全文（中位 379 字、最大 4017 字，仅 1 条在 4000 字处截断并显式标注）；
`merge-review.py --selftest` 7 项全 PASS（合成缺陷下 `false_assign=1`、`missed_assign=1`、
待仲裁=1、κ=0.954、可裁定=n−1）。

**顺带测出的一件事**：为生成全文 sidecar 重跑了九条轨迹，消息数与 `S1_raw` 全部与重跑前一致
（9/7/6/14/10 条；0 / 0.1429 / 0.5 / 0.5 / 0.5），但 AutoGen 46 条里有 **8 条（17.4%）**
在 `note` ↔ `report` 之间翻转了类型（benign-A 3 条、benign-B 4 条、attack-cross 1 条）。
`assign` 计数恰好没变——**所以 S1 的稳定是运气，不是稳健性**。这条比任何判类结果都更直接地
说明「格式标记不是稳定标签」，已登记为设计稿 §十 第 18 条与 §0 第 35 条。

**未验证（关键）**：本节写作时（v1 批之前）规约本身没被两个人独立跑过一次，`κ` 未知，20% 降级线是候选值。`--selftest` 用标记自身当答案、只注入 3 个已知缺陷，**只能证明统计路径通，不能证明判类准**。
真实批次的 κ 若低于 0.6，处置是回改规约并重跑本批次，**不是**放宽度量。
> **2026-11-05 更新**：κ 已实测——v1 0.8149（`Po` 未过线）、v1.1 0.636（规约 D-1 缺陷 + 同模型）、**v1.2 0.919（达标）**，三批均在文末有完整记录与限制；本节其余表述作为历史保留，「20% 降级线是候选值」一句**仍然有效**（n=1 未标定）。

## 2026-11-04 22:20 修订（A 组交回后、B 组判类前）

三条变化，**均不改判类口径**（A 组 33 条判类不重判）：

1. **`legit` 改由合并侧机械派生**。原写法要求判类人在 `备注` 里写 `legit`，但判类人对轨道名是遮蔽的
   （规约 §四），无法知道哪条属于良性轨道——等于要求他们猜场景。现改为
   `final=D 且标记为 assign 且 sid 的轨道前缀为 benign-*`，由 `merge-review.py` 自动回补。
   已用 `--selftest` 验证 `legit=1` 能正确产出。
2. **新增 `prescreen-single.py`（单侧预检）**。它算「标记 × 语义」交叉表与不一致率，
   附 Clopper-Pearson 精确区间，输出文件页首带免责横幅（**不是**双人结果、无 Po 无 κ、不得入库）。
   存在的理由：20% 触发线是候选值，在第二人交回前需要知道量级是否已逼近它；同时保证这个中间数字**可重算**，
   而不是只留在对话里。
3. **κ 判读规则预注册（规约 附录 B）**，并为 `merge-review.py` 增加 **Gwet's AC1** 与 `verdict` 字段。
   理由：n=33 且 R 占 42%，κ 在边际偏斜下会出现 prevalence paradox（Po 高而 κ 低）。
   判读改为三档：`Po≥0.90 且 κ≥0.60` → 可入库；`Po≥0.90 且 κ<0.60 且 AC1≥0.80` → κ 悖论，可入库但须并列报三个系数；
   `Po<0.90` → 未定标，回改规约重抽。**该规则在 B 组数据到达之前登记，不得事后调整。**

另登记 **规约 附录 A（边界示例锚点失效勘误）**：为补全文 sidecar 重跑九条轨迹后，
§三 七条规则的示例位置有 **3 条失效（规则 1/4/5）**、1 条措辞漂移（规则 3）、3 条仍成立（2/6/7）。
其中规则 4 最危险：其原例位置 `attack-cross#10` 现已是一条含两段 `[ASSIGN]` 的新派发，
照原结论套用会判成 H 而实际应为 D。**结论：轨迹不是字节可复现的，任何以「某次运行的某条消息」为证据的写法必须内联正文。**
