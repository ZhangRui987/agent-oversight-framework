## 三、H1″ 判定：**分化成立**（判读带预注册冻结 ≥ 2）

| 指标 | 族间 P99 比（max/min） | 分化？ |
|---|---|---|
| **单次时长** | **25.51×**（F1 158,996 / F3 6,232） | **是** |
| **执行步数** | **2.36×**（F1 118 / F3 50） | **是** |
| 频次/60s | 1.43×（F4 20 / F1 14） | 否 |
| 输出字节 | 1.69×（F1 21,575 / F2 12,764） | 否 |

**判读**：

1. **时长类必须按任务族分化**：F3 应用开发的单次调用 P99 只有 6.2 秒（原型 UI 迭代、快速反馈），F1 框架维护高达 159 秒（长测试/构建）——**25.5× 的差距意味着统一时长阈值要么对 F3 过松（6s 的调用形同虚设）、要么对 F1 持续误伤**。这一类是「按任务族标定」最强的实证。
2. **步数类分化成立但幅度温和**（2.36×）：F2 求职块短（P50=7）、F1 框架块长（P50=11 但 P99=118）。
3. **频次与输出字节跨族同分布**（1.43× / 1.69× < 2）——这两类**合并标定可行**（各 4 族 P99 挤在 14–20 / 12.7K–21.6K 窄带内），「按任务族分别标定」对它们不是必要条件。
4. **与 CALIB-008 对照**：S0 单会话 89 块时步数 P99=140/上限 140；F1 扩到 944 块（含 S0 + 49 会话）后 P99=118/上限 120——**单会话口径系统性高估尾部**（单次长跑把尾部拉长），多会话口径更接近跨会话正常形态。CALIB-008 的 140/任务块数值应理解为「单会话族内参考」而非通用值。
