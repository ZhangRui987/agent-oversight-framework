## 〇、对预注册的一处勘误（预注册文件不回改）

预注册 §二 S0 写「同一 agent 在同一 sessionId 下**跨约两个月**的连续开发工作」——**错**。实测 transcript 的 function_call 时间跨度为 **3.06 天**（2026-11-04 至 11-07；该 sessionId 起于 11-04，此前工作在更早的其他 sessionId）。跨度比预注册陈述短，不影响任何统计口径（口径均不依赖「两个月」），但按「预注册不重写历史」纪律在此勘误并留痕。**对边界的实际影响**：3 天的连续工作比两个月更集中，任务块分布的多样性更低——「长期运行登记继续」的结论因此加重而非减轻。

## 一、S0 主源分布（真实个人 agent 开发工作流）

样本：`function_call` **3,486** 条（配对 completed **3,464** / 未配对或非 completed **22 = 0.63%**）；user 发起边界 125 条 → **任务块 89 个**；跨度 3.06 天。工具构成（前六）：Bash 1,925 / Edit 1,039 / Read 187 / Write 162 / TaskUpdate 55 / TaskCreate 40。

| 指标（预注册口径） | n | P50 | P90 | P99 | max | **建议上限**（max(P99, P50×K)，K=4） |
|---|---|---|---|---|---|---|
| ① 执行步数（任务块内工具调用数） | 89 | 25 | 97 | 140 | 145 | **140 步/任务块** |
| ② 调用频次（块内 60s 滑窗峰值） | 89 | 9 | 13 | 14 | 14 | **40 次/60s** |
| ③ 单次调用时长（callId 配对） | 3,464 | 832ms | 7.7s | 56.6s | 540s | **56,650ms（≈57s）** |
| ④ 资源（S0：单次 output 字节，**代理口径**） | 3,464 | 609 | 2,651 | 9,385 | 28,161 | **9,390 字节/次**（代理） |

**三条必须与数字同行的判读**（小米教训同款纪律）：

1. **P99 上限必然误伤 ~1%**：步数 max=145 > cap=140、时长 max=540s > cap=57s——P99 型上限天然拦掉约 1% 的真实任务块（本批 89 块中即 1 块）。这不是统计缺陷，是阈值语义的固有取舍：**「拦截上限定在哪」是产品决策（接受 1% 误伤还是放宽到 max），统计只提供分布**。spec/09 的「触发后按 G 档分流（暂停/终止/转人工）」意味着被拦块进入转人工而非硬丢弃——1% 转人工率是否可接受须由采用方决定，本报告不替其决定。
2. **频次的建议上限（40）远高于 P99（14）**——K=4 规则把上限抬到 P50 的 4.4 倍。这是刻意保守：频次误伤的代价（打断正常工作流）高于漏检收益，且 S0 无攻击样本，无法验证 40 以下的「免费区」里藏着什么（小米教训：阈值下行为分布才是真正的攻击空间——本报告只测了良性侧的分布，免费区内部的形态**未测**）。
3. **资源是双口径且不可互换**：S0 的 9,390 字节是**单次工具输出**的代理（非 token、非任务累计）；S1 的 token 是**episode 级真实计量**（n=6）。两者都不能直接当 spec/09「资源消耗上限」的标定值使用——该类只能给出「量级参考」，维持部分未标定。

## 四、消费端回放（#9 打包部分）

- **CreditEventStream 块级投影**（冻结口径：块内任一 status≠completed → failure）：89 块 = **success 70 / failure 19**（21.3% 的任务块含至少一次非 completed 调用——用户中断、命令失败、重试；与「1,925 条 Bash 里含大量探索性失败」的开发工作流形态一致）。failure 是行为事件**不是操守违规**，不进 O21。
- **AbstentionGate 全量回放**：操守违规记录 **0** 条 → O21 = 0 → **89/89 全部 allow**，与预注册预期一致。这是消费端在真实数据上的**第一次运行**：良性开发工作流在 θ2=0.40 下零误触发——与量规 v2.1 的「良性零误伤 0/96」在**完全不同的数据域**（真实工作流 vs 构造分布）方向一致。
- **语义限定（不得收回）**：这是**回放**，不是**生产启用**。生产启用 = 在线接入真实工作流、裁决实时消费、消费动作被审计——仍缺。#9 维持未解。

## 五、#33 判定：**不闭合**，状态从「无任何经验依据」升级为「有第一份真实分布 + 保守区间候选」

不闭合的四条理由：

1. **单 agent、单 harness（WorkBuddy）、单任务族**（文档与代码维护）——spec/09 要求「按任务族分别标定」，本报告只覆盖一个族的一个实例；
2. **步数口径是「工具调用/任务块」**，与 spec/09 原义的「agent 执行步数」在不同 harness 上不同物（S1 的消息口径对照显示跨框架口径差异真实存在）；
3. **资源类只有代理口径（S0）与 n=6 真实 token（S1）**，任务级 token 上界不可从 6 条推断；
4. **P99 型上限的 ~1% 误伤是产品决策输入，不是统计输出**——四类阈值「取保守值」的最终数值仍须采用方按 G 档后果选定，本报告提供的是选值的分布依据。

**已闭合的子项**：spec/09 四类上限的「阈值无任何经验依据」状态终止——①②③三类有了真实良性侧分布与预注册规则下的建议上限；10-D4 处置时限（P0 24h/72h/7d）**仍为占位**（预注册边界 4：需真实处置样本）。
